# Evidence for `0124-connector-removal`

The owner decided on 2026-11-15 to remove connectors from Lenny. The files below are the analysis and the spikes the decision and its design rest on. They are records of read-only studies, a read-only review, and a throwaway test run on 2026-11-15. They are not product code, and they carry no specification citation.

| File | What it is |
| :-- | :-- |
| `tools-egress-study-condensed.md` | A condensed copy of study 2.5, which compared keeping tool connectors in the gateway (option A), moving external MCP servers to the egress path (option B), and a pass-through MCP proxy in the gateway (option C). It keeps the question, the recommendation, the properties compared, the risks, option C, the open decisions, the validation items, and the sources, and drops the per-design change tables. |
| `fidelity-study-summary.md` | The condensed summary of study 2.3, on connector-to-runtime fidelity. It records the translation work (widened descriptors, `residue`, `render_report`, `tool_progress`, and MP-6 handling of `input_required` and Tasks) that gateway-mediated connectors would need, and the harness facts of 2026-11-15. |
| `remote-child-study-summary.md` | The condensed summary of study 2.4, on presenting external A2A agents as child sessions. It records the remote-child backend and the A2A task-state mapping, which `0124-connector-removal` lists under "Alternatives rejected" since its revision 2, because the owner removed external agents from Lenny on 2026-11-15. |
| `tool-server-spike/RESULTS.md` | The tool-server spike: native MCP clients (TypeScript SDK 2.4.0 and Python `mcp` 2.3.0) reaching MCP servers of both protocol eras through a Go stand-in for `netagent` that terminated TLS with a per-pod CA, injected a bound token, redacted reflected tokens, inspected JSON-RPC, and held calls for approval. It ran on macOS on loopback, with no cloud resources and no Docker. |
| `tool-server-spike/logs/07-approval-hold-summary.md` | The summary table of the spike's approval-hold matrix (holds of 10, 70, and 300 seconds against each client). |
| `tool-server-spike/logs/08-overhead-summary.md` | The summary table of the spike's overhead benchmark. |
| `harness-egress-spike/RESULTS.md` | The harness-egress spike of 2026-11-15: Claude Code 2.1.323, Codex CLI 0.136.0, the TypeScript MCP client 2.4.0 on Node 22.22.0, and the Python `mcp` 2.3.0 client on Python 3.13.13, reaching MCP servers through the same Go stand-in for `netagent` on loopback, with no logins and no model calls. It measures which proxy and CA variables each client reads, credential injection with and without a placeholder `Authorization` header, each harness's OAuth behaviour on a 401, the harnesses' other egress, and Codex elicitation through `codex app-server`. Claude Code elicitation is documented only. |
| `decision52-review.md` | A read-only adversarial review of 2026-11-15 on whether O10, the lift of `0151-user-credential-delivery` decision 41 for `delivery: inject` on recycled and used pods, should extend to the repositories of a VCS pool with `userAuthorization: required` under `0152-user-git-identity` decision 52. It found that the recorded ground of both decisions is the compromised pod-wide component that a slot release does not reach, and it recommended against the extension. After reading it, the owner withdrew O10 itself: "refusal on both (I changed my mind)". It is kept verbatim as the record of that review. |

Left out: both spikes' raw logs (the tool-server spike's are about 11 MB), source code, generated certificates and keys, isolated harness configuration directories, and vendored SDKs. Each `RESULTS.md` cites paths under `logs/` and `src/` that this folder does not hold. Its "Commands" section records how to rebuild them. The tokens quoted in `RESULTS.md` are test values the spike generated, valid nowhere.

No harness CLI ran in the tool-server spike. The harness-egress spike ran Claude Code and Codex without a model turn, so Claude Code's handling of an elicitation during a tool call stays owed, as `0124-connector-removal` "Validation owed" states.
