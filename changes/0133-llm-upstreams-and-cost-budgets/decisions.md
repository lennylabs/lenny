5. **Whether a refused budget extension still ends the session.** Today the in-process budget enforcer ends a proxy-mode session whose extension is refused: it denies the session's next request and expires it, which 0117.S3 routes through a seam operation, `GWSEAM-ExpireSession`. "LU-6", step 5, says that on `CEILING_REACHED`, `REJECTED`, an extension still pending at the deadline, or a window refusal, the proxy returns `BUDGET_EXHAUSTED` and does not call the upstream, and it does not say whether the session ends. The step that changes the mechanism names its seam edits under decision 8 of 0117, so 0133.S3 has to state the operation's fate. Options: (a) the session continues and each call is refused until the budget is raised, so 0133.S3 removes `GWSEAM-ExpireSession` with the in-process enforcer; (b) a terminal extension outcome still expires the session, so 0133.S3 keeps the operation and states the expiry in the rewritten §11.2 and §8.6. **D10. A generic proxy with no provider-specific code.** In the owner's words: "I don't want provider specific code in Lenny. Deployers can use LLM gateways for this. I want the thin LLM proxy to be as generic as possible (supporting the formats we discussed)."

The decision reads as follows. The thin LLM proxy keeps the four metered API formats, `anthropic-messages`, `openai-chat`, `openai-responses`, and `google-generate`, with their parsers, routes, usage normalization, budgets, rate cards, and forwarded attribution. It drops everything that exists to reach a specific provider or cloud: the `channel` enum and its per-channel behaviour, the `workloadIdentity` credential source with the AWS, Google Cloud, and Azure exchangers, the Bedrock and Vertex rehosting with the existing `AWSBedrockTranslator`, `VertexAITranslator`, and `AzureOpenAITranslator`, which a step removes, the per-channel attribution defaults, provider-specific endpoint and header rules, and provider-specific statements, such as which provider isolates caches by workspace. An upstream is a generic record: an endpoint URL, a format, a credential from a Secret placed in a header, optional extra headers, a model allowlist, a rate card, and attribution settings. A provider that speaks one of the formats natively with a key, such as Anthropic's API, OpenAI's API, or the Gemini API, is reached as an ordinary upstream. A provider API that needs request signing, token exchange, or rehosting is reached through an operator-run LLM gateway. 16. **Usage is attributed by upstream and model, with no `provider` or `contract` label.** Option (b). The upstream record carries no `provider` and no `contract`. The upstream's name is the attribution key on every usage record, every `llm_usage` entry of `token_usage.checkpoint`, the `visibleTo` read, and the posture `llm` section, and the operator's billing system maps upstream names to vendors and agreements. D2 reads "usage is attributed by upstream and model", and OD-6's list of quantities for the operator's cost computation holds the upstream in place of the contract ("LU-1" **Record**, LUR-3, "LU-7").
17. **A default credential header per format, with an override.** Option (a). `anthropic-messages` places the credential in `x-api-key` with no prefix, `openai-chat` and `openai-responses` in `Authorization` with `Bearer `, and `google-generate` in `x-goog-api-key` with no prefix. `credential.header` and `credential.prefix` on the record override the default. A write is refused when the header is a `Lenny-*` header, `Host`, `Content-Length`, a hop-by-hop header, or one of the record's extra headers. The proxy removes the inbound header of the chosen name and the headers that carried the proxy token, and never places a credential in the query string or the body ("LU-1" **Credential**).
18. **The cache isolation rule rests on the shared credential.** Option (a). §4.9 and the documentation state that an upstream's tenants share its credential and any prompt cache the provider keys on the account behind it, Lenny states no provider's boundary, and the operator reads its provider's documentation. A tenant that must not share a cache gets its own upstream whose credential belongs to a separate provider account. The `hipaa` and `fedramp` warning reads as a warning that the tenant shares an upstream's credential and its provider cache, and posture reports the sharing in the form open decision 7 settles. Lenny compares upstream records, so two upstreams whose Secrets hold keys of one provider account are not reported as shared, and "Limits" states it ("LU-9", LUR-14).
19. **Two maps of extra headers.** Option (a). `headers` are set on every forwarded call and replace any value the runtime sent, so a runtime cannot choose the account, organization, project, or workspace its spend lands in. `defaultHeaders` are added only when the runtime sent no value of that name, and `session_start` carries them in each format entry. A name may appear in only one map ("LU-1" **Extra headers.**).
20. **No attribute forwarded by default, and a separate `user` setting on `openai-chat`.** Option (a) with (ii). Every upstream defaults to `attributes: []`, and the gateway guide gives the configuration that forwards every attribute with `user` pseudonymous. `attribution.chatUserField`, off by default, writes the forwarded user into the body's `user` on `openai-chat` for a gateway that keys budgets on that field, and `nativeUserField` writes `metadata.user_id` and `safety_identifier` alone ("LU-11" **Provider-native fields** and **Defaults.**).
