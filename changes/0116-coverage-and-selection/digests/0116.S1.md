## Defaults applied

- **Files the index reads.** The harness indexes the tracked files (`scope.GitLister`), as CS-1 states. `where` and `digest` keep indexing the working tree with its untracked files that are not ignored, as `survey` did before.
- **Test function.** A top-level function of a `_test.go` file whose name `go test` runs as a test (`Test`, then nothing or a character that is not a lower-case letter), excluding `TestMain`, methods, benchmarks, fuzz targets, and examples. A test's items are the union of the annotations in its doc comment.
- **Indirect coverage.** A test reaches an identifier when it cites the stub's own section and the stub's successor list links the identifier's anchor on its page (the review round settled the exact section). A successor link to a whole page reaches no identifier. A test that cites the identifier directly is listed once, as direct.
- **Code citing an identifier.** Every annotation outside test files, including package doc comments.
- **Issues.** Records `issues/<CODE>/<file>.md` with status `open` or `planned`; the README, the generated index, and `issues/closed/` are left out.
- **Output.** Without an argument the text view prints one line per page, identifier, and numbered heading, then the unresolved citations and the unannotated counts by tier and by package; an argument prints every test, code site, and issue of the rows it selects. Queries may sit between the flags.
- **Rate and threshold.** The rate counts identifier rows and numbered-heading rows; page rows are groupings. `--threshold` keeps its meaning over that rate, so the nightly workflow's `coverage --spec --threshold 0.40` keeps working.
- **Area.** `--area` takes the area's folder name or the code of a page that has an area, lists the area's pages and identifiers, and leaves the numbered sections out, because only the placeholder pages' prose names the sections an area holds.
- **Unknown query.** All three commands exit 2 and name every unknown query (the review round settled `list --spec` and `run --spec`).
- **Spec-map union.** A query adds the map's entries under its section number; an identifier or a page code adds nothing from the map, whose keys are section numbers. `list --spec` prints the index's tests as `path::Name`, then the map's entries as the map writes them.
- **Unread files.** `where` and `digest` print each file the index left out on stderr and continue.
- **Unresolved citations.** Both tests and code sites are listed, which is why the count (55) exceeds the 46 numbers that `change.md` measured over tests.
- **`run --spec`.** Each tier that holds a resolved test runs, the unit tier is scoped to the packages of its tests unless the spec-map half of the union runs it whole, and selected packages run whole; running functions by name is CS-5 (0116.S3). When no test resolves, the unit tier runs whole, as before. The test lists now survive `mergeDiscoveryPlans`, so `--dry-run` prints them.
- **Verdict field.** `spec_sections` keeps its key and lists the test's identifiers, then its section numbers written `§N.M` (the bare form before), and a failing subtest reports its top-level test's annotation.
- **Reachability check.** Rather than routing the new symbols through a pass, the exported-symbol check of `scripts/specshift` counts `pkg.Sym` references from the harness's non-test sources, where `pkg` names an import of the tooling.
