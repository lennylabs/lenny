## Defaults applied

- **Requirement wording on an index page.** GW-R1 sits on `components/gateway/index.md`, a page of type `index`, and the page gates refuse a normative keyword on an index page. GW-R1 states its rule in declarative sentences without one, as `change.md` words it.
- **Operation blocks.** Each operation is an `operation` definition block with `method: Go method`, `path` naming the Go interface, and `requirements: [GW-R1]`. The page states no Go signatures, which the conventions place in package documentation.
- **Owned terms.** The page owns "Seam interface" and "Holder replica". The generator adds both to `spec/catalogs/glossary.md` and to the generated region of `docs/reference/glossary.md`, which is the only change under `docs/`.
- **Documentation record.** The documentation gate needed the line "No reader-facing behavior changes: GWSEAM, GW." in the Documentation section of `change.md`, which says in prose that no page under `docs/` changes. The line was added there.
- **Values crossing the seam.** `pkg/gateway/seam` carries its own value types and imports only `pkg/session/state` and `pkg/sessionrecord` outside the standard library. The pod recycle policy and retirement carry the pod scrub values as strings, so the package imports nothing that 0137.S5 renames. A subscription returns a channel and a close function, so it has no methods of its own that would need operations.

The package's `doc.go` ends with `// spec: GWSEAM, GW`.
- **Layout gate semantics.** A register row gives a package its part and overrides its directory, so a package sitting today in a directory the layout gives to another part fails the placement rule (the seam model and `semver` under `pkg/gateway/core`). A registered package in transit, `domain` or `removed`, may be imported by any part. A `domain` package is held to the outside-imports rule, and the imports of a `removed` package are not checked.
