## Defaults applied

- **Package names (decision 6).** The moves keep each package's name, except the three middleware packages that join a concern package of the same name. Those become `pkg/auth/authmw`, `pkg/idempotency/idempotencymw`, and `pkg/environment/environmentmw`, the aliases that 265, 13, and 10 of their importers already used. The redundant aliases are removed, and the `idemmw` alias becomes `idempotencymw`.
- **Concern packages for the domain logic the seam page names.** The pool status reader becomes `pkg/runtime/poolstatus` (`Lookup` and `ConditionPoolWarmingUp`). The service-account token verifier becomes `pkg/auth/satoken`, and `TokenVerifier` stays in `leasecontrol` for its interceptor. The seam page already said that both belong in a concern package outside the gateway, so no decision was raised.
- **The quota adapter.** `admin.QuotaCheckpointReconciler` takes the checkpoint service through a small interface, `CheckpointReconciler`, so its test needs no checkpoint store. The test moved with it as `TestQuotaCheckpointReconcilerMapsScopeResultAndErrors`.
- **Adapters on the admin side.** The admin router's `With*` signatures are unchanged, so the router's tests keep their fakes, and so do the integration, security, chaos, and load tests that wire it. The composition root hands each `With*` an admin adapter whose field is a seam interface: `SeamRevokeHook`, `SeamUserPods`, `SeamRevocationCache`, `SeamPoolCredentialRevoker`, `SeamUserLeaseRevoker`, `SeamKMSProbe`, `SeamClientSecrets`, `SeamLeaseDenials`, `SeamElicitationFloor`, or `SessionTerminator`.
- **The core's side.** `sessionserver.AdminSeam` serves the API front's terminal, revocation, and force-terminate operations, with one adapter per seam as decision 41 settles. The binding-release fan-out stays in `cmd/lenny-gateway` and reaches `AdminSeam` through `sessionserver.UserBindingReleases`. `GWSEAM-LastTenantKMSProbe` sits beside `GWSEAM-ProbeTenantKMS`, because the router also reads the time of the last successful probe.
- **The step's scope.** The first part did not build the route registration work of decisions 3, 24, and 34, the routes still mounted in `cmd/lenny-gateway`, the decision 7 move of the admin router's constructor and flags, or the split of `sessionserver`'s pipeline files. The second part built the first three, and the third part built the split, as "What the step built" states.
- **Comments left with old paths.** The historical records and the applied migrations keep the old paths. One comment in `tests/e2e_kind/auth_modes_test.go` keeps `middleware/auth`, because its comment block quotes specification text, which the annotation lint refuses on a changed line.
- **The move driver's gates.** The driver ran with `-skip-gates`, because its build gate fails on darwin in `tests/testinfra/supervisedpod`. The gates were run by hand.
- **The internal listener's routes.** The `/internal/` paths, `/healthz`, `/readyz`, and `/metrics` register on the internal listener; the platform health API, under `/v1/admin/health`, stays on the client listener as part of the admin API. Both listeners share one mux, so the classification changes no answer.
- **Prefix routes.** Each route that `main` mounted as a path prefix for every method, such as `/v1/admin/`, `/playground/`, and the session paths, registers for `seam.MethodAny` under the same pattern, so the mux answers as it did, and a handler that dispatches by method keeps its own 405 answers. Decision 24 rejected registering one route per method for the same reason.
- **The session handler's patterns.** The session handler is built once per listener and mounted under every session path of that listener, where `main` built one per mounted prefix; each build was the same mux.
- **The forwarded Open Responses turn.** `POST /v1/responses` registers on the forward listener only when the forward listener is built, as `main` mounted it only then.
- **`connector-oauth-client-secret-key`.** The flag stays in `cmd/lenny-gateway`, because it configures the connector secret resolver that the session core holds and serves through `GWSEAM-ResolveConnectorSecret`, and its default is a constant of the confined `connectorsecret` package (decision 67, settled by the owner on 2026-11-19).
- **Flag packages.** Each moved flag joins the package of the part that reads it, as `uploadhandler.Flags` and `playground.Flags` did, rather than one flag package for the API front. `idempotency-max-body-bytes` joins `pkg/idempotency/idempotencymw`, the request pipeline's idempotency stage.
- **Harnesses.** `tests/testinfra/apifront` gives a test's session server the API front's route table, and `uploadwire`, `toolwire`, and `streamwire` register their parts through it, so each harness mounts the routes `main` mounted.
- **Session paths.** The pipeline serves fixed session paths per listener, the prefixes `main` mounted the session handler on (`routetable.SessionPaths`), so the routes `main` left unreachable stay unreachable (open decision 69).
- **The access checks the session core's routes take.** `seam.AccessSessionCreate` and `seam.AccessSessionList` are new values for the permission gates of routes that name no session; the routes whose handlers apply their own gate, such as `GET /v1/sessions/{id}/usage` and `GET /v1/usage`, take `seam.AccessTenant`, as `main` mounted them behind the tenant check alone.

- **The in-process service handler.** The session core takes the pipeline's client handler as a `net/http.Handler` through `SetServiceHandler`, which decision 17 does not count as a crossing; `apifront` gives a test's server a service handler that builds the pipeline on the first call, so a harness that never builds the handlers still reaches it.
