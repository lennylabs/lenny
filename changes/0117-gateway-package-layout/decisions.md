# Decisions: 0117 Gateway package layout

## Open decisions

The branch of 0117.S1 and 0117.S2 implements the recommendation of each decision below. The owner confirms it or changes it; the branch does not wait on the answer.

17. **Interfaces declared outside the gateway parts as crossing targets.** The wiring check reads values given to interfaces and function types. Some of those types are declared in domain packages of the module, and some in the standard library or a dependency, such as the `net/http.Handler` of the middleware chains.
    - (a) Count interfaces declared in the module, domain packages included, and leave standard-library and third-party types out, because they are in-process composition that an extraction replaces with the extracted service's own middleware.
    - (b) Count all of them, which adds 12 handler-chain rows today.

    Recommendation: (a), which GW-R1 and `tests/static/lint/gatewaywiring/doc.go` state and the branch builds. Raised by the fourth review round on 2026-11-18.

18. **The API front's allowance under `pkg/credential`.** Decision 16 lets the API front import `pkg/credential` itself while the packages under it stay confined, and the decision-11 default lets it import the credential pool store and impersonation, which its admin handlers read.
    - (a) GW-R2 and decision 16 say the API front may import `pkg/credential` itself and, of the packages under it, only the credential pool store and impersonation, matching `confined.go`.
    - (b) Withdraw the credential pool store and impersonation from the API front and route the admin handlers' reads through seam operations.

    Recommendation: (a), which GW-R2 states and the branch builds. Raised by the fourth review round on 2026-11-18.

19. **More token and key packages to confine.** `pkg/uploadtoken`, `pkg/webhooksig`, `pkg/connectoroauth`, `pkg/tokenexchange`, `pkg/tokenservice`, `pkg/proto/tokenservice/v1`, `pkg/gateway/serviceidentity`, `pkg/gateway/pki/carotation` with its store, and `pkg/mtls/denylist` hold token, signature, or key material and are not on the confined list.
    - (a) Extend the list with them, allowing the API front those its admin handlers read under decision 11 (the connector OAuth package, the Token Service protocol, service identity, and the CA rotation packages). Only the session core or the API front imports them today, so the layout register needs no row; the wiring register gains three rows for the Token Service protocol values the composition root hands to the seam model's subsystem.
    - (b) Leave them unconfined, as domain packages any component may import.

    Recommendation: (a), which GW-R2 states and the branch builds. 0117.S13 keeps a leftover it moves under a confined path confined. Raised by the fourth review round on 2026-11-18.

## Decisions

Settled by the owner on 2026-11-17 ("go with all your recommendations, except ..."); the questions as framed are in `review-history.md`.

1. **Domain packages.** All 124 domain packages leave `pkg/gateway`.
2. **Directory level.** Concern directories under `pkg/`, extending the existing ones.
3. **REST handlers.** Each part registers its own routes with the API front through the registration interface in `pkg/gateway/seam`.
4. **`sessionserver`.** The seam, plumbing, and domain files move out, and the rest, about 19,400 lines, stays as one session core package.
5. **Packages a member change removes.** They stay in place, listed in the layout gate's register with the change that removes it. In the owner's words: "keep in place but remember to move at the end if for whatever reason they weren't deleted (fully or partially)". Step 0117.S13 runs before v1 closes and moves into the layout whatever a removal left, whole packages or parts, so the register is empty when v1 closes.
6. **Package names.** Directories change, and each move step settles the names of the packages it moves: a package keeps its name where the name fits its component page or concern, and is renamed in the same step where it does not, so that every package is named appropriately when v1 closes. In the owner's words: "let's make sure packages are named appropriately at the end of v1 (done at each step and not at the end)". No rename is deferred to a final pass.
7. **`cmd/lenny-gateway`.** Each move step also moves the wiring of the part it moves into that part's package: its constructor, the flags only it reads, and its route registration under decision 3. Shared startup (stores, telemetry, and shutdown order) stays in `cmd/lenny-gateway`, which thins with every step and ends v1 as a composition root. Step 0117.S1 first adds two guard tests: one that fixes the set of flag names, defaults, and help text, and one that fixes the startup and shutdown order; every later step keeps both green. Settled by the owner on 2026-11-17 ("I'm ok with 0117's decision 7"), after an elaboration that recommended this option over moving only import paths, consistent with decisions 5 and 6.
8. **Seam operations that member changes remove, reshape, or add.** (a): the seam interface page states today's operations, as "SP-2" says. Each member change that removes, reshapes, or adds a mechanism behind a seam operation edits `spec/interfaces/gateway-seams.md` and `pkg/gateway/seam` in the step that changes the mechanism, and that step names the operations it edits. The affected changes are 0118, 0122, 0126, 0133, 0135, 0138, 0139, 0141, 0142, 0145, 0146, 0151, and 0153. Settled by the owner on 2026-11-17, choosing the recommendation.
9. **Crossings at the wiring level.** (a): a static check of `cmd/lenny-gateway` refuses a value of one part passed where another part expects an interface, unless the interface is declared in `pkg/gateway/seam`. Today's crossings are listed in a register that only shrinks, and each move step routes its crossings through the seam interface and deletes their rows. Settled by the owner on 2026-11-17, choosing the recommendation.
10. **Credential and admission packages.** (a): the layout gate confines `credentialstore`, `credleasestore`, the authentication middleware, `quota`, `policy`, and the tenant store to the session core, the metering proxy, the API front (the authentication middleware only), and `cmd/lenny-gateway`, with today's other importers listed in the register. The owner added no package to the list. Settled by the owner on 2026-11-17, choosing the recommendation. Decision 11 widens what the API front may import, and decision 13 extends the list.
11. **The API front's admin handlers.** The API front may import the admin stores, quota, the interceptor stores, and the rate limiter, which its admin handlers read, as well as the authentication middleware. This amends the allowed parts of decision 10: the API front is a replica-level part that is not extracted, and decision 10's reason concerns extracting a seam. "Policy" includes `pkg/gateway/policy/ratelimit`, which this decision allows to the API front. The packages decision 13 adds that the admin handlers import are allowed to the API front for the same reason. Settled by the owner on 2026-11-18, choosing the recommendation.
12. **The wiring check's scope.** The check counts a crossing only where the import rules would refuse the receiving part importing the value's part, and GW-R1's wiring sentence says so. An adapter type that `cmd/lenny-gateway` declares is attributed to the parts whose values its fields hold, and a function literal to the parts whose functions or methods it calls or whose values it captures. Settled by the owner on 2026-11-18, choosing the recommendation.
13. **The confined list, extended.** GW-R2 and the layout gate confine, besides the packages of decision 10, the credential packages (`credassign`, `credcache`, `credentialpoolstore`, `credentialserver`, `usercreds`, `impersonation`, `revocation`, `denylist`, `connectorcredstore`, `connectorsecret`, `vcscred`, `credrouter`, and `pkg/credential`), the token and key packages (`pkg/auth/jwt`, `issuedtokenstore`, `pkg/kms`, and `pkg/tenantkms`), and the authorization predicates (`callercheck`, `envaccess`, `tenantaccessstore`, `customrolestore`, and `delegationpolicystore`), each at its directory today and at its manifest destination. `storage/pgtenant` stays out. The rule governs direct imports, and indirect reach stays with review. Settled by the owner on 2026-11-18, choosing the recommendation.
14. **The review path of the move manifest.** `scripts/refactor/manifest` joins the paths of "Review changes to the merge gate" in `.claude/rules/git-workflow.md`, because the layout and wiring ratchets map renamed rows back through it. This amends that rule alongside decision 6 of change 0158. Settled by the owner on 2026-11-18, choosing the recommendation.
15. **Move steps add no register rows.** A move step adds no row to the layout or wiring register: a row whose paths a move rewrote still maps back to its old paths, and a step routes any crossing it would create through the seam interface. The ratchets have no step exemption and no check of landed steps. Settled by the owner on 2026-11-18, choosing the recommendation.
16. **The credentials subtree.** GW-R2 confines `pkg/gateway/credentials` as a whole subtree, together with the named credential and token packages outside it (`connectors/connectorauthz`, `externalapi/admintoken` with `k8ssecret`, `pkg/auth/introspection`, and `pkg/tokensvcproxy`). Today's importers are registered, or allowed under decisions 10 and 11. The API front may import `pkg/credential` itself while the packages under it stay confined. Settled by the owner on 2026-11-18, choosing the recommendation.
