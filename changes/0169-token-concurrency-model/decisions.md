# Decisions: 0169 A concurrency model of the token rules

## Decisions

1. **Build the TLA+ model now, as its own change (owner, 2026-11-23).** The owner decided on 2026-11-23 to build the TLA+ model of the concurrent orderings of the token rules now, as this change. This amends decision 14 of change 0165 (a formal model of the token rules), under which the model stayed a candidate until step 0165.S2 was done.
2. **The model checks 0168's locking design before its code lane (owner, 2026-11-23).** The owner decided on 2026-11-23 that the model checks the locking design of change 0168 (token rule fixes from the property tests), as its decisions 1, 2, 5, and 6 and its sections TF-1 to TF-5 state it, before the code lane of 0168.S1 is written. The specification lane of 0168.S1 may proceed in parallel. The counterexamples the model finds in that design are reported to the owner before the code lane starts.

The owner answered FM-19 to FM-25 on the M3 readiness decision page on 2026-11-23, each with option (a). The answers settle open decisions 3 to 9 of revision 1.

3. **PlusCal for the request processes (FM-19).** The request processes are written in PlusCal, with one label per statement or lock step, and Postgres, the deadlock detector, and the event bus are TLA+ operators and actions in the same module. The translator ships in `tla2tools.jar` (`pcal.trans`), the translation is committed in the module between the translator's markers, and the runner checks that it is current. Owner's answer to FM-19 on the M3 readiness decision page, 2026-11-23. The option not chosen was (b), the whole model in plain TLA+ as one next-state relation.
4. **TLC `v1.7.4` is pinned (FM-20).** The runner uses `tla2tools.jar` of the tlaplus release `v1.7.4`, downloaded from `https://github.com/tlaplus/tlaplus/releases/download/v1.7.4/tla2tools.jar`, with SHA-256 `936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88`, and stops when the jar's SHA-256 differs. Owner's answer to FM-20 on the M3 readiness decision page, 2026-11-23. The option not chosen was (b), the pre-release `v1.8.0`.
5. **Directed configurations and one free configuration (FM-21).** The directed configurations run at 2 tenants, 2 users per tenant, 2 replicas, up to 3 request processes, up to 6 tokens, 1 abort per behavior, and the 3 cascade attempts the code makes, one configuration per ordering of "Scope" in `change.md`. One free configuration runs at 2 request processes and 5 tokens, in which each process chooses any operation. A configuration that does not finish within 12 hours is stopped, and the bound it reached is recorded. Owner's answer to FM-21 on the M3 readiness decision page, 2026-11-23. The options not chosen were (b), free configurations only, and (c), directed configurations at 3 tenants as well.
6. **No tier of `lenny-test` runs the model (FM-22).** The model is a design check run by hand with `tests/formal/tokenconcurrency/run.sh`, which runs TLC in an `eclipse-temurin` container with `--network none`, the model and the jar mounted read-only, and the jar's SHA-256 checked, as `tests/formal/tokens/run.sh` runs the Alloy model. The change that edits a rule the model describes reruns it. Owner's answer to FM-22 on the M3 readiness decision page, 2026-11-23. The options not chosen were (b), the static tier running the translator and the parser only, and (c), the release gate running the directed configurations.
7. **The model checks the `I13Lock` variant (FM-23).** Step 0169.S2 adds the variant `I13Lock`, which is `TF` with the per-tenant audit advisory lock taken by the cascade and by `RevokeBySubject` before the statement that reads their snapshot, as TOKX-I13 suggests, and checks C1, C5, C7, and C8 under it. Owner's answer to FM-23 on the M3 readiness decision page, 2026-11-23. The option not chosen was (b), checking `Main` and `TF` only.
8. **Steps 0169.S1 and 0169.S2 share one branch and one digest (FM-24).** Owner's answer to FM-24 on the M3 readiness decision page, 2026-11-23. The option not chosen was (b), separate branches with 0169.S1 merged first.
9. **No specification text (FM-25).** The properties stay in `change.md` and in the model's README, and each change that fixes a counterexample states in §13.3 the ordering it settles. Owner's answer to FM-25 on the M3 readiness decision page, 2026-11-23. The option not chosen was (b), a specification lane on 0169.S2's branch stating the confirmed properties in §13.3.
