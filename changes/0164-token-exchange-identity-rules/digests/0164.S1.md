## Defaults applied

- **One step.** The lineage of decision 3 is one function and one sentence of §13.3, so the change plans one step rather than two.
- **Non-canonical requested values.** A requested value that is not canonical is refused even when the subject carries it literally, and an explicit request from a subject whose scope does not parse is refused, as decision 1's "every value parses" reads. A request without scope from such a subject still receives the subject's scope (the 0163 default). The tests that sent `sessions:read` send `tools:sessions:read`, and the §13.3 `scope` row names the §25.1 syntax in place of its non-canonical examples.
- **Rule (e) for wildcards.** The child allowlist keeps the entries the issued scope grants under §25.1 **Matching.**, so a `tools:<domain>:*` issued scope keeps the entries of its domain, and an issued scope that does not parse keeps none.
- **Playground refusal.** The refusal applies to exchanges that mint a token, through `tokenexchange.Validate`, so it writes the rejected `token.exchanged` row with reason `subject_token_playground` or `actor_token_playground`. The recursive-revocation request accepts a playground subject.
- **Different-caller refusal.** The error is `400 invalid_scope` with reason `scope_not_narrowed`, because the remedy is a narrower `scope`. A `caller_type` that only one of the two tokens carries is not compared, because an IdP caller token carries none.
- **Rotation lineage.** A self-rotation records the token it replaces as its parent, as decision 3's "every exchange" reads; the review raised it as O1.
- **Lineage index.** Migration 0199 adds `(tenant_id, parent_jti) WHERE parent_jti IS NOT NULL` from the security review; revision 1 of `change.md` had declined it.
- **Impersonation scope source.** The handler passes `principal.Scopes.Raw`, the parsed claim text, and the row records the claim split on whitespace.
