## Defaults applied

- **A new chain's value.** Every mint that starts a chain sets `rch` to the issued token's own `jti`.
- **The agent chain.** A platform tool call from a session's pod has the calling session's id as its chain, the only value that matches decision 8's "pod-path calls keep replay across refresh".
- **The IdP chain encoding.** The chain is a JSON array of the issuer, the kind (`azp`, `client_id`, or `aud`), and the values, so no two kinds collide.
- **Unreported source.** A verifier that reports no source yields no chain, so a keyed request on it is refused.
- **The embedded OIDC member.** The development install's embedded OIDC HMAC member is normalized as an IdP token and reports `idp` (`jwt.IdPMember`).
- **The bootstrap rotation's chain.** The rotation reads `rch` from the payload of the token the `lenny-admin-token` Secret holds, without a signature check because the gateway wrote it, and falls back to the Secret's recorded `jti`; the Secret's layout is unchanged.
- **The playground chains.** The `oidc` chain is a 256-bit base64url value drawn like the session id; a record or a pasted token without a chain starts a new chain per mint.
- **The table.** Migration 0207 keeps `idempotency_key` as data, adds `scope_digest BYTEA NOT NULL DEFAULT '\x'`, and fronts the drop of `session_id` with a `DO` gate on `pg_relation_size`, which the §10.5 lint requires.
- **The digest.** Each field is written with a 4-byte big-endian length, and the path parameters with their count, sorted by name.
- **Unresolved route.** A request no route matches is scoped by its literal path; a resolver descends into a handler that exposes its own mux (`MuxUnwrapper`).
- **The MCP record.** The key value is the caller's key with no prefix, the route is `mcp:<tool>`, and the explicit environment is the path parameter `environment`.
- **The REST hook of `/mcp`.** The REST middleware's hook for the JSON-RPC endpoint decodes the tool from the body and runs the tool's admission; it is registered under `/mcp` and `POST /mcp`.
- **The replay rejection row.** Its `exchange_type` is `session_mint_replay`.
- **Clearable 403 codes.** Every `403 FORBIDDEN` is not stored, beside `USER_INVALIDATED` and `ERASURE_IN_PROGRESS`, because the creating-caller refusal is `FORBIDDEN`; the skip metric's reason is `refusal`.
- **Per-route admission.** Approve/DenyDelegation runs the user checks only, `lenny/delegate_task` the creating-caller check only, and FinalizeWorkspace, StartSession, and Resume run none, as each operation runs them; a check that cannot read its row refuses with `500`.
- **Test fixtures.** `ownerprincipal` gives its principal the source `lenny` and the chain `chain:<subject>`, and `DevScope` gives a dev-header principal that chain, pending O9.
- **The caller seam.** `seam.Caller` carries the source as a string, so the seam imports no auth package.
- **Records of other changes.** 0138 R5, its design note and table row, and its 0138.S1 entry take decision 8's scope and the operation-check hook, recorded in 0138's `review-history.md`.
