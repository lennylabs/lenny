## Defaults applied

- **Migration number.** The migration is `0206`. It was `0205`, after change 0176's `0204`, until change 0177 merged first with `0205_platform_signing_keys`.
- **Clearing the table.** Migration 0206 empties the table with `TRUNCATE` rather than `DELETE`. The row-level security policy and the per-row tenant guard filter a `DELETE` that runs with no tenant, and they do not filter a `TRUNCATE`.
- **Default for `subject`.** `subject` is `TEXT NOT NULL DEFAULT ''` rather than IP-3's `TEXT NOT NULL`. The §10.5 expand-contract checks refuse an added NOT NULL column with no default. The stores refuse an empty subject before any write, and a NULL subject is still refused.
- **MCP caller resolution.** The MCP hook takes `Callers seam.CallerIdentity` (GWSEAM-RequestCaller) in place of IP-2's `PrincipalFromRequest` function. The gateway layout lint refuses an `authmw` value handed to the platform tools seam outside `pkg/gateway/seam`. The REST middleware keeps `PrincipalFromRequest`. The gateway wires `idempotencyPrincipal`, which reads the same `pipeline.Callers`, so both paths resolve one scope.
- **Validation in the memory store.** `MemoryStore.Put` and `Claim` now validate the key, as the Postgres store does, so neither store files a record under an empty subject.
- **Fixture resolver.** A test fixture `ownerprincipal.Scope` and `WrapFromHeader` give the contract and security suites the principal resolver without the gateway's auth middleware.
- **MCP documentation.** `docs/api/mcp.md` said the MCP tool input has no `idempotencyKey` field, which contradicted the tool schema and §11.5. It now documents the field.
- **Section citations.** Code and tests cite `§11.5 (Idempotency)` and `§12.8 (Compliance Interfaces)`, because both pages are placeholders, and the counts in `tests/registers/spec-section-citations.yaml` are raised to match.
