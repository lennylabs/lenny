## Defaults applied

- **Remedy per operation.** Every operation whose response carries an `uploadToken` (CreateSession over REST and MCP, create-and-start over REST and MCP, and derive) stores the response with the token replaced by a redaction reference and mints it on replay. Not storing those responses would make a retry create a second session.
- **Which token a replay mints.** The replay mints under the key that signed the original, so the token equals the original. Raised as open decision 2.
- **Byte-level redaction.** The redactor works on the response bytes, so a client value with the token's or the reference's form is stored with a mark no key reproduces. Raised as open decision 3.
- **Where the redaction sits.** At the store boundary (`idempotencymw.WithCredentials`) rather than in the middleware and the MCP hook, because the gateway wiring lint refuses an upload-token value handed to the platform tools seam.
- **Classification.** Idempotency records are T3, Confidential, in Postgres, the class of the most sensitive data a stored response holds (user identifiers and task results).
- **VCS token.** `lenny/vcs_token`'s result is not stored, through a new `DoNotStoreCredential` mark and the `credential` skip reason of `lenny_idempotency_cache_skipped_total`, kept separate from `DoNotStore` because the forward listener reads that mark as a forward refusal.
- **Canonical tokens.** The verifier refuses a spelling of a token other than the issuer's, which also closes the single-use bypass through a non-canonical spelling.
- **No ring.** A redactor with no ring removes every token and restores none.
- **Program membership.** 0173 is not added to program v1's members, following 0162, which carried an owner decision of the M3 readiness review outside the program.
