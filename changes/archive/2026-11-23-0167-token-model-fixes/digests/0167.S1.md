## Defaults applied

- **Impersonator link in a separate column pair (decision 2).** The owner's answer records the admin token on the impersonation bearer's row as its parent. `parent_jti` cannot carry it: rule 2 of **Platform-admin impersonation.** identifies an impersonation row by `act_sub IS NOT NULL AND parent_jti IS NULL`, a delegation child already has `act_sub` and `parent_jti` set, so a new predicate would need a third column to tell the two apart, and the in-tenant lineage walk cannot reach a row in another tenant. The step adds `impersonator_tenant_id` and `impersonator_jti` (migration 0200) and keeps the rule 2 predicate and the lineage index unchanged. Reason: it changes no existing impersonation query and makes the cross-tenant step explicit. Open decision 1 asks whether the `__all__` exception it needs stays.
- **Impersonation step before the cascade (decision 2).** The recursive-revocation request reads the root's subtree (refusing a revoked caller), ends the impersonation sessions under `__all__`, then cascades, so a failure of the cross-tenant step revokes nothing and the caller can retry. It emits one `cross_tenant_read` event per request served by a durable store, also when it ends nothing (TOKX-I17), logs an emit failure, and fails closed without an emitter. `revoked_count` counts the request's own tenant only. Only this request follows the link (open decision 2).
- **Impersonation from an expiring caller bearer (decision 2).** A bearer whose capped `exp` is at or before the issue instant is refused with `ErrIssuanceRefused` (`403 FORBIDDEN`) before the started event is written.
- **Revocation root without a row (decision 3).** The request verifies its `subject_token` with the caller verifier, so an upstream ID token is accepted as a root, and builds the row from it: `jti`, tenant (from the claim mapping for an ID token), `sub`, `scope`, audience, `iat` (the request time when absent), `exp`, and the SHA-256 of the raw token. A subject without `exp` is not recorded and is refused as unknown, because the expired-row GC could not bound its row. A `jti` conflict on insert is a no-op followed by a re-read, so a concurrent first revocation succeeds and a `jti` held by another tenant is refused as unknown.
- **Child bound by its actor (decision 4).** An actor with an absent `scope` claim grants every child scope; a child with an absent issued scope needs an actor with no `scope` claim or `tools:*`; the reason is `scope_exceeds_actor`, checked after `scope_not_narrowed`.
- **Copied `act` (decision 7).** The claim is copied; the row's `act_sub` stays null, because a row with `act_sub` names a child or an impersonation and the lineage already holds through `parent_jti`. TOKX-I14's suggested `act_sub` copy is not done, and its closed record says so.
- **Caller check in step (1a) (decision 8).** The caller is listed after the subject and the actor, a caller that is also the subject or the actor is checked in that role, and the impersonation predicate is not applied to the caller row; the refusal is `401 invalid_client` with reason `caller_token_revoked`, and the rejection `token.exchanged` row carries `error_code` `invalid_client`.
- **Full revoke seed (decision 9).** The walk is seeded with every row of the user in the tenant, revoked or not, so the descendants of a token the user had already revoked (such as one rotated away from) are reached. It follows `parent_jti` inside the tenant only; impersonation rows the user started keep the rule 6 path.
- **Default audience (decision 10).** A subject without an `aud` claim grants `lenny-gateway` and no other audience, in the subset check and in rotation detection, so the bootstrap admin token and impersonation bearers of a default install (whose gateway mints carry no `aud` while `--bearer-expected-audiences` is empty) can still rotate and narrow without an `audience` parameter. A subject with an `aud` claim that does not list `lenny-gateway`, such as an embedded-mode `dev.local` token, must name its audience.
- **Playground record (decision 1).** Every mode records the bearer when the gateway has an issued-token store; the `oidc` and `dev` rows carry no parent. The record repeats the step (1a) re-read of the pasted subject under the per-tenant lock through `RecordWithSources`; a Postgres outage returns `503 SERVICE_UNAVAILABLE` and any other failure `500 INTERNAL_ERROR`. Playground bearer `jti` values are 128 random bits, because the row's `jti` is a global primary key. A logout still revokes the bearer in Redis only (PLAY-I2).
