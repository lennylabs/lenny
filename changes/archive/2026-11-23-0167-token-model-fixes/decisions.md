# Decisions: 0167 Token rule fixes from the formal model

## Open decisions

None. Open decisions 1 and 2 are settled as decisions 12 and 13.

## Decisions

The owner answered questions FM-0 to FM-11 on the M3 readiness decision page on 2026-11-22, each with option (a). The owner answered questions FM-12 and FM-13 on the same page on 2026-11-23, each with option (a), which settle the step's open decisions 1 and 2 as decisions 12 and 13. The counterexamples and gaps are those of change 0165 (a formal model of the token rules), whose `change.md` lists them under "Counterexamples" and "Current state", and whose `decisions.md` records the same answers as its decisions 3 to 11 and 13 to 14, with the options the page offered.

0. **Where the fixes land (FM-0).** The fixes go into a new change after 0164 merged. The page named it 0166; that number was taken by another change created the same day, so this change is 0167.
1. **CX-3 and G2, a playground bearer outlives the revocation of its subject (FM-1, 0165 decision 3).** Record each playground bearer in `issued_tokens` with the pasted subject token as its parent, so revoking the subject ends it, and the revocation request's handling of a playground subject then matches the text.
2. **CX-4, an impersonation bearer outlives and escapes the caller's token (FM-2, 0165 decision 4), Medium.** Cap the bearer's expiry at the calling admin token's expiry, and record the admin token on the bearer's row so revoking it ends the impersonation. The record uses a separate column pair rather than `parent_jti`, as "Limits, and alternatives rejected" in `change.md` and "Defaults applied" in the step's digest state.
3. **CX-5 and G3, a token without a row cannot be a revocation root (FM-3, 0165 decision 5).** A revocation may start from a token that has no row: record it as revoked and cascade to what was derived from it.
4. **CX-6, a child is broader than its actor (FM-4, 0165 decision 6), Medium.** For a child mint, the actor token's scope must also grant every scope value the child is issued.
5. **CX-7, strictly narrower by values (FM-5, 0165 decision 7, option (b) of the model's open question).** Documentation only: state that a domain wildcard is broader than a list of that domain's current actions, because it also covers actions added later, so the strictly-narrower rule accepts the listed form.
6. **CX-8, a child's depth (FM-6, 0165 decision 8).** State in §13.3 that a child's depth is the delegating token's depth plus one, and that rule (b)'s no-decrement check compares a child with the delegating token. The text changes to match the code.
7. **CX-9, a delegated token loses `act` (FM-7, 0165 decision 9).** On exchanges without an actor token, copy the subject's `act` claim, so narrowing or rotating a delegation child keeps its delegation record. This closes [TOKX-I14](../../../issues/closed/TOKX/TOKX-I14-rotated-delegation-child-drops-its-act-claim.md).
8. **CX-10 and G4, a revoked caller authenticates a mint (FM-8, 0165 decision 10), Medium.** Check the caller token's revocation on every mint, in step (1a) of write-before-issue, as for the subject and actor tokens.
9. **CX-11, a full revoke misses delegations (FM-9, 0165 decision 11).** A full revocation of a user (§11.4 step 5) also cascades through the lineage of each revoked token, so tokens others minted from the user's tokens end too.
10. **G1, default audience (FM-10).** Apply the default audience `lenny-gateway` when an exchange request omits `audience`, as §13.3's parameter table states; a self-exchange without `audience` is then detected as a rotation.
11. **G5, G6, and G7 (FM-11).** File them as issues under the owning page codes, each with the evidence from 0165, and do not fix them in this change. The property tests (0165.S2) and the TLA+ model come later.
12. **Whether the impersonator-link revocation may set `__all__` for a caller without `platform-admin` (FM-12, open decision 1).** Keep the exception as built: every recursive-revocation request runs the cross-tenant impersonator-link update under `__all__` and writes a `cross_tenant_read` event, and §4.2 and §12.3 name it as the one exception to their `__all__` rule. Change 0168, the next token fix change, removes it together with [TOKX-I17](../../../issues/closed/TOKX/TOKX-I17-every-revocation-request-runs-a-cross-tenant-step.md): it records, in the admin's own tenant, which bearers started an impersonation, and runs the cross-tenant step only when one did. Owner's answer to FM-12 on the M3 readiness decision page, 2026-11-23. The options not chosen were (b) now, the per-target-tenant record and transactions without `__all__`, which the follow-up takes up, and (c), having the gateway refuse an impersonation bearer whose impersonator row is revoked.
13. **Which revocations of the admin's bearer end its impersonation sessions (FM-13, open decision 2).** Keep the narrower reading as built: only a recursive-revocation request on the admin's token ends the impersonation sessions it started. A self-rotation of the admin's bearer, an operator revocation of its `jti`, the bootstrap admin-credential rotation, and a full revoke of the admin by a `tenant-admin` leave the sessions running until their `exp`, which rule 1 of **Platform-admin impersonation.** caps at the admin token's `exp`, as §13.3 rule 4 states. No further work follows. Owner's answer to FM-13 on the M3 readiness decision page, 2026-11-23. The options not chosen were (b), also following the link from the full revoke and the operator revocation, and (c), also ending the sessions on a rotation of the admin's bearer.
