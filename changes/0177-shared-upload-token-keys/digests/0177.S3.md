## Defaults applied

- The append path takes a redacted tail row's link from its receipt only when the tail's payload carries the redaction marker, the rule `applyReceipts` applies for the chain verifier; one helper, `markRedacted`, serves both. The receipt is read in the append transaction by a second query that runs only for a marked tail, so an ordinary append costs no extra read.
- The append path does not verify the receipt's signature; the chain verifier and the receipt scan do.
- The chain verifier reports a redaction-marked row without a receipt `broken` even when its hash equals its content and the tenant has no receipt at all. Before the step such a tail row read `verified`, which §12.8 step 14 already forbade; the step's security test is extended to this tail case.
- The startup and periodic continuity check applies receipts the same way (from the review).
- No migration: the receipt read uses the `lenny_app` `SELECT` grant on `audit_redaction_receipts` that migration 0160 gives.
