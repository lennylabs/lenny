## Defaults applied

- The stale bound of the upload-token ring stays the overlap window (`uploadtoken.DefaultOverlapWindow`), and the verification time is `overlap + max(overlap, token lifetime)`, computed by `signingkeys.UploadTokenVerificationTime` from the values the gateway passes; the token lifetime is `--max-created-state-timeout-seconds`, or `uploadtoken.DefaultTTL` when that is not positive. No startup refusal of a lifetime above the overlap window (decision 7), and no setting for the overlap window (UPLOAD-I3).
- A row that has a receipt counts as a redacted row whether or not it carries the redaction marker (from the review). The periodic scan reads redaction-marked rows and every row with a receipt; a receipt whose row was deleted is not read, as before.
- The setting is `audit.retiredReceiptKeyIds` in the chart's `audit` block (default `[]`), rendered as `LENNY_AUDIT_RETIRED_RECEIPT_KEY_IDS` only when not empty, and the gateway flag `--audit-retired-receipt-key-ids` takes a comma-separated list (default empty), following the other `audit.*` settings.
- The lookup is a new `kms.Provider` method, `PublicKeyByID(ctx, keyID)`, implemented on every provider: AWS reads the key ID or key ARN, GCP the `cryptoKeyVersions/<n>` resource name, Azure `<name>@<version>` (refusing a name without a version), and the local provider derives the key from the reference string, as an alias mapped to it does. S1 had not added a lookup.
- The gateway refuses to start when a listed identifier does not pin one key version on a cloud provider (`providerflags.ValidateSigningReference`, the rule for the receipt aliases' references) or when the KMS cannot return its public key, as for the alias keys.
- The retired keys are trusted by the chain verifier, the periodic scan, and the audit-events chain walk, and `GET /v1/admin/audit-receipt-keys` lists them with the alias keys. An identifier listed twice, or equal to an alias's reference, is one trusted key.
- `AuditRedactionReceiptMissing` in §16.5 and the metrics reference also count a receipt under an untrusted key and a row whose content no longer matches `new_hash`; the alert rule's expression and `pkg/alerting/rules` are unchanged.
- No migration.
