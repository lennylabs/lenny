## Defaults applied

- The rehydration loop is `revocation.Cache.RunRehydration` with a coalescing `revocation.Trigger` in `pkg/credential/revocation`, which `cmd/lenny-gateway/billing_security_workers.go` starts, rather than a loop written in `cmd/lenny-gateway`, so the component and chaos tests drive the loop the gateway runs. RR-2 and "Tests" in `change.md` now say so.
- `Bus.Subscribe` takes the reconnect callback as a variadic option (`pubsub.OnReconnect`), so the deny-list and bind-release subscribers are unchanged, and `propagator.Run` takes the callback as a second parameter, which `lenny-ops` passes as nil.
- A request from the trigger does not move the periodic schedule: the next tick comes one interval after the previous one.
- Each rehydration in the loop runs under a deadline of one interval (30 seconds in the gateway). The startup rehydration keeps no deadline, as before.
- The staleness age counts from the start of the last successful read rather than from its end, and §13.3 states it that way.
- The chaos test models a Redis restart as a cut and a restore of the replica's TCP link to Redis through `tests/testinfra/tcpfault`, which keeps the address and the data, and shifts the clock the staleness gate reads rather than waiting 90 seconds.
- The security test bounds the peer's refusal at 5 seconds with Redis up, 35 seconds with its link held down, and 5 seconds from the link coming back.
