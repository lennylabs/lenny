## Defaults applied

- `pubsub.OnReconnect` is renamed `pubsub.OnSubscribed`, the name RR-1 gives as its example, because it now runs on every confirmation; no caller of the old name remains.
- The spacing is a parameter of `revocation.Cache.RunRehydration` (`interval, spacing`), with `revocation.DefaultReconnectSpacing` of 5 seconds, which the gateway flag `--revocation-reconnect-spacing` and its environment variable `LENNY_REVOCATION_RECONNECT_SPACING` default to, in the form of the gateway's other duration flags. A spacing of zero or less starts every request's rehydration at once; the flag has no upper bound and no startup check.
- The spacing counts from the start of the previous requested rehydration, a held one included, on the cache's clock (`WithClock`); the first request starts at once. The wait never exceeds the spacing, so a clock that steps back does not lengthen it.
- A tick that runs while a request is held does not discharge it: the held request runs once the spacing has passed. Requests made while one is held fold into it, and the pending one is dropped just before the held rehydration starts, because that read covers it.
- The unit tests drive the spacing from a fake clock and a fake timer set through an unexported `Cache.after`. The component and chaos tests run with `DefaultReconnectSpacing`; the end-to-end reconnect test of `propagator` keeps a spacing of zero.
- The security test holds the peer's link down for the spacing before it restores it, so the rehydration of that reconnect is not held by the one the previous reconnect started and the 5-second bound still measures the reconnect.
