# Program v1

This program carries Lenny to v1: every change that came from `designs/` implemented, every open finding in `BUILD-GAPS.md` and `TEST-GAPS.md` closed, and the specification restructured to state the result. The front matter is the plan; this text explains it.

## Order

- **M0** puts the records and the helpers in place, so every later change uses them.
- **M1** lands the specification structure (0115) and the tooling it needs. Coverage derived from annotations (0116) replaces the registers keyed by path or section number, which caused most of the friction in the migration spike. The pod lifecycle controller's kind renames run once, tree-wide, before any area migrates, because they touch 463 Go files.
- **M2** settles the gateway's package layout (0117) before areas move code.
- **M3 onward** migrates one area per milestone. Each area change writes the area's pages and discharges the specification lane of every change touching the area. The code steps stay with their changes. Areas run in parallel once M1 has landed.

## Left out for now

The open proposals under `proposals/` (38 approved and 5 drafts) are outside the program until the owner returns to them.
