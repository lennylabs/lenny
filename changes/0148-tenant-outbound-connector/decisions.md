# Decisions: 0148 Tenant outbound connector

## Settled decisions

- **Local allowlist default.** The allowlist starts empty, so the agent refuses until configured. Following the platform's routes would let a compromised platform reach anything the agent's host can reach, which defeats C3. The cost is a required step, and a drift failure when routes change, which the liveness read reports.
- **Non-TLS internal hosts.** Both ends refuse them. Without TLS, C6 and C7 fail, since a stolen key or a compromised replica would read tokens. A customer with a plain-HTTP internal registry fronts it with TLS.
- **Intercepting customer proxies.** The agent refuses them, and the customer exempts the outbound gateway's hostname. Authenticating inside the tunnel would let the proxy hold what a replica holds, plus the agent's replica session. The agent routes to the API host work through inspection. Some customers need a change approved by their security team.
- **A runtime-held token through a connector.** On a host no pool or route covers, under `delivery: file`, the token crosses the connector inside the runtime's own TLS, and nothing on the platform side sees or limits its use, as [`0151-user-credential-delivery`, "What `file` does not promise"](../0151-user-credential-delivery/change.md#what-file-does-not-promise) states.
- **Naming.** Identifiers use `outbound` or `site`, and the [egress design](../0127-egress-and-git/change.md) renamed its kind, because §28.1 forbids reuse of the §9.3 term. ([`0124-connector-removal`](../0124-connector-removal/change.md) removes §9.3's MCP connectors on 2026-11-15, and the identifiers keep their names.)
- **First version.** The connector ships in the first version, which takes OC-1, OC-2, and OC-3, since the chart's refusal lifts only with OC-3. OC-4 lands after those.
- **Build or adopt.** Build on grpc-go, in the owner's words "go with your recommendations", which also covers the next two entries. Lenny owns an internet-facing service and a customer-distributed binary, with review and support duties. This rests partly on preference, as "Recommendation" states, so the reversed gRPC and hostile peer spikes under "Spikes owed" in `steps.md` run first, and inlets Uplink is the option to try if they fail.
- **Isolation on shared replicas.** Shared replicas with signed grants, and OC-4's exclusive groups, filtered at admission and at the decision, for those who need them. The in-flight grant residual stays on shared replicas, where OR-4 holds except for that case.
- **Agent identity.** A self-signed key looked up by public key hash, which the owner accepted with "ok". Replicas depend on a store snapshot, and there is no offline verification. A Lenny CA would add a key to protect and a separate revocation path.
- **Mirror for connector hosts.** Off unless `allowMirror` is set on the host, which the owner accepted with "ok". GitHub Enterprise Server behind a connector has no store fallback or warm fill by default, and each fetch crosses the customer's link.
- **Namespace.** Its own namespace, in the owner's words "move to its own namespace, assuming you don't find any blockers when doing that". A first check found none, and a review then showed that its separate `outbound` CA could not deliver trust to Envoy or to `lenny-evidence` without widening trust elsewhere. Copying an egress PKI leaf into the namespace resolves both, so no blocker stands. The work is the copy, cross-namespace network rows, an informer and Role, TLS on the pooler hop, and the scrape selector. It needs an end-to-end run on Kind, which has not happened.
- **Anonymous hosts on a private CA.** A binding with `secret: {kind: none}` in OC-2, which the owner accepted with "ok". This replaces deferring it to [EG-4](../0127-egress-and-git/steps.md#steps), credential delivery, because no stored format changes and `caBundle` lives on the outbound host.
- **Grant signing key storage.** An in-memory key per decision service replica, replaced every 24 hours, with its public part in `outbound_grant_key`, a 25-hour cap in the database and at the agent, and revoke and revoke-all routes, which the owner accepted with "ok". The cost is a table, a dedicated database role, an on-demand trust fetch, first-use latency, and agents depending on the API host within a day. An inserted key is not reliably detected. A Secret would be readable with no trace by `lenny-ops`, whose Secret rights [SO-7](../0142-security-oversight/change.md#so-7-f-25440-lenny-ops-rights) removes, though a Job could still mount it. `lenny-ops` can patch the decision service's Deployment and capture an in-memory key, which causes a visible rollout, and a captured key dies within 25 hours.
- **Pool ceiling.** `tenantOverride.outboundHosts`, defaulting to `deny`, in the owner's words "go with your recommendation". A SaaS operator sets it on each shared pool with a named ceiling, and a pool whose ceiling is `*` needs no step. The setup guide recommends setting it at install for an operator selling the connector. The overlay table of [EG-9](../0127-egress-and-git/steps.md#steps) gains a row. Connector hosts reach only the tenant's own network, so the flag's value is that a ceiling stays the outer bound with no exception.
- **Authorization at the agent.** A per-CONNECT signed grant. The decision service holds a signing key and signs each CONNECT, and a compromise reaches every customer's allowlisted hosts at TCP level, with the bounds "Grants" states.
- **External review.** OC-1's outbound gateway and agent need an external security review. The review blocks no proposal, chart setting, or release, and the chart's refusal under "Deployment and network rules" stays tied to OC-3 alone. Its findings are fixed as defects when they arrive. The cost is stated under "Residual risks".
- **TLS to the outbound gateway.** TLS with a verified SAN, in the owner's words "yes, encrypt and test". The Envoy spike under "Spikes owed" in `steps.md` ran and supports it. Accepted cost: one Envoy cluster, a route per tunnel lifetime entry, and the level 2 assertion `outboundUpstreamTLS`.
- **Attachment register.** Agent-signed attestations in append-only Postgres, polled each second, which the owner accepted with "ok". Accepted cost: an insert per instance per minute, signature checks in the decision service, and up to 180 seconds of 503s from a replica after an agent loses every replica session.
- **Grant-to-instance binding.** A grant names up to two instances, each with its boot identifier, in the owner's words "up to 2". An instance is one agent process with its own key, so redundancy comes from enrolling more instances, and two processes sharing one key raise `outbound_connector.duplicate_instance`. Accepted cost: a compromised replica can open up to two streams per grant, which is C2's bound.
- **The outbound gateway's hosts on the reserved set.** Settled by the owner on 2026-11-08 ("ok"). "The gateway's own hosts" means the outbound gateway's public hosts: `outboundGateway.publicHost` and each OC-4 group's public host. This document calls `lenny-gateway` the API gateway, and every other bare "gateway" in its first full draft meant the outbound gateway. Reserving these names keeps a tenant from registering Lenny's connector endpoint as a host behind its own connector. The API host is not reserved by this rule.
- **Data classes of the new records.** Confirmed as written by the owner on 2026-11-13, in the answer "18–21 ok" to the consolidated list of open decisions: enrollment token hashes are Secret; outbound hosts and the `outbound.session`, `outbound.stream`, and `outbound.agent` streams are Confidential; and connector records, instance records, `REG-SITEATTACH` attestations, and the outbound grant with its quotas are Internal ("Specification sections affected", the §12.9 item).
- **Values of `tenantOverride.outboundHosts`.** Settled by the owner on 2026-11-08 ("ok"): `deny`, the default, and `allow`. The egress design's `narrow` and `narrowOrExtend` were not reused, because this flag only adds hosts and has nothing to narrow.

## Open decisions

- **O1. How a replica learns of the events that close an instance's replica sessions.** The replica's role reads `outbound_agent_instance`, `outbound_grant_key`, and `outbound_grant_key_revocation`, while "Revocation" requires a replica to close sessions when a connector is revoked, the tenant's outbound grant is removed, or the tenant is suspended or deleted, and "Identity" requires its snapshot to filter by the tenant's OC-4 group assignment. None of those records is in the replica's read set, and the store of group assignments is unnamed. Options: (a) the API gateway writes each of those events into the affected `outbound_agent_instance` rows (a `revoked_at` column and a `group` column), so the replica keeps a single-table snapshot, and the group assignment is stored in a platform-scoped table the API gateway alone writes; (b) the replica's role also reads `outbound_connector`, the outbound grant, the tenant's status, and the group assignment table, which puts tenant-scoped tables in the read set of an internet-facing component and needs those tables readable without a tenant context. Recommendation: (a), because it keeps the replica's read set to one table and keeps row-level security on the tenant-scoped tables. Either option adds a `component` tier test per event that the replica closes the affected sessions within its poll. Blocks: 0148.S1, and 0148.S4 for the group assignment. (raised by the M3 readiness review, 2026-11-19; sources: 0148-F1)
- **O2. The bound on the decision service's work for junk attestations.** A compromised replica can insert any number of rows into `REG-SITEATTACH`, and each decision service replica polls and verifies each new row naming a real instance every second, on the path of every tenant's egress. Options: (a) bounds in the decision service: the replica sets its pod UID on each row it inserts, the decision service checks it against the attested set and reads at most a fixed number of rows per inserting replica per poll, skips rows superseded by a verified higher sequence without verifying them, and caps verifications per poll; (b) the bounds of (a) and a per-login insert quota enforced in Postgres; (c) no bound, with the residual on the decision service stated and an alert on the insert rate. Recommendation: (b), with a `security` or `chaos` tier test that a stand-in replica inserting at a high rate does not raise decision latency for another tenant's egress outside connector routes. Blocks: 0148.S1. (raised by the M3 readiness review, 2026-11-19; sources: 0148-F4)
- **O3. Where the outbound grant is stored.** `PUT /v1/admin/tenants/{id}/outbound-grant` sets the outbound grant and its quotas, and [`0142-security-oversight`](../0142-security-oversight/change.md#so-2-tenant-security-record-and-posture) SO-2's `gates` row reads it as one of EG-9's per-class gate grants. This change names no store. Options: (a) an EG-9 per-class gate grant, with the route above writing it and the quotas beside it; (b) a table of its own, with 0142's `gates` row amended to read it. Recommendation: (a), because 0142's posture already reads gate grants. The answer also sets the grant's class in §4.2's tenant-scoping table. Blocks: 0148.S1. Other change: 0142. (raised by the M3 readiness review, 2026-11-19; sources: 0148-F6)
- **O4. Where the spikes that gate the build decision run.** "Build or adopt" holds only if the reversed gRPC and hostile peer spikes pass, the idle cost, grant cost, and attestation rate spikes set defaults, and the CONNECT budget spike decides a request to 0127.S3. No step owns any of them. Options: (a) a separate spike step with the lane `evidence`, listing the reversed gRPC, hostile peer, and CONNECT budget spikes as blocking and the rest as inputs to the defaults the load tiers confirm, with 0148.S1 depending on it and 0127.S3's request naming it; (b) a precondition sentence in 0148.S1. Recommendation: (a). Blocks: 0148.S1, and the request on 0127.S3. Other change: 0127. (raised by the M3 readiness review, 2026-11-19; sources: 0148-F7)
- **O5. Whether 0148.S1 is split.** 0148.S1 carries a new proto, a customer-distributed binary with its image and chart, an internet-facing Deployment in its own namespace, five tables and the register, two restricted logins, TLS on the pooler hop, every connector, token, instance, and agent route, the grant signer, attestation verification, the Envoy cluster, the evidence producers, the network rows, and the controller's Secret copy, and this review moves the outbound grant, the permissions, the count quotas, and the grant key revoke routes into it. Options: (a) split into (i) the tables, restricted logins, pooler TLS, namespace, controller copy, and network rows; (ii) the proto, the agent, the outbound gateway, identity, and the instance snapshot, tested against a stand-in decision service; (iii) the agent and admin routes with enrollment, rotation, reuse, retirement, reaping, the outbound grant, permissions, and count quotas; (iv) the grant signer, the revoke routes, attestation verification, replica selection, the Envoy cluster, and the evidence producers, landing in that order with `depends-on` edges; (b) keep one step. Recommendation: (a). Blocks: 0148.S1. (raised by the M3 readiness review, 2026-11-19; sources: 0148-F8)
- **O6. Which boot of an instance the decision keeps.** "Verification" keeps "the newest boot per instance" without an ordering, and a holder of a stolen key attesting under a second boot either takes every stream of that instance or makes selection alternate between boots, depending on the reading. Options: (a) the boot whose first verified attestation is latest, with selection continuing on that boot while `outbound_connector.duplicate_instance` is active; (b) the boot with the latest verified attestation; (c) while `duplicate_instance` is active, the decision selects neither boot of that instance and uses the connector's other instances. Recommendation: (a), which the review proposed and which keeps the rule under "Duplicate use" that `duplicate_instance` does not block. Option (c) gives a thief no streams, and it reverses that rule and costs the honest instance its share while the condition lasts. The answer also fixes the outcome the "A stolen agent key" scenario states. Blocks: 0148.S1. (raised by the M3 readiness review, 2026-11-19; sources: 0148-L4)
- **O7. How connector bytes are metered.** "Quotas (P7)" states that bytes per tenant are metered because the operator pays for this traffic, and names no metric, event, or field, and [`0121-billing-resource-attribution`](../0121-billing-resource-attribution/change.md) defines no billing quantity for it. Options: (a) a metric of bytes per tenant and direction, with bytes stated as not a billing quantity; (b) a billing event under 0121's rules for periodic events, with 0148.S3 depending on 0121.S2. Recommendation: (a), the smaller option, which leaves (b) open for a later change. Blocks: the metering item of 0148.S3. Other change: 0121. (raised by the M3 readiness review, 2026-11-19; sources: 0148-L10, connectors-llm-billing-C14)
- **O8. The per-source handshake limit when the load balancer hides the source address.** The limit of 5 handshakes per second per source address assumes source address preservation, which the load balancer spike has not confirmed. Without it every agent shares the load balancer's address, and the limit throttles every tenant. Options: (a) the chart sets `externalTrafficPolicy: Local` on the public Service, and preflight refuses a deployment whose test handshake shows no preserved source; (b) the replica accepts PROXY protocol v2 from the load balancer, and the chart enables it where the provider supports it; (c) when preflight finds no preserved source, the per-source limit is off and only the per-replica limit applies, which the documentation states. Recommendation: (a), with (c) as the documented behaviour for a provider that preserves no source. Blocks: 0148.S1, and the Load balancers spike's reading. (raised by the M3 readiness review, 2026-11-19; sources: 0148-L13)
