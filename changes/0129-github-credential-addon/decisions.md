# Decisions: 0129 GitHub credential add-on

## Decisions

| # | Decision | Recommendation | Cost of the recommendation | Alternative |
| :-- | :-- | :-- | :-- | :-- |
| 1 | Scoped tokens (formerly [`0152-user-git-identity` decision 7](../0152-user-git-identity/decisions.md#decisions)) | **Settled**, in the owner's word "ok", after S2 found no per-user limit: leave limits to GitHub. The owner had asked to leave it to GitHub "unless GH's limit is global for all users combined, in which case I agree we need a limit", which decision 7 takes up. Each session mints its own children, an API child and, on a VCS pool with `pushIdentity: user`, a git child, and revokes them at session end (S5). Lenny sets no per-person or per-link budget, a GitHub refusal is the result, and the per-App counter and alert near 2,000 per hour stay. | Each session costs one or two token requests against the App's 2,000 per hour, and a large tenant can reach that limit, whose behaviour S2 did not test. GHES is untested. | A child shared across a user's sessions with the same repositories under an 8-per-hour budget, which guarded against a ten-token rule that S2 showed does not apply. Or a user-wide child, which fails finding 1 of ["Verification of the review findings"](../0152-user-git-identity/review-history.md#verification-of-the-review-findings) under "Review history" in `0152-user-git-identity`. |
| 2 | Sessions across owners (formerly [`0152-user-git-identity` decision 23](../0152-user-git-identity/decisions.md#decisions)) | Refuse the second owner on the binding | A session cannot author pull requests in two organizations. | One child per target, with `netagent` selecting by request path, which adds path parsing to the attach step. |
| 3 | Read-only repositories on the child (formerly [`0152-user-git-identity` decision 24](../0152-user-git-identity/decisions.md#decisions)) | Absent, per [`0142-security-oversight` decision 25](../0142-security-oversight/decisions.md#decisions)'s reasoning | `gh pr view` on a read-only declared repository gets 404 from GitHub. | A second read-only child selected by path, at the cost that decision names. |
| 4 | Review comments (formerly [`0152-user-git-identity` decision 34](../0152-user-git-identity/decisions.md#decisions)) | `gh pr review --comment` stays refused by default, because the preset names `addPullRequestReview` | An agent loses inline review comments, and `gh pr comment` is the substitute. A tenant can change that by dropping the name and accepting approval with it, since rules no longer read the event. | Have the preset read `event: COMMENT`, which needs an input check of the kind D1 removed. |
| 5 | The child's permissions (formerly [`0152-user-git-identity` decision 42](../0152-user-git-identity/decisions.md#decisions)) | **Settled by the owner.** `permissions` is template data a tenant can widen, defaulting to `pull_requests: write` and `contents: read` | At the default, `gh issue`, `gh run`, and more are refused by the host, so "all `gh` commands", the owner's condition, holds only within the token. Once widened to `contents: write`, merges and content writes rest on the deny preset alone, with no host check behind it. | Fix the default wider, which makes `gh` work out of the box and removes the host's limit by default. Or fix permissions as the VCS layer's revision 3 did, which keeps the limit and fails the condition. |
| 6 | The user's email addresses (formerly [`0152-user-git-identity` decision 46](../0152-user-git-identity/decisions.md#decisions)) | Add `GET /user/emails` and `GET /user/public_emails` to `github-deny`, which a tenant can drop. Found by S6 in the VCS layer's revision 25, on an App holding the email addresses permission: a child does not narrow that account permission. | A tool or script that reads the user's addresses through the API fails inside a session. | Leave it, which lets an agent read its user's private addresses. Or drop the App's email permission, which also breaks link providers with `identityBinding: verifiedEmail`, since that reads `GET /user/emails` with the parent. |
| 7 | A per-person limit on child mints (formerly [`0152-user-git-identity` decision 48](../0152-user-git-identity/decisions.md#decisions)) | Open, found in the review of the VCS layer's revision 25. GitHub's 2,000 per hour applies per App, so it is shared by every user of the tenant. When settling decision 1 the owner said limits should be left to GitHub "unless GH's limit is global for all users combined, in which case I agree we need a limit", and this limit is. A per-person hourly limit on mints, set by Helm and narrowed per tenant, keeps one user's runaway delegation from stopping everyone else's. | A person past the limit gets a retryable `USER_TOKEN_RATE_LIMITED`. The limit must sit well above normal use, since each session takes one or two mints. | No limit, which lets one injected session exhaust the tenant's App for an hour. |
| 8 | Preset body (formerly [`0151-user-credential-delivery` decision 24](../0151-user-credential-delivery/decisions.md#decisions)) | **Settled by the owner.** The extended preset, with both root forms and the `/repositories/{id}` alias. It refused 94 of 120 listed routes and mutations, by name search and manual reading **[measured]**. | It refuses `gh issue develop`, `gh repo sync`, `gh repo deploy-key add` and `delete`, `gh ssh-key add` and `delete`, `gh gpg-key add`, `gh api` contents writes, and `gh api` branch protection writes **[measured]**. | The earlier smaller preset (11 REST rules and 18 mutations), under which 94 of the 120 reach the stub, including `merge-async` and every protection write. |
