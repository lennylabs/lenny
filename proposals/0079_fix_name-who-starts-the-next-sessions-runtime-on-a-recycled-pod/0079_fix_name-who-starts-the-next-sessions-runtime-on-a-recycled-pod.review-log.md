# Review log: Name who starts the next session's runtime on a recycled pod

## Standing context

### Settled

- The runtime process lives as long as the pod on every pool and in both deployment models (human decision, 2026-09-30). No close at occupancy zero, no retirement keyed on deployment model, and no runtime redial.
- The adapter rule is unconditional. The adapter reads no recycle, acknowledgment, or cross-tenant setting, because the recycle `Shutdown` follows the last slot's close on the concurrent path; every non-reuse case is a gateway retire.
- Process reuse requires the existing `acknowledgeProcessLevelIsolation` (human decision, D5). A pool without it is admitted and its pods retire at each boundary.
- On `allowCrossTenantReuse` pools, a pod is drained when a different tenant's session would be assigned to it (human decision, D6).
- A runtime that has stopped at a boundary retires the pod through the adapter's `runtime_live` report (human decision, D4). The fail-fast `Start` covers only a runtime that stops after the report.
- The generation never resets inside the pod's life, and `soleSession` requires its session to be live (D9).
- New `Decide` inputs are true to retire; the wire field is positive (D13).
