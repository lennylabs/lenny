# Non-spec changes: Session suspend, idle suspension, and resume driver

## Design (implementation-facing)

This proposal lands after proposal 0091. CODE-4 deletes the `ErrHeld` hold in `holdOrFailOnResumeError` that 0091 CODE-2 adds, CODE-5 edits the `Sweep` loop that 0091 CODE-5 rewrites, and CODE-6 reads the turn token that 0091 CODE-1 adds. Each of those edits is located below by function and quoted text, and each assumes the 0091 version of the code.

The components and the work each one does:

- **Watchdog** (`pkg/gateway/runtime/watchdog`). It runs on every replica every tick and already lists every state. It gains optional hooks beside `RetryAttemptNotifier`, each implemented by the session server: `ResumeDriver` (CODE-4), and `SuspendedPodReleaser`, `IdleSuspender`, and `BacklogResumer` (CODE-6). It gains one new sweep, `sweepSuspended` (CODE-6), and it measures session age as active time (CODE-1). Its `sweepResuming` exit gains the incarnation guard (CODE-4 item 15), and `sweepDLQExpiry` also lists `resuming` rows (CODE-6 item 12).
- **Session server** (`pkg/gateway/sessionserver`). It implements the hooks. The resume driver, the suspension release, the idle suspension, the backlog resume of a row that names a pod, and the held-pod resume (`resumeHeldAndDrain`, CODE-4 item 8) each act only on a session whose `REG-COORDLEASE` names this replica, or on every session when no lease store is wired (dev mode). A lease read that fails is treated as "not the holder". This is the Design lease gate. When it refuses this replica, a hook does nothing, and each held-pod resume site takes the outcome it states for a refusal.
- **Binder** (`pkg/gateway/podlifecycle/podsession`). It gains a post-claim callback (CODE-3), which is the only seam through which the driver writes `resuming`, and `ReleaseUncommitted` (CODE-4 item 5.3).
- **Coordination Sweeper** (`pkg/gateway/coordination/coordination`). Its adoption predicate widens (CODE-5).

**Per-session delivery lock.** CODE-4 adds `deliveryLocks sessionLocks` to `Server`, a second instance of the per-session lock type in `slot_bind.go`, separate from `slotAccountLocks`. On one replica it orders every classification, hold, and send of a message against the delivery of held messages (CODE-4 item 6). The REST and MCP message paths take it, honoring the request context, before they re-read the session row, classify that fresh row, and hold it through `holdMessage` (CODE-4 item 7), or through `resumeHeldAndDrain` and the `executor.Send` of the message. `completeResume` and `resumeHeldAndDrain` (CODE-4 item 8) hold it from before their `running` write until `deliverBuffered` returns. `handleStart` holds it the same way (CODE-4 item 21), and the `lenny/delegate_task` handler holds it around `DeliverHeld` (CODE-6 item 7). The lock is in-process and orders nothing served by another replica. A message another replica holds is delivered at the coordinating replica's next delivery point (CODE-4 item 6), and the row guards of `resumeHeldPod`, `enterResumePending`, and `ReleaseSuspendedPod` step 3 order the state writes against each other. `SuspendIdle`, `ReleaseSuspendedPod`, and `enterResumePending` do not take it. The executor's admission write orders a send against the `running → suspended` write on every replica (CODE-6 item 5). The lock is not reentrant: never call `ResumeSuspended` or take `slotAccountLocks` while holding it. Cite `// spec: §7.2 (Message delivery routing — seven paths, path 6)`.

## Staged code changes

### CODE-1 · Active-time session age in the store funnel

Targets: `migrations/0182_sessions_accumulated_session_age.up.sql` and `.down.sql` (the next number after 0181); `pkg/gateway/session/sessionstore/sessionstore.go`; `pkg/gateway/session/sessionstore/pgstore/pgstore.go`; `pkg/gateway/session/sessionstore/memstore/memstore.go`; `pkg/gateway/runtime/watchdog/watchdog.go`; `pkg/gateway/sessionserver/resume_held_pod.go`; `cmd/lenny-gateway/flags.go`.

1. **Migration.** `ALTER TABLE sessions ADD COLUMN accumulated_session_age_seconds double precision NOT NULL DEFAULT 0 CHECK (accumulated_session_age_seconds >= 0)`. The down migration drops the column.
2. **Field and helpers** in `sessionstore.go`: the field `AccumulatedSessionAgeSeconds float64` on `Session`, and two exported helpers.
   - `AccrueSessionAge(prev session.State, prevUpdatedAt time.Time, row *Session, now time.Time)`: when `prev` is `starting`, `running`, or `input_required`, it adds `max(0, now - prevUpdatedAt)` in seconds to `row.AccumulatedSessionAgeSeconds`.
   - `ActiveAge(row Session, now time.Time) time.Duration`: the accumulated value, plus `now - row.UpdatedAt` when `row.State` is one of those counting states.
3. **The funnel.** In both stores' `Update`, after the mutator returns and before the `UpdatedAt` stamp, call `AccrueSessionAge(prev.State, prev.UpdatedAt, &row, now)` with the same `now` the stamp uses. Add the column to `Create`, to the `UPDATE` statement, to the select list, and to the scan in `pgstore.go`. `Store.Update` is the only writer of the sessions row; grep for any other `UPDATE sessions` statement and route it through the helper. A write that does not change the state still accrues, because the row stays in the counting state across it.
4. **Sweeps.** `sweepMaxAge` and `sweepExpiryWarning` compare `sessionstore.ActiveAge(row, now)` with `effectiveAgeCap` in place of `now.Sub(row.CreatedAt)`. Rewrite the doc comments of `sweepMaxAge`, `sweepExpiryWarning`, the `resume_pending` and idle-clock comments, and the `--max-session-age-seconds` help in `cmd/lenny-gateway/flags.go`, which describe age as wall-clock time from creation. Cite `// spec: §6.2 (maxSessionAge timer behavior across states)`.
5. **Evaluation on entry to `running`.** The §6.2 paragraph after the pause table evaluates the timer on every transition into `running`. A paused session cannot gain age, so the only over-cap row that can reach `running` is one that left a counting state over the cap before a sweep saw it. CODE-4 item 1 covers the driver call, and this step covers the held-pod resume:
   - `resumeHeldPod` refuses, with an error the message path already treats as a failed resume, a row whose `ActiveAge` exceeds the effective cap.
   **IMPLEMENTOR'S CHOICE:** how `resumeHeldPod` obtains the effective cap. The constraint is that it returns the value `effectiveAgeCap` returns for the same row, from one shared resolver rather than a second copy of the min-wins logic.

## Edge cases and accepted failure modes

- **Hung pre-claim wait.** A claim that waits on an exhausted pool is bounded by the remaining window, after which the attempt context is cancelled and `sweepResumePending` moves the row to `awaiting_client_action`.
- **Driver goroutine at shutdown.** The server-lifetime context cancels an in-flight attempt. A cancelled attempt before the hook writes nothing. One after the hook leaves a `resuming` row for `sweepResuming` and its claimed pod for the claim-orphan GC, or a `running` row whose commit landed unacknowledged, with its pod, for the peer's adoption (SPEC-1b **Exits from `resuming`.**).
- **Message held by a non-coordinator replica during a delivery.** The delivery lock does not reach it. SPEC-5i **Delivery of held messages.** states when the entry is delivered. A message to a `running` target follows the §29.3 `running` row (RECORDS-1 item 7(f)).
- **Idle-suspended session with a delegation tree.** Children keep running. The parent's suspension releases only its own pod or slot.
- **Takeover racing the entry write.** A Sweeper whose `List` read a row in `resume_pending` can acquire the lease after the driver's entry write. Its `RecordHandoff` compare-and-swap at the listed generation misses, it releases the lease, and the incarnation continues (CODE-5 item 2b).
- **Terminal transition on another replica.** The attempt learns of it at its next write, so restoration RPCs run until then, bounded by the attempt deadline.
- **Watchdog anchor.** `sweepResuming` measures from `UpdatedAt`, which every write in the incarnation advances, including the asynchronous `AdvanceLastSeq`. The watchdog therefore fires `MaxResumingSeconds` after the last write in the incarnation, while §6.2 states a watchdog set on entry. This predates the proposal and is accepted.
- **Lease mirror lag.** A barrier sent within one Sweeper interval of a resume commit carries a stale generation (RECORDS-1 item 7(g)).
- **Session-wide lease release on a replica that lost the lease.** The slot-accounting lock orders the suspension release and the failure funnel's release against a resume on one replica only (CODE-6 item 4 step 4, CODE-4 item 22). A replica whose coordination lease lapsed between its binding clear or its failure commit and its `releaseExecutor` can revoke leases a peer's resume assigned. This is the residual every session-wide release carries on a replica that lost the lease, and it is accepted.
- **Concurrent-pool counter after an ambiguous commit.** `slotcounter.Counter.Release` decrements unconditionally. A `ReleaseUncommitted` after a commit that landed unacknowledged, followed by a release of the committed binding, therefore decrements twice. This requires a commit `Update` that applied and then errored, plus a state change before the repeat (CODE-4 item 5.3). The counter under-counts by one until post-recovery rehydration recounts the pod's live sessions. This is accepted.
