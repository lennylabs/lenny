# Non-spec changes — Terminal pipeline completeness: seal and writer context

## Design (implementation-facing)

CODE-1 detaches and bounds the hook context once, at the two entries every terminal writer reaches (`AfterTerminalWrite` and `recordSessionCompleted`), and detaches the terminal write itself only in `failFinalizing` and admin `ForceTerminate`. CODE-2 makes gateway shutdown wait on the existing `terminalClaimRecord` before `sessionSrv.Close()`. CODE-3 resolves a lost commit acknowledgement once, in `pgstore.Store.Update`, by reading back from the primary a write identifier the update stored. CODE-4 fixes the seal outcome, adds the closing gate that keeps message delivery off a sealing binding, and gives each checkpoint intent row the deadline its attempt runs under. CODE-5 makes the Checkpointer release a binding whose row is gone on the primary. CODE-6 moves the §5.2 startup gate and the chart gate to the terminal pipeline budget. CODE-7 holds the retention GC guard, generation-scoped resume cleanup, the fenced derive-failure insert, the terminate precondition, the release marker with the post-terminal window predicate, and the lifecycle store-deletion gate. TEST-1 pins each change. REC-1 records the resolutions in `BUILD-GAPS.md`.

The normative rules live in the staged spec text: the context, the budget, and the post-terminal window in SPEC-1; the seal outcomes in SPEC-2; the retention start in SPEC-3; the shutdown wait in SPEC-4; the commit-status rule in SPEC-5; the slot invariant, the rehydration seed, the stale-member release, the orphan predicates, the pool-drain finalizer rule, and the intent-row deadlines in SPEC-6; the terminate edges in SPEC-7. Each CODE deliverable cites its rule by spec heading in a `// spec:` comment.

### CODE-1 · One gateway-owned, bounded context at the hook entry, and detached gateway-decided writes

Targets: `pkg/gateway/sessionserver/terminal_hook.go`, `pkg/gateway/sessionserver/usage.go`, `pkg/gateway/sessionserver/sessionserver.go`, `pkg/gateway/sessionserver/session_terminal.go`, `cmd/lenny-gateway/session_admin.go`, `pkg/gateway/externalapi/admin/sessions.go`, `cmd/lenny-gateway/session_budget.go`.

1. In `sessionserver.go`, add

   ```go
   // TerminalPipelineBudgetFor is the one computation of the §7.1 terminal
   // pipeline budget: the seal window plus the release allowance
   // (--stream-failure-report-timeout). A non-positive allowance falls back to
   // DefaultStreamFailureReportTimeout. The server's budget, the §5.2 startup
   // gate, and the session-store window cap call it, so they take one value.
   // spec: §7.1 (Terminal pipeline context)
   func TerminalPipelineBudgetFor(sealWindow, releaseAllowance time.Duration) time.Duration {
   	if releaseAllowance <= 0 {
   		releaseAllowance = DefaultStreamFailureReportTimeout
   	}
   	return sealWindow + releaseAllowance
   }

   // terminalPipelineBudget is the §7.1 terminal pipeline budget: the seal
   // window plus the release allowance (--stream-failure-report-timeout).
   // spec: §7.1 (Terminal pipeline context)
   func (s *Server) terminalPipelineBudget() time.Duration {
   	return TerminalPipelineBudgetFor(s.sealMaxDuration, s.streamFailureReportTimeout)
   }

   // TerminalPipelineBudget exports terminalPipelineBudget for the shutdown
   // wait.
   func (s *Server) TerminalPipelineBudget() time.Duration { return s.terminalPipelineBudget() }

   // terminalContext detaches ctx from its caller's cancellation and bounds
   // it by what remains of the terminal pipeline budget counted from
   // terminatedAt, the instant the §5.2 stale slot release ages the session
   // from. A zero terminatedAt, which that release never ages, gets the
   // whole budget. spec: §7.1 (Terminal pipeline context)
   func (s *Server) terminalContext(ctx context.Context, terminatedAt time.Time) (context.Context, context.CancelFunc) {
   	remaining := s.terminalPipelineBudget()
   	if !terminatedAt.IsZero() {
   		remaining = min(remaining, remaining-s.clock().Sub(terminatedAt))
   	}
   	return context.WithTimeout(context.WithoutCancel(ctx), remaining)
   }
   ```

   `context.WithoutCancel` keeps the caller's values (trace span, tenant), so the seal span still stitches under the writer's trace. Measure the elapsed time on `s.clock` rather than with `time.Now` or an absolute `WithDeadline`, so a hook test's fake server clock does not hand the pipeline an already-expired context.

### CODE-4 · Seal outcome fixes, the closing gate, and the intent-row deadline

Targets: `pkg/gateway/checkpoint/checkpointer/checkpointer.go`, `pkg/gateway/checkpoint/checkpointer/uploaddriver.go`, `pkg/gateway/sessionserver/seal.go`, `pkg/gateway/sessionserver/terminal_hook.go`, `pkg/gateway/podlifecycle/podsession/bindrequest.go`, `pkg/gateway/session/executor/pod.go`, `pkg/gateway/session/executor/executor.go`.

1. **Closing mark.** `BindResult` gains an atomic `closing` flag with `MarkClosing()` and `Closing() bool`. Once set it is never cleared; a new binding is a new `BindResult`.
2. **streamFor refuses a closing binding.** Under `e.mu`, on both the cache hit and the cache miss, `streamFor` returns `fmt.Errorf("podexec: session %s: %w", sessionID, ErrSessionSealed)` when the registry's `BindResult` for the session reports `Closing()`. On a cache hit the check reads the registry entry for the session, so an evicted-then-reopened path cannot bypass it.
3. **Send converts the refusal.** `PodExecutor.Send` returns `&SealedError{Delivered: 0}` when `streamFor` returns `ErrSessionSealed`, before any message is written. Every `Send` caller then takes its existing sealed-reroute branch: REST `deliverNow` through `errors.As` on `*executor.SealedError`, MCP through `errors.Is`, and held delivery through its `%w` wrap. A bare sentinel would reach REST `deliverNow`'s fallthrough and surface as `EXECUTOR_FAILURE`.
4. **Doc comments.** Widen the `ErrSessionSealed` and `SealedError` doc comments to cover the terminal-seal closing mark (`// spec: §7.1 (Delivery and checkpoints during the seal)`) as well as the §4.7.1 idle-suspension refusal.
5. **Seal start.** In `sealWorkspace`, before the retry loop, read `s.podRegistry.Get(sess.ID)`. With no binding (or a nil registry), skip the `Seal` call and return nil, which is the outcome today's no-op seal records. With a binding, call `MarkClosing()` on it, then `EvictStream(sess.ID)` through the existing `streamEvicter` seam when `s.executor` satisfies it, then enter the loop. The existing tests that build the server with a `Sealer` and no `PodRegistry` (`seal_internal_test.go`, `seal_span_internal_test.go`, and `TestTerminalTransitionSealsTheWorkspaceBeforeClosing` in `session_close_test.go`) register a binding in a `podsession.Registry` passed as `Options.PodRegistry`. In `driveCheckpoint`, after `lockFlight` returns, an attempt whose source is not `sealed` returns `ErrNoBinding` without opening a stream when the binding reports `Closing()`; `snapshot` passes its source in, because `Seal` stamps `TriggerPeriodic` and the trigger cannot tell a seal apart. The periodic sweep, the barrier, and the preStop loop all reach it through `CheckpointWithTrigger`.
6. **Binding lost during the loop.** After a `Seal` error, when `s.podRegistry.Get(sess.ID)` reports no binding, record `sealOutcomePermanent` and return the error. `Checkpointer.Seal` no longer maps `ErrNoBinding` to nil; delete that branch, and keep no second mapping path. `TestSealNoOpsForAnUncoordinatedSession_spec_7_1` (`checkpointer_test.go`) asserts `ErrNoBinding`, under a name stating that.
7. **Absent row.** The Checkpointer's row read (see CODE-5 item 2) returns `sessionstore.ErrNotFound` for a row absent on the primary. `isPermanentSealError` adds `errors.Is(err, sessionstore.ErrNotFound)`. Adapter gRPC `NotFound` stays transient.
8. **Release disposition after a failed seal.** In `afterTerminalWrite`, record `sealFailed := true` when `sealWorkspace` returns an error. `releaseAfterTerminal` takes the disposition as a parameter, and the hook passes `executor.DispositionFailed` when `sealFailed` is set and `dispositionForState(sess.State)` otherwise. The relabel's returned row no longer decides the disposition, so a relabel store error cannot produce the clean disposition.
9. **Intent-row deadline.** In `driveCheckpoint`, when `c.Deadline` is zero and the parent context carries no deadline, derive the attempt's context with `context.WithTimeout` of the §4.4 checkpoint timeout (60 s) in place of `context.WithCancel`, so every attempt's context carries a deadline. In `uploaddriver.go`, where the intent row is built, set `CheckpointTimeoutAt` to that deadline. For a seal the context carries the `sealWorkspace` window (`context.WithTimeout(ctx, s.sealMaxDuration)` in `seal.go`) inside the CODE-1 budget context, and for a periodic attempt on the `Run` context it carries the 60 s timeout. Production leaves `Checkpointer.Deadline` zero (`cmd/lenny-gateway/pod_lifecycle.go`), so without this item every row's `CheckpointTimeoutAt` equals its `CheckpointStartedAt` (D21).

Cite `// spec: §7.1 (Seal-and-export invariant)` on items 5 to 8, `// spec: §10.1.7 (preStop Hook Drain), §7.1 (Terminal pipeline context), §4.4.3 (Checkpoint timeout and recovery)` on item 9, `// spec: §7.1 (Delivery and checkpoints during the seal)` on the item 5 checkpoint skip, and `// spec: §7.1 (Delivery and checkpoints during the seal)` on items 1 to 3. The seal export uses the separate `Adapter.Checkpoint` RPC, so evicting the Attach stream does not disturb it.

## Edge cases and accepted failure modes

- A claim opened by a background loop during the shutdown wait extends the wait up to the budget bound (CODE-2).
- A committed write that the CODE-3 read-back classifies as not applied takes the outcome SPEC-5 states.
- A row absent on the replica but present on the primary releases nothing (CODE-5 item 2).
- A periodic checkpoint that starts after the resume carries the resumed generation and is left by cleanup (CODE-7 item 2).
- An old residue row behind a live row is left to the §12.5 backstop (CODE-7 item 2).
- A collapse-path `completed` session that never seals is collectable under the CODE-7 item 1 predicate.
- A release whose record write fails, or a pipeline that ends with no release on this replica, leaves the session in its post-terminal window until the cap (CODE-7 item 5 (d)). A slot member that the seed re-adds in that interval is removed by the stale-slot reaper or, as a pod's last member, by the orphaned-claim drain.
- A §12.8 erasure or tenant deletion whose scope holds a session in its post-terminal window waits under CODE-7 item 6, for at most the cap of CODE-7 item 5 (b).
