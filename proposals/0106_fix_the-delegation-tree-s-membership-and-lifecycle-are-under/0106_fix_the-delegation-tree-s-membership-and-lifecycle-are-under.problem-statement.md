# Problem: Delegation tree membership and lifecycle code departs from the specification, and the specification is silent on cascade convergence and orphan selection

## Statement

The delegation tree code departs from rules the specification already states, and the specification is silent or inconsistent on a smaller set of lifecycle points (plan item P4a). The BUILD-GAPS members are F-8.2.30, F-8.8.18, F-8.8.19, F-8.9.13, F-8.10.17, and F-8.10.19 to F-8.10.26. Validation found that F-8.10.24 no longer holds and that approved proposal 0104 already stages most of F-8.10.17.

Code that does not conform to existing specification text:

- Derive and replay set `ParentSessionID` to the source session and inherit `root_session_id` through the store insert, so the orphan sweeper, the `usage.go` cascade, `cancel_child`, tree recovery, lease registration, and sibling messaging scope all treat a derived or replayed session as a delegated child (F-8.9.13, High). The specification already makes a derived session a new independent root that forms a new tree (§12.6 StoreRouter), calls a replay a new independent session (§15.1 Session Replay Semantics), identifies root sessions by `parent_session_id IS NULL` (§12.8 erasure step 16), and records derive lineage in `parent_workspace_ref` (§4.5 Workspace lineage, §7.1). A new lineage field is therefore optional. The required change is that derive and replay stop writing `parent_session_id` and `root_session_id`. The specification does not state outright which column defines tree membership, and replay's lineage pointer is stated only through `parent_workspace_ref`.
- Tree recovery bounds a node by `ResumeEligibleUntil`, which creation sets to `CreatedAt` plus the resume window. A node whose window has already elapsed gets no individual bound, falls to the level or tree budget, and ends `failed`. §8.10 "Interaction with `maxResumeWindowSeconds`" says such a node transitions to `expired` (F-8.10.19, High). The fix anchors on the store-owned `state_entered_at` instant that approved proposal 0105 introduces.
- Tree recovery fails unrecovered nodes in one pass after the whole traversal returns. §8.10 says unrecovered nodes at a level are marked failed before the gateway continues upward (F-8.10.21).
- `FailNode` writes `failed` or `expired` through `nonTerminalGuard`, which admits a `resuming` row, so tree recovery races the resume driver on a node mid-resume (F-8.10.20). 0105's §7.2 "Terminal writes from any non-terminal state" paragraph does not list tree recovery's `FailNode` among the writers it admits.
- A detach descendant that the cascade cancels runs `AfterTerminalWrite` with `archiveSettledChild` as its signal tail, so its own `cascadeToChildren` and the `maxOrphanTasksPerTenant` check never run. §8.10 states the cap fallback without an exemption for cascaded descendants (F-8.10.26).
- The deadlock fail closure fails any non-terminal row without re-checking that the `request_input` wait is still pending (F-8.8.18), and `Manager.Observe` records the `timeout` resolution and deletes the active entry before the guarded write runs (F-8.8.19).
- The delegated child materializer runs `rollbackClaim` and `rollbackBinding` on the `delegate_task` request context, so a cancelled request abandons the rollback (F-8.2.30). This needs no specification change.

Points the specification does not settle:

- Convergence and retry ownership for the `usage.go` cascade and `cancelSubtree`. The cascade takes one `List`, returns on a `List` error, and skips a node whose `Update` fails with no retry owner. `cancelSubtree` walks the caller's pre-cancel `ListByRoot` snapshot and returns on the first `cancelNode` error, leaving the rest of the subtree live (F-8.10.22, F-8.10.23). Approved 0104 CODE-2 item 7 stages the per-level re-listing from the primary. Retry of a failed `List` or `Update` and continuation past a per-node error remain unstaged.
- Orphan selection. The §8.10 orphan-cleanup paragraph detects only nodes "whose root session has been terminated", and the sweeper follows that text. The §8.10 cascade table bounds `await_completion` and `detach` children of any terminated parent by `cascadeTimeoutSeconds`. The children of a terminal non-root parent are never bounded while the root lives, and when the root row is gone `treeRoot` stops at the deepest reachable ancestor, which can be non-terminal (F-8.10.25).
- The fence between a `delegate_task` admitted before the parent's terminal write and the cascade (F-8.10.17). Approved 0104 D6, CODE-2, and SPEC-3 Edit (a) stage that fence in §12.8, and 0092 guards the materializer's running commit on the child row still being `created`. 0106 records F-8.10.17 as discharged by 0104 and adds only what remains after 0104 lands.

The proposal settles these points against the implemented 0092 and 0100 and the approved 0104 and 0105, sequences the tree-recovery and deadlock members after 0105, sequences the cascade members after 0104 CODE-2 and 0105 CODE-4 and CODE-5, and implements the members with expansive tests across the tiers each change reaches.

## Who observes it

- A client that derives or replays a session. Derive by default requires a terminal source (`DERIVE_ON_LIVE_SESSION` without `allowStale`, `derive.go:233-236`). When that source's tree root ended more than `cascadeTimeoutSeconds` (default 3600s) ago, the production orphan sweeper force-expires the new session with `FailureExpiredDeadline` on its next 60s tick. The same client sees the derived session skipped by §8.6 lease registration (`pkg/gateway/sessionserver/delegation_seams.go:74-77`), placed in `siblings` messaging scope with other sessions derived from the same source (`pkg/gateway/mcpfabric/mcptools/messaging.go:148-152`), and cancelled by a live source's `cancel_all` cascade (`usage.go:746-783`).
- A parent whose long-lived child reaches `resume_pending` after its creation-relative window elapsed. The parent observes `failed` where §8.10 prescribes `expired`, with the corresponding failure class.
- A tenant whose `await_completion` or `detach` children sit under a terminal non-root parent, or under a hard-deleted root. Those children keep pods and per-user concurrency with no lifetime bound, against §8.10's statement that `cascadeTimeoutSeconds` bounds exposure.
- A tenant whose cascaded detach descendants exceed `maxOrphanTasksPerTenant`. The cap fallback never fires for them.
- An orchestrator calling `cancel_child`. One failed `cancelNode` leaves the rest of the subtree running and returns an error after a partial cancel.

## What breaks if nothing changes

- Derived and replayed sessions are force-expired an hour after their source tree ended and are exposed to the source tree's cascade, so derive and replay are unreliable for any source older than `cascadeTimeoutSeconds`.
- Tree recovery reports the wrong terminal state for elapsed nodes, fails nodes later than §8.10 allows, and can write a terminal state over a node the resume driver is bringing back.
- A cascade or `cancel_child` that hits one transient store error leaves live descendants under a terminal ancestor with nothing to retry them, and orphan cleanup does not reach the ones under a non-root parent.
- The deadlock detector can fail a task whose wait was already answered and records a timeout for a write that may not apply.
- A cancelled `delegate_task` request can strand a claimed pod or binding.

## Validated premises

- **Derive and replay set `ParentSessionID` and inherit `root_session_id`.** Confirmed by the premise, evidence, impact, and alternatives lenses (`derive.go:416`, `replay.go:184`, `pgstore.go:293-302`).
- **"The specification has no lineage field distinct from parentSessionId."** Refuted by the premise, evidence, prior-art, and alternatives lenses. `parent_workspace_ref` is the specified lineage pointer (§4.5, §7.1), §12.6 and §15.1 make derived and replayed sessions independent, and §12.8 identifies roots by `parent_session_id IS NULL`. F-8.9.13 is a conformance defect. A new lineage field is optional. The scope lens proposed adding a lineage field to §8.9 and §15.1; that proposal rested on this refuted premise.
- **"The specification does not state which sessions belong to a tree."** Refuted for derive and replay by the same evidence. It holds only in the narrow sense that no sentence names the membership column.
- **F-8.9.13 reaches clients.** Confirmed by the impact lens: a derived or replayed session whose source tree ended more than `cascadeTimeoutSeconds` ago is force-expired on the next sweep, and it is also skipped by lease registration, placed in sibling scope, and exposed to the source's cascade. The premise lens independently confirmed the orphan-cleanup and cascade consequences.
- **F-8.10.19: the resume deadline is computed from `CreatedAt` and an elapsed node is failed.** Confirmed by every lens that checked it, with the mechanism stated precisely: `ResumeEligibleUntil` is creation-relative, a past deadline yields no individual bound, and the level or tree budget fails the node.
- **"The specification does not state how tree recovery bounds and ends a node."** Refuted by the premise and alternatives lenses: §8.10 prescribes `expired` for an elapsed resume window and per-level failure. F-8.10.19 and F-8.10.21 are conformance defects.
- **F-8.10.20: `FailNode` writes over a `resuming` node.** Confirmed by the premise, evidence, and prior-art lenses. After 0105 the terminal edge from any non-terminal state is legal for the writers 0105 lists, and tree recovery is absent from that list, so the residual is the race with the resume driver.
- **F-8.10.21: unrecovered nodes are failed only after the whole traversal.** Confirmed by the premise and evidence lenses.
- **F-8.10.22 and F-8.10.23: one-shot snapshot traversals.** Confirmed by the premise, evidence, impact, and prior-art lenses. The prior-art lens found that 0104 CODE-2 item 7 stages the re-listing half; retry ownership and continuation past errors remain.
- **F-8.10.24: the unguarded cascade overwrites a node `cancelSubtree` cancelled and returns its budget twice.** Refuted by the premise, evidence, prior-art, scope, and impact lenses, and re-verified here: both writers apply only over a non-terminal locked row since 3f943f56f (2026-10-13), and the finding was filed on 2026-10-12 against 319b80091, which lacks the guard. The alternatives lens treated the budget leg as a live conformance defect without checking the current tree; that reading does not survive.
- **F-8.10.17: a child admitted before the parent's terminal write is never cancelled.** Confirmed in current code by the premise and evidence lenses. The prior-art and scope lenses showed that approved 0104 D6 stages the fence, so it leaves the scope of 0106 except for any residual after 0104 lands. The alternatives lens called the fence spec-silent; 0104 SPEC-3 Edit (a) is the staged text.
- **F-8.10.25: orphan cleanup misses non-root-parent and hard-deleted-root orphans.** Confirmed by the premise, evidence, impact, and alternatives lenses as a specification gap: the §8.10 orphan-cleanup paragraph is keyed on the root, which is inconsistent with the cascade table's per-parent bound.
- **F-8.10.26: cascaded detach descendants skip the orphan-cap fallback.** Confirmed by the premise and evidence lenses. The alternatives lens showed §8.10 already states the fallback, so it is a conformance defect.
- **F-8.8.18 and F-8.8.19: the deadlock closure does not re-check the wait and counts before the write.** Confirmed by the premise and evidence lenses. The scope and prior-art lenses tie the re-check to 0105 D13's wait identity.
- **F-8.2.30: materializer rollback on the request context.** Confirmed by the premise and evidence lenses. The scope lens showed it needs no specification change.
- **The statement's code locations.** Refuted by the evidence lens: the materializer, deadlock, tree recovery, and orphan cleanup are not in `pkg/gateway/mcpfabric/delegation`, and the deadlock closure in `cmd/lenny-gateway/reconciler_workers.go` was omitted. The Evidence section above carries the corrected locations.
- **One proposal for all members.** Contested by the scope lens, which found four specification questions plus code-only fixes with different dependencies and recommended cutting membership (F-8.9.13) out first, then cascade reach, then tree recovery, with deadlock and F-8.2.30 riding along. After validation, membership and recovery reduce to conformance work against existing text, which weakens the case for separate proposals. The cut remains a sequencing decision for the drafting stage.
