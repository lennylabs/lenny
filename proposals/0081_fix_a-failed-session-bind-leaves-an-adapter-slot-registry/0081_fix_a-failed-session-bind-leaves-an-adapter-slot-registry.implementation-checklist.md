## Implementation checklist

Every spec step leads. Each implementation step carries the tests for the tiers its line
names, per `## Testing` in the non-spec changes file. Every step runs tier 0, registers its
tests in `tests/spec-map.json` under the sections its `// spec:` annotations cite, carries a
`// diagnosis:` comment at tier 2 and above, and cites the specification by heading. A step
that changes the wire or adds a normative claim adds its `tests/claim-map.json` rows by
editing the `EXPLICIT` list in `scripts/seed-claim-register.py` and regenerating from it in
the same commit.

One ordering rule governs the code lane beyond the dependency lines below: the gateway learns
to send the new fields before the adapter begins requiring them. S12 mints and carries the
attempt token and sets `unconditional_teardown` at every non-compensating `Shutdown` caller;
S13 and S15 then refuse a request that carries neither. Landing them in the other order
refuses every bind and every teardown in the window between the two steps.

The block states the refusal of a request whose non-empty token differs from the entry's non-empty token, the refusal of a request whose `mid_session` is false against an entry whose session has started, the requests exempt from that refusal, the rule that a request whose `mid_session` is true never creates an entry and meets `FailedPrecondition` when none exists, the rule that `bind_attempt` is non-empty exactly when `mid_session` is false, and `Shutdown`'s requirement that exactly one of a non-empty `bind_attempt` and `unconditional_teardown` is set. §15.4 is re-cut to the published non-conformance clause set, carrying forward the four clauses that survive: that `superseded` and `absent` are successful outcomes answered on a successful RPC, the resolve-once rule on `PrepareWorkspace`, that `Resume` stamps the entry it creates, and the slot-identifier reclaim-hold contract, which is not rewritten. §15.1 gains a catalog row for `ERROR_CODE_SLOT_BIND_ALREADY_STARTED` and for `ERROR_CODE_SLOT_BIND_ATTEMPT_SUPERSEDED` with each code's category and HTTP status, and the false claim that §15.1 mints no client-visible error code comes out of the deliberately-untouched list. The gateway sends the compensating `Shutdown` at every post-connection bind failure and at a failed `Resume`, on a detached context, carrying the token its own attempt minted. It suppresses the compensation entirely when the failing stage was refused with either typed code, because a refusal means another attempt owns the entry.
