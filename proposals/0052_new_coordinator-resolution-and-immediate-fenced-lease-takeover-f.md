# Proposal: Coordinator resolution and immediate fenced lease takeover for agent-pod eviction checkpoints

- **Status:** Approved (2026-07-22). Verified (2026-07-20) after 3 adversarial review rounds (2 findings fixed). Trigger-seam open decision resolved on sign-off: the eviction signal reaches the coordinator directly (the agent pod's preStop signals its own coordinator over the existing control channel), so C1 is the whole change; the arbitrary-landing takeover, the forward-to-holder transport, and any takeover-primitive naming are deferred to the trigger-wiring proposal.
- **Date:** 2026-07-20.
- **Scope:** Classified `new`. This is prerequisite 2 of the pre-approved prerequisite-first sequence for the §4.4/§4.6.1 individual agent-pod eviction-checkpoint trigger (prerequisite 1, slot-aware checkpointing, landed as proposal 0050). The draft entered adversarial review proposing a new §10.1 "immediate forced takeover of a still-live coordination lease" subsection, a forced-steal `LeaseStore.Steal` primitive on all implementers, a coordinator-resolution layer, and a takeover-mode fence policy. Review reduced it to the change the existing surfaces do not already cover: a one-sentence §4.6.1 clarification stating how an evicted agent pod's preStop reaches its coordinating gateway replica. It stages a single spec-prose edit to `spec/04_system-components.md` §4.6.1 (**C1**). The forced-steal primitive (former **C2**), the coordination-layer takeover fallback (former **C3**), and the standalone test change (former **C4**) are all recorded in Non-goals with the reasons review dropped them. An unreachable coordinator is recovered through the existing §10.1 TTL-driven handoff rather than through a new within-grace-window takeover, because a still-held coordination lease cannot be acquired by a non-holder replica without a forced-acquisition primitive the leasestore holder invariant forbids. This proposal produces the coordinator-direct routing statement; it does not drive `CheckpointWithTrigger(TriggerEviction)` itself, so it unblocks but does not close T-4.4.14 (`TEST-GAPS.md:639`) or T-4.6.4 (`TEST-GAPS.md:825`). It closes no C-22 finding by itself.

This document stages the proposed spec and code changes. It does not modify any spec, code, or doc file. Apply the changes in the "Proposed changes" section after sign-off.

## 1. Problem

Under §10.1 a session is coordinated by the single gateway replica holding the session-coordination lease (the §12.2/§12.4 key `t:{tenant_id}:lease:session:{session_id}`), and the §4.4 checkpoint driver runs only on that holder. The checkpointer returns `ErrNoBinding` on a non-holder replica (`pkg/gateway/checkpoint/checkpointer/checkpointer.go:33`, `:375-377`, `:426`), and `leasestore` refuses any non-holder Acquire, Renew, or Release through an atomic Lua holder check (`pkg/gateway/storage/leasestore/leasestore.go:13-14`, `:127-161`, `ErrHeld`/`ErrNotHeld` at `:35-41`). Two gaps stand between an eviction signal and a driven eviction checkpoint.

### (A) The eviction signal has no defined route to the coordinator

`spec/04_system-components.md:489` states that the preStop hook on an agent pod "triggers a checkpoint via the runtime adapter's `Checkpoint` RPC before allowing termination." The `Checkpoint` RPC is gateway-driven: the coordinating replica opens the stream (`CheckpointWithTrigger`, `checkpointer.go:375`), and the pod's own preStop hook cannot open it. The spec does not state how the preStop reaches the coordinating replica so that the coordinator drives the checkpoint. The gateway opens the bidirectional control channel once per pod, and the coordinating replica is the replica that holds it (`pkg/adapter/controlchannel.go:81`); the adapter already pushes self-initiated terminal events to that coordinator over the same channel (`EmitAdapterTerminating`, `controlchannel.go:212-216`; the §4.7 `AdapterTerminating` event at `spec/04_system-components.md:679`, `:688`). The route the preStop needs already exists as a control-channel event. The spec omits the sentence that names it for the eviction case.

### (B) No immediate fenced takeover for a still-live lease

Cross-replica takeover today runs only through TTL-driven crash recovery. The coordination `Sweeper` calls `leasestore.Acquire` per session per sweep, skips a lease held by a live replica with `ErrHeld` and continues (`pkg/gateway/coordination/coordination/coordination.go:102`, `:134`), and adopts a foreign session only after that replica's lease TTL-lapses on a crash. That path is structurally inapplicable to an individual agent-pod eviction that leaves the coordinating gateway replica alive and renewing: the lease never lapses. The relevant residual case is a coordinator that is itself unreachable within the pod's termination grace window, where TTL expiry can outlast the grace window. `leasestore` exposes no forced-acquisition entry point on its interface (`leasestore.go:58`) or on any implementation, so there is no primitive to take over a lease inside the grace window without waiting for TTL.

The §10.1 fencing foundation for the normal and crash-recovery handoff already exists at the coordination layer. §10.1 defines the handoff protocol at `spec/10_gateway-internals.md:30-34`: the acquiring replica reads the session row, increments `coordination_generation` through a session-row compare-and-swap keyed on the expected generation (`spec/10_gateway-internals.md:33`), then fences. The code implements this handoff with a different election surface than the spec's generation CAS. Election is `leasestore.Acquire`'s atomic holder check (a non-holder receives `ErrHeld`), and the generation is bumped by `RecordHandoff`'s unconditional monotonic increment (`coordination.go:168-176`), which the store floors per §4.2 and which carries no expected-generation predicate and returns no 0-row result. The `CoordinatorFence` handshake then announces the new generation so the pod rejects a prior coordinator's straggler RPCs with `FailedPrecondition` (`spec/10_gateway-internals.md:34`; `coordfence.Fencer`, invoked on the new coordinator's re-establishment at `pkg/gateway/sessionserver/start.go:3611`). This handoff runs only after a successful `Acquire`, so it cannot take over a lease that a live, renewing holder still owns.

This proposal is prerequisite 2 of the eviction sequence (prerequisite 1, slot-aware checkpointing, landed as proposal 0050). It unblocks but must not claim to close T-4.4.14 (`TEST-GAPS.md:639`, the gateway never drives the individual agent-pod eviction trigger) or T-4.6.4 (`TEST-GAPS.md:825`, node-drain checkpoint-before-eviction); both close when the trigger ships.

## 2. Decisions

- **Classified `new`, and reduced to the gap the existing surfaces do not cover.** The concrete staged edit is a §4.6.1 clarification of the coordinator-direct route (C1). The draft's new §10.1 "forced takeover of a still-live lease" subsection and its `LeaseStore.Steal` primitive are dropped, because the eviction signal reaches the coordinator over the existing adapter-to-gateway control channel and the live coordinator drives the checkpoint under its already-held lease. Per `spec-driven-development.md` the behavior is staged in the spec before code, so C1 lands the one sentence the spec is missing.
- **Coordinator-direct is the primary route.** The agent pod's preStop signals its coordinating gateway replica over the existing control channel, the same channel that carries `AdapterTerminating` (`controlchannel.go:212-216`; §4.7 at `spec/04_system-components.md:688`). The coordinator, which is the live session-coordination lease holder, drives the existing `CheckpointWithTrigger(TriggerEviction)` (`checkpointer.go:375`; already live on the gateway-drain path at `pkg/gateway/coordination/barrier/barrier.go:228`). This route needs no coordinator-resolution layer, no forced lease steal, and no §10.1 edit.
- **Recovery of an unreachable coordinator reuses the existing §10.1 TTL-driven handoff.** The existing `Sweeper` already recovers a lapsed coordination lease: it elects a single winner through `leasestore.Acquire`'s atomic holder check (a loser receives `ErrHeld` and skips the session, `coordination.go:133-137`), bumps `coordination_generation` through `RecordHandoff`'s monotonic increment (`coordination.go:168`), and the new coordinator fences on re-establishment (`coordfence.Fencer`, `start.go:3611`). This election rests on `Acquire`, and the code does not implement the spec's generation compare-and-swap. No new takeover primitive is built, so the draft's coordfence "takeover-mode relinquish-on-advance" flag is dropped: the existing `Acquire`-based election already elects a single winner, and a parallel policy would re-arbitrate a race `Acquire` already settles.
- **No forced takeover is built; the residual within-window case is deferred.** A coordinator that is unreachable while its lease is still live cannot be taken over inside the pod's termination grace window, because `leasestore.Acquire` returns `ErrHeld` to a non-holder and no forced-acquisition entry point exists (`leasestore.go:13-14`, `:129-140`). That case is recovered by the existing §10.1 TTL-driven handoff once the lease lapses, which may fall outside the grace window, in which case the session terminates before adoption. Closing that residual requires a forced-acquisition primitive (the dropped former C2) and is deferred to the trigger-wiring proposal, gated on the trigger-seam decision (Open decisions). The resolution decision layer and the classified-but-unactionable Forward outcome are likewise deferred.
- **Boundary with the trigger.** This proposal states the coordinator-direct route (C1). It does not drive the checkpoint and it builds no takeover. Driving `CheckpointWithTrigger(TriggerEviction)`, establishing the pod-adapter connection for it, and any within-window takeover of an unreachable coordinator are the trigger's responsibility (T-4.4.14).
- **Dual-store unavailability inherits §10.1's frozen-handoff rule.** No replica can increment `coordination_generation` while Postgres is unreachable (`spec/10_gateway-internals.md:43`, dual-store item 3), so no handoff occurs. In that state the eviction checkpoint degrades to the §4.4 minimal-session-state fallback (`spec/04_system-components.md:264`). Fail closed: on any handoff or fence uncertainty a non-holder replica does not drive an unfenced checkpoint.

## 3. How the eviction checkpoint reaches the coordinator

An individual agent pod is evicted by a node drain, the kubelet Eviction API, a cluster upgrade, or a direct pod delete. The pod's preStop hook runs inside the pod and cannot open the gateway-driven `Checkpoint` stream. The coordinating gateway replica already holds the per-pod control channel (`controlchannel.go:81`) and already holds the session-coordination lease, so it is the one replica that can both address the pod and drive the checkpoint.

On the coordinator-direct route, the preStop emits a terminal control-channel event to that replica, reusing the transport that already carries `AdapterTerminating`. The coordinator drives `CheckpointWithTrigger(TriggerEviction)` under its held lease, exactly as the gateway-drain path already does at `barrier.go:228`. No non-coordinator replica participates, so there is no lease to resolve and no lease to steal.

The residual case is a coordinator that is unreachable while its coordination lease is still live and renewing. The existing TTL Sweeper adopts the session only after that lease lapses, and TTL expiry (default 4×15s) can outlast the pod's grace window, so the session may terminate before adoption. No replica can take over a still-live lease inside the window, because `leasestore.Acquire` refuses a non-holder (`leasestore.go:129-140`) and no forced-acquisition primitive exists. Closing that residual requires the forced-acquisition primitive dropped in review (Non-goals) and is deferred to the trigger-wiring proposal. This proposal recovers an unreachable coordinator only through the existing §10.1 TTL-driven handoff.

## 4. Proposed changes

### C1. `spec/04_system-components.md` §4.6.1: state how the agent-pod preStop reaches its coordinator

**Target:** `spec/04_system-components.md` §4.6.1, the "Disruption protection for agent pods" paragraph at `:489`. The sentence to extend ends "triggers a checkpoint via the runtime adapter's `Checkpoint` RPC before allowing termination."

**Rationale.** §4.6.1 states that the preStop triggers a checkpoint via the gateway-driven `Checkpoint` RPC, but the preStop runs in the pod and cannot open that stream. The spec omits the one sentence naming how the preStop reaches the coordinating replica that can. The route already exists: the coordinator holds the per-pod control channel (`controlchannel.go:81`) and the adapter already emits self-initiated terminal events to it (`EmitAdapterTerminating`, `controlchannel.go:212-216`; §4.7 `AdapterTerminating` at `:688`). The edit names that route for the eviction case and resolves the actual gap using only existing surfaces. It introduces no new lease operation, RPC, or coordinator-resolution concept.

**Change.** After "before allowing termination." at `:489`, insert:

```markdown
The agent pod's preStop hook cannot open the gateway-driven `Checkpoint` stream itself; it signals its coordinating gateway replica over the per-pod adapter-to-gateway control channel (the same channel that carries `AdapterTerminating`, [§4.7](#47-runtime-adapter)). The coordinating replica is the replica holding the session-coordination lease ([§10.1](10_gateway-internals.md#101-horizontal-scaling)); on receiving the signal it drives the eviction checkpoint through the existing `Checkpoint` RPC with the `TriggerEviction` trigger under its held lease. When the coordinating replica is unreachable, its session is recovered through the [§10.1](10_gateway-internals.md#101-horizontal-scaling) TTL-driven coordinator handoff once its coordination lease lapses; no replica drives the eviction checkpoint until it holds that lease and has fenced the pod through the handoff, so no unfenced replica ever drives the checkpoint.
```

The final sentence records that recovery of an unreachable coordinator uses the existing §10.1 TTL-driven handoff, and it states the fail-closed rule (no unfenced checkpoint) so the code has a spec section to cite. It asserts no forced-steal primitive and no within-window takeover; both are deferred (Non-goals).

The coordination-layer takeover fallback the draft carried as **C3** is dropped; the reasons are recorded in Non-goals. No code file is applied by this proposal.

## 5. Non-goals

- **Wiring the agent-pod eviction trigger itself (T-4.4.14, `TEST-GAPS.md:639`).** This proposal states the coordinator-direct route. It does not drive `CheckpointWithTrigger(TriggerEviction)` from an evicted agent pod. The trigger and its checkpoint drive remain a separate proposal. This proposal unblocks but does not close T-4.4.14 or T-4.6.4 (`TEST-GAPS.md:825`).
- **A forced-steal `LeaseStore.Steal` primitive on the lease store (the draft's former C2).** The draft added a `Steal` primitive that force-overwrites a still-live, still-renewing session-coordination lease held by a healthy remote coordinator, breaking the invariant that a lease can never be stolen or renewed by a replica that does not hold it (`leasestore.go:13-14`, enforced by the holder-checked Lua scripts). Review dropped it: the case it uniquely enabled (seizing a functioning coordinator's live lease) never arises on the common path. A draining coordinator checkpoints its own coordinated sessions locally (`barrier.go:228` already drives `CheckpointWithTrigger(TriggerEviction)`), so no replica steals from it. A crashed or unreachable coordinator is recovered through the existing §10.1 TTL-driven handoff once its lease lapses, which elects a single winner through `leasestore.Acquire`'s atomic holder check (`coordination.go:133-137`) and bumps the generation through `RecordHandoff`'s monotonic increment (`coordination.go:168`) rather than force-overwriting a live lease. The §7.2 coordinator-routing pattern (`spec/07_session-lifecycle.md`, the `delivery: immediate` non-coordinator forward via the internal `ForwardMessage` RPC, tied to §10.1 per-session coordination) is the canonical route for an operation that only the coordinator can perform, and `pkg/gateway/sessionserver/messages.go` records that the minimal gateway currently elides that transport rather than lacking a design for it. Adding `Steal` would build a parallel mechanism where an existing pattern applies, contrary to preferring an existing surface over a parallel one and to minimal new protocol surface.
- **A within-grace-window takeover of a still-live coordination lease (the draft's former C3).** The draft built a coordination-layer takeover that, on observing an unreachable coordinator, would become the fenced coordinator inside the pod's grace window. It cannot be built on the reused surfaces. Becoming coordinator requires holding the session-coordination lease (§10.1), and `leasestore.Acquire` returns `ErrHeld` to a non-holder while the unreachable coordinator's lease is still live (`leasestore.go:129-140`), with no forced-acquisition entry point on the interface (`leasestore.go:58`). The draft also misattributed the §10.1 expected-generation compare-and-swap to `Sweeper.RecordHandoff`, which is an unconditional monotonic increment with no expected-generation predicate and no 0-row result (`coordination.go:168-176`); the code's actual single-winner election is `leasestore.Acquire`'s atomic holder check (`coordination.go:133-137`). An unreachable coordinator is therefore recovered by the existing §10.1 TTL-driven handoff once its lease lapses, which the `Sweeper` already performs. The residual case, the lease outlasting the grace window, requires the forced-acquisition primitive dropped above and is deferred to the trigger-wiring proposal, gated on the trigger-seam decision (Open decisions).
- **A standalone "write the tests" change (the draft's former C4).** The draft carried the tier-mapped tests as a separate change. Review folded them into the change that owns the code (C1) and into the standing `test-coverage.md` obligation, because a proposal change whose entire content restates a project rule and re-enumerates tests another change already lists adds no distinct work and risks two enumerations drifting apart. The tests are still required; they are owned by the change that owns each surface (see Testing).
- **Building the forward-to-holder inter-replica transport.** A holder-to-address registry plus an inter-replica RPC, or a Redis-stream signal keyed by holder replica, is new protocol surface coupled to the trigger seam. It is deferred to the trigger-wiring proposal (Open decisions).
- **Establishing a taking replica's pod-adapter connection and the podsession binding needed to drive the checkpoint.** Connecting to the terminating pod and driving the checkpoint over that connection are the trigger's responsibility.
- **Committing to the trigger seam (pod-to-gateway signal over the control channel versus a gateway-side pod informer).** No gateway-side agent-pod informer exists in code today (`pkg/gateway` carries only `pod_evicted` failure-reason handling in `sessionserver`, no pod watch). The seam is surfaced as an open decision that gates whether the trigger-wiring proposal needs a takeover.
- **Re-solving prerequisite 1 (slot-aware checkpointing).** Proposal 0050 landed `slot_id` on `CheckpointStart`, the slot-scoped `checkpointRoots()`, and the per-slot op lock. This proposal touches none of the checkpoint-capture path.
- **Prerequisite 3 (the agent-pod termination-grace-period arithmetic) and prerequisite 4 (a container-termination story for the runtime container).** The grace and TTL budget is referenced only as motivation; prerequisite 3 re-derives it, and this proposal does not assert it.
- **Changing the crash-recovery TTL takeover path, the CheckpointBarrier gateway-drain path (`barrier.go:228`, which already checkpoints locally coordinated sessions and needs no resolution), or the periodic checkpoint loop.**

## 8. Resolved in adversarial review

Subsequent adversarial review rounds populate this section. The drafting pass applied the following convergence revisions before first review.

- **C1 was reduced from a new §10.1 forced-takeover subsection to a one-sentence §4.6.1 clarification.** The draft staged a new §10.1 "immediate forced takeover of a still-live coordination lease" subsection on the premise that an individual agent-pod eviction signal lands on an arbitrary non-coordinator replica that must resolve the holder and either forward the drive or fence-and-steal the lease. That premise is uncommitted (the trigger seam is an open decision) and non-canonical (no gateway-side agent-pod informer exists in code). The existing surfaces already cover the need: the agent pod's preStop reaches its live coordinator over the per-pod control channel (`controlchannel.go:81`, `:212-216`; §4.7 `AdapterTerminating` at `spec/04_system-components.md:688`), and the coordinator drives the existing `CheckpointWithTrigger(TriggerEviction)` (`checkpointer.go:375`; `barrier.go:228`) under its held lease. The gap was that §4.6.1 does not state how the preStop reaches the coordinator. C1 now stages that one sentence and defers any forced-takeover machinery to a committed seam decision.
- **The forced-steal `LeaseStore.Steal` primitive (former C2) was dropped.** It force-overwrote a still-live, still-renewing lease held by a healthy remote coordinator, breaking the leasestore holder invariant (`leasestore.go:13-14`). The case it uniquely enabled never arises on the common path: a draining coordinator checkpoints locally (`barrier.go:228`), and an unreachable coordinator is recovered through the existing §10.1 TTL-driven handoff once its lease lapses rather than by force-overwriting a live lease (the drafting pass also proposed a C3 within-window fallback here; Pass 1 below drops it). The §7.2 coordinator-routing pattern (`spec/07_session-lifecycle.md`, the `ForwardMessage` forward tied to §10.1) is the canonical route for a coordinator-only operation on a non-coordinator replica, and `messages.go` records that transport as specced-but-unbuilt rather than absent. The drop is recorded in Non-goals.
- **C3 was reshaped and gated on the trigger-seam decision.** The resolution decision layer and the classified-but-unactionable Forward outcome were dropped until the seam and its inter-replica transport are decided, collapsing the operation to two live outcomes (AlreadyHolder, TookOver). The draft's coordfence "takeover-mode relinquish-on-advance" flag was dropped because the existing §10.1 handoff already elects a single winner through `leasestore.Acquire`'s atomic holder check (`coordination.go:133-137`); a parallel policy would re-arbitrate a race `Acquire` already settles. (Pass 1 below corrects this bullet's earlier attribution of the election to a generation compare-and-swap and drops C3 in full: `RecordHandoff` is an unconditional monotonic increment rather than a CAS, and no non-holder can acquire a still-live lease inside the grace window.)
- **The standalone test change (former C4) was folded into the change that owns the code.** Its content restated the `test-coverage.md` obligation and re-enumerated tests C1 already carries. The Testing section now maps each test to the change that owns its surface.

### Pass 1 (2026-07-20, automated)

- **C3's election surface was corrected: `RecordHandoff` performs an unconditional monotonic increment rather than the §10.1 expected-generation compare-and-swap.** The draft attributed the §10.1 step-1 CAS (the 0-row-relinquish election at `spec/10_gateway-internals.md:33`) to `Sweeper.RecordHandoff` (`coordination.go:168-176`), which has no return value, carries no `coordination_generation = $expected` predicate, and always persists a floored increment, so it produces no 0-row result and elects no single winner. The code's actual single-winner election is `leasestore.Acquire`'s atomic holder check (`coordination.go:133-137`; a loser receives `ErrHeld`). The generation-CAS and 0-row-relinquish tests premised on a return `RecordHandoff` never produces were removed with C3, and the misattribution was corrected in the Problem section, Decisions, and the prior Section 8 bullet. The correct citation for the 0-row relinquish is `spec/10_gateway-internals.md:33` (step 1 CAS), not `:32` (step 0 pre-CAS read).
- **C3's within-grace-window takeover was dropped: a non-holder cannot acquire a still-live coordination lease with the reused surfaces.** The residual case C3 targeted is an unreachable coordinator whose lease is still live and renewing. Becoming coordinator requires holding that lease (§10.1), but `leasestore.Acquire` returns `ErrHeld` to a non-holder (`leasestore.go:129-140`) and the interface exposes no forced-acquisition entry point (`leasestore.go:58`), so the TookOver outcome could neither acquire the lease it claimed to hold nor produce the "lease held" state, and the §10.1 handoff, which runs only after a successful `Acquire`, could not recover coordination inside the window as the draft asserted (contradicting Problem (B), which states no such primitive exists). With the forced-steal primitive already dropped in the drafting pass and forced acquisition ruled out by the leasestore holder invariant and the §10.1 TTL-driven precedent, C3 is dropped in full: an unreachable coordinator is recovered through the existing TTL Sweeper handoff once its lease lapses, and closing the within-window residual is deferred to the trigger-wiring proposal (Non-goals, Open decisions).

## 9. Open decisions for review

- **RESOLVED on sign-off (2026-07-22): coordinator-direct seam.** The eviction signal reaches the coordinator directly — the agent pod's preStop signals its own coordinating replica over the existing control channel — so C1 is the whole change and no forced takeover is built here. The arbitrary-landing seam, its within-window takeover and forced-acquisition primitive, the forward-to-holder transport, and any takeover-primitive naming are deferred to the trigger-wiring proposal. Implement C1 as staged.
- **Trigger-seam decision (gates whether a takeover is ever needed).** Does the eviction signal reach the coordinator directly (the agent pod's preStop signals its own coordinator over the existing control channel, so resolution collapses to the coordinator-direct route and a takeover is needed only when that coordinator is unreachable), or can it land on an arbitrary replica (a gateway-side pod informer event every replica receives, or a load-balancer-routed pod signal, which requires an observing non-coordinator to take over)? The coordinator-direct seam closes the gap with C1 alone. The arbitrary-landing seam additionally requires a within-window takeover, which needs a forced-acquisition primitive (Non-goals) and is deferred to the trigger-wiring proposal. This decision must precede any forced-takeover code rather than follow it.
- **Forward-to-holder transport scope.** If a takeover path is built in the trigger-wiring proposal, should it also build the inter-replica forward hop (a holder-to-address registry plus a new inter-replica RPC, or a Redis-stream signal keyed by holder replica), or defer it further? Building it adds new protocol surface. Deferring it means every remote-holder eviction takes over locally, losing a warm-connection optimization. The drafted design defers it.
- **Naming, if a takeover primitive is eventually needed.** The draft used `Steal` (matching the §25 remediation-lock subsystem's audited steal vocabulary) versus `ForceAcquire` or `Takeover`. The primitive is dropped in the current design, so this is moot unless a later seam decision reintroduces a forced-acquisition entry point.
