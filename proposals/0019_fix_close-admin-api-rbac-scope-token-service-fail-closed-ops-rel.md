- **Status:** Applied to spec (2026-06-29).
- **Date:** 2026-06-25.
- **Scope:** Reconciles the surfaces outside [proposal 0018](0018_fix_reconcile-the-gateway-external-rest-api-contract-and-close-l.md)'s gateway-REST scope against a converged adversarial review (`tmp/admin-cli-ops-api-review.md`): the gateway admin REST API (`pkg/gateway/admin`), the token service (`pkg/tokenservice`), the `lenny-ops` operability service (`pkg/ops`, `cmd/lenny-ops`), and `lenny-ctl` (`pkg/ctlcli`, `pkg/embedded/localcli`). Twelve findings survived two adversarial refutation rounds. The findings verified UPHELD or REVISED in `tmp/admin-cli-ops-api-review.md` are the scope source of truth. Findings refuted or judged by-design after both rounds are recorded in Non-goals.

## 1. Problem

A coherence review of the admin, CLI, and operability surfaces outside proposal 0018's gateway-REST scope surfaced behavioral security and reliability defects against a correct spec. The findings divide into four groups by surface: security and RBAC on the gateway admin API and the token service, reliability gaps in `lenny-ops`, host-assignment and correlation gaps, and CLI behavioral defects. Each finding is verified directly against `spec/`, `pkg/`, `cmd/`, `migrations/`, and `BUILD-GAPS.md`.

### 1.1 Security and RBAC gaps

- **ADM-1 (HIGH, tracked OPEN as 25.1-H2): the admin REST surface never enforces the per-route `x-lenny-scope` claim before routing.** The auth middleware parses `Scopes` onto the `Principal` (`pkg/gateway/middleware/auth/auth.go:466-487`) but performs no enforcement. `Router.Handler` wraps every route only in role checks (`r.requireAdmin` / `r.requirePermission`, `pkg/gateway/admin/tenants.go:577`) with no route-to-scope registry and no scope step. Only the four §25.9 audit handlers call `HasScope` (`pkg/gateway/admin/audit_query.go:291,571,899,1041`), and those return a generic `FORBIDDEN` with nil details (`audit_query.go:292`) rather than the `SCOPE_FORBIDDEN` with `details.requiredScope`/`details.activeScope` the §15.1 catalog row defines (`spec/15_external-api-surface.md:1030`). `spec/15_external-api-surface.md:914,920` and `spec/25_agent-operability.md:94` require the admin-API middleware to enforce per-route scope before routing. A scope-narrowed token is therefore honored at the full role ceiling on every non-audit destructive admin endpoint. ADM-1 additionally subsumes the prerequisite finding 25.1-H1 (`BUILD-GAPS.md`): the served `openapi.json` and the `me.go` tool catalog declare scope values in the `admin.<domain>.<action>` form, which the canonical matcher rejects (§1.4 below).
- **token_exchange_failed (MED, fail-open): the rejected-exchange path discards the rejection-audit write error.** `emitExchangeAudit` discards `auditor.Append`'s error with `_, _ =` (`pkg/tokenservice/tokenservice.go:665-670`), and the rejection path returns the original 4xx (`tokenservice.go:469-480`). `spec/13_security-model.md:589` mandates a `500 token_exchange_failed` when the rejection-audit write fails. In production the auditor is the durable Postgres `auditstore` (`cmd/lenny-token-service/main.go:197`), so a transient audit-store outage on the rejection path drops the audit record and returns the 4xx the client can retry, leaving no durable record of the rejection. Separately, the accepted-exchange non-outage write-before-issue failure emits `server_error` (`tokenservice.go:981`) where the spec names `token_exchange_failed`.
- **ADM-4 (MED, cross-tenant write): the extension-denial clear runs before the caller-tenant check.** `handleClearExtensionDenial` clears the durable row (`pkg/gateway/admin/lease_extension.go:54`) before reading the principal (`lease_extension.go:64`), with no caller-tenant-vs-tree-tenant check. The role gate admits any tenant-admin, and the clear scopes by the tree-owner tenant (`pkg/gateway/leasecontrol/membudget.go:459,465`), so a tenant-admin of tenant A clears tenant B's denial row given opaque session UUIDs. `spec/10_gateway-internals.md:261` states a tenant-admin cannot access other tenants' data, and `spec/15_external-api-surface.md:869` admits tenant-admin to this endpoint, so the spec is correct and the code is the defect.
- **ADM-2 (MED, under-grant): the legal-hold `POST` is gated platform-admin-only.** `POST /v1/admin/legal-hold` is registered platform-admin-only (`pkg/gateway/admin/tenants.go:752-753`) while `spec/15_external-api-surface.md:865` and the §10.2 RBAC matrix at `spec/10_gateway-internals.md:280` grant tenant-admin own-tenant set/clear. The `GET` list is already tenant-admin-capable (`tenants.go:756`), `pkg/gateway/admin/legalhold_test.go:168` pins the wrong gate, and the `POST` handler has no tenant binding, so widening the gate alone would open a cross-tenant write.
- **ADM-3 (MED, under-grant plus dropped provenance): the elicitation-integrity gate is platform-admin-only and the GET body is incomplete.** `GET`/`PUT /v1/admin/tenants/{id}/elicitation-content-integrity` are registered platform-admin-only (`pkg/gateway/admin/tenants.go:593-595`) while `spec/15_external-api-surface.md:823-824` grant tenant-admin own-tenant. The tenant row persists only `mode` (`pkg/gateway/admin/elicitation_integrity.go:163-167`; `pkg/gateway/tenantstore/tenantstore.go:86-91`); `justification`, `changedAt`, and `changedBy` go only to the audit event (`elicitation_integrity.go:206-209`); and the GET response omits `platformFloor`, `justification`, `changedAt`, and `changedBy` (`elicitation_integrity.go:22-27`). The spec already requires the GET body to carry `storedMode`, `effectiveMode`, `platformFloor`, `justification`, `changedAt`, and `changedBy` (`spec/15_external-api-surface.md:824`) and the PUT to record `mode`, `justification`, `changedAt`, and `changedBy` on the tenant (`spec/15_external-api-surface.md:823`), so the spec is correct and the code is the defect.
- **ADM-7 (LOW, uncataloged code): the 409 emit sites use an uncataloged string.** `RESOURCE_CONFLICT` is emitted at 15 sites across 13 admin files but is absent from the §15.1 catalog, which names the 409 duplicate-identifier code `RESOURCE_ALREADY_EXISTS` (`spec/15_external-api-surface.md:983`). Two of the 15 sites are state conflicts rather than duplicate-identifier conflicts: a compliance-profile optimistic-concurrency guard (`pkg/gateway/admin/tenants.go:2037`) and an upgrade-in-progress conflict (`pkg/gateway/admin/pool_upgrade.go:223`); the §15.1 catalog names `INVALID_STATE_TRANSITION` (`spec/15_external-api-surface.md:981`) for those. `errorclassify.ClassifyStatus` already yields `(PERMANENT, false)` via the 409 default (`pkg/gateway/errorclassify/errorclassify.go:68-76`), so only the uncataloged code string is non-conformant.

### 1.2 Reliability gaps in `lenny-ops`

The wired reconcilers (`cmd/lenny-ops/main.go:1035-1087`; `pkg/ops/opsservice/reconcile.go:50-65`) include no emission-retry loop, so an escalation created during a dual Redis-plus-gateway-buffer outage is recovered as a record but never pushed once a destination recovers.
- **F-DR-3 (MED, untracked): the drift target-snapshot writer and promoter are unbuilt.** The §25.8 upgrade orchestrator wires a delete-only `DriftCleaner` (`pkg/ops/upgradeservice/upgradeservice.go:249-252,498`) but no writer and no promoter. The durable store exists (migration 0117); F-25.10.5 is CLOSED store-only and its resolution states the call sites remain to be wired.
- **F-SH-1 (MED, untracked): the Postgres-Redis clock-skew gauge has no producer and no alert.** `SetClockSkew` (`cmd/lenny-ops/locks.go:124`) has zero producers, so the `lenny_ops_clock_skew_seconds` gauge always reads 0, and no alert references it. `spec/25_agent-operability.md:2280` mandates Postgres-Redis skew monitoring and a `>10s` alert (the gauge is cataloged at `spec/16_observability.md:712` and `spec/25_agent-operability.md:2336`). F-25.4.18 is CLOSED and does not cover the producer or the alert.

The identical gap exists on `handleCreateBackup` (`pkg/ops/opsserver/backup.go:143`), where `BackupRequest.OperationID` and the row propagation also already exist (`pkg/ops/backup/orchestrator.go:224`). ### 1.4 The ADM-1 scope-format prerequisite (finding 25.1-H1)

The ADM-1 enforcement step compares the caller's `scope` claim against each route's required scope. The served `openapi.json` declares the per-route `x-lenny-scope` values in the `admin.<domain>.<action>` form (for example `admin.tenants.write`), and `adminToolCatalog()` in `me.go` declares the same form. The canonical scope matcher `scopes.ParseScope` rejects anything without the colon-separated `tools:` prefix and rejects any domain absent from the closed `Domains` map (`pkg/common/scopes/scopes.go:105-134`), and `Set.Matches` returns false on that parse error (`scopes.go:216-237`). The §15.1 taxonomy, the §15.1 examples (`tools:circuit_breaker:read`), and the audit-handler constants (`tools:audit:partition_drop`, `audit_query.go:37-45`) all use the `tools:<domain>:<action>` form. A registry built from the current `openapi.json` values would yield `admin.tenants.write` while a narrowed JWT carries `tools:tenant:write`, and the two forms can never reconcile.

The mismatch is more than a mechanical prefix swap. After canonicalizing each served domain to the exact form the taxonomy carries (the singular underscore form for most domains, the plural `sessions` for that one), the served `openapi.json` `x-lenny-scope` values cover 35 distinct domains, of which 21 are absent from the `scopes.Domains` map (`scopes.go:50-78`): `artifact_replication`, `billing_correction`, `bootstrap`, `ca_rotation`, `connector`, `credential_rekey`, `delegation_policy`, `deployment`, `environment`, `erasure_job`, `external_adapter`, `impersonation`, `interceptor`, `issued_token`, `legal_hold`, `platform`, `preflight`, `rbac`, `schema`, `tree`, and `user`. Each backs a real destructive admin endpoint family (for example `POST /v1/admin/ca-rotation/begin`, `POST /v1/admin/billing-corrections`, `POST /v1/admin/impersonation`, `POST /v1/admin/deployment/config-change`, `POST /v1/admin/preflight`, `GET /v1/admin/platform/config`, and the `DELETE /v1/admin/trees/{rootSessionId}/subtrees/{sessionId}/extension-denial` route ADM-4 itself targets, all present in `openapi.json`). Two further domains, `sessions` and `experiment`, are present in `scopes.Domains` yet absent from the §15.1:918 taxonomy bullet, so the §15.1 taxonomy is missing 23 of the canonicalized served domains. The served forms also carry plural and dash variants (`tenants`, `circuit_breakers`, `credential-pools`, `delegation-policies`) that the taxonomy records in singular underscore form (`tenant`, `circuit_breaker`, `credential_pool`) and that the §15.1:933 CI syntax regex `^tools:[a-z0-9_]+:[a-z0-9_*]+$` (`openapi_test.go:166`) rejects outright for the dash. So the C1 rename to `tools:<domain>:<action>` is a per-domain mapping that must (a) expand the §15.1:918 closed taxonomy with the complete set of missing admin domains (a normative spec edit), (b) add the same domains to the `scopes.Domains` map (a code edit), and (c) map each served domain to the exact form the taxonomy and the `scopes.Domains` map carry, dropping the dash and matching the existing entry's number rather than applying a blanket plural-to-singular transform. Most served plural and dash forms map to a singular underscore entry (`admin.tenants.write` to `tools:tenant:write`, `admin.circuit_breakers.read` to `tools:circuit_breaker:read`, `admin.credential-pools.read` to `tools:credential_pool:read`), but `admin.sessions.read`/`admin.sessions.write` map to `tools:sessions:read`/`tools:sessions:write` because the existing taxonomy and map entry is the plural `sessions` (there is no singular `session` entry); a blanket plural-to-singular rule would emit `tools:session:*`, which neither the taxonomy nor the map carries, so `scopes.ParseScope` would reject it and `Set.Matches` would mis-deny every call to the two `admin.sessions.*` routes. Without the complete (a) and (b), the renamed values for any unenumerated domain fail the §15.1:933 CI contract, `scopes.ParseScope` rejects them at runtime, and `Set.Matches` mis-denies every call to that endpoint family regardless of the caller's scope (the exact 25.1-H1 failure ADM-1 must close). The format mismatch is the separate OPEN finding 25.1-H1 (`BUILD-GAPS.md`); ADM-1 cannot enforce scope until the served `openapi.json` and the `me.go` catalog are mapped to the canonical `tools:<domain>:<action>` taxonomy and the taxonomy is expanded to cover them. The exact set is derived programmatically from the served document on application so it cannot drift. C1 absorbs 25.1-H1 as a prerequisite step.

### 1.5 CLI behavioral gaps

- **F-CTL-7 (MED): `lenny image import` lacks the Embedded-Mode guard.** `cmdImageImport` (`pkg/embedded/localcli/image.go:52-90`) reaches `stack.CtrCommand` directly with no embedded-stack probe, so a clustered invocation yields exit 4 `K3S_UNAVAILABLE` where `spec/24_lenny-ctl-command-reference.md:282,291` mandate exit 3 `EMBEDDED_MODE_REQUIRED` ("same guard as `lenny token print`"). `cmdTokenPrint` already performs the guard (`pkg/embedded/localcli/token.go:63-66`; `exitEmbeddedModeRequired = 3` at `pkg/embedded/localcli/localcli.go:34`).
- **F-CTL-4 (MED): three admin mutating commands write non-JSON advisory lines to stdout.** `tenants force-delete` appends an advisory line after the JSON envelope (`pkg/ctlcli/main.go:1056`, after the `printJSON` at `:1055`), and `tenants delete` (`main.go:983`) and `external-adapters delete` (`main.go:1806`) emit an advisory line as their sole stdout output, breaking a strict `| jq` pipeline under `--output json`. `spec/24_lenny-ctl-command-reference.md:205` defines `--quiet` as the mechanism that suppresses informational messages, and the bootstrap path already routes advisory lines to stderr and gates them on `--quiet` (`pkg/ctlcli/main.go:2110-2114,2177-2193`). The review's "five" count (`tmp/admin-cli-ops-api-review.md:126`) is not borne out by code; a full grep of non-JSON stdout writes confirms exactly these three plus usage and version.

## 2. Decisions

- **Honor the review's where-the-fix-lands split.** Every in-scope finding is a code-vs-spec divergence against a correct spec, so the fixes land in code (`pkg/gateway/admin`, `pkg/tokenservice`, `pkg/ops`, `cmd/lenny-ops`, `cmd/lenny-gateway`, `pkg/ctlcli`, `pkg/embedded/localcli`) plus one new migration (ADM-3) and one §16.5 alert-rule addition (F-SH-1). `tmp/admin-cli-ops-api-review.md` is the scope source of truth; only findings tagged UPHELD or REVISED after both rounds are in scope.
- **Fix ADM-1 in code, absorbing the 25.1-H1 scope-format prerequisite plus a taxonomy expansion.** `spec/15_external-api-surface.md:914,920` and `spec/25_agent-operability.md:94` already mandate middleware-before-routing scope enforcement returning `403 SCOPE_FORBIDDEN`. The served `openapi.json` carries the `x-lenny-scope` extensions but in the malformed `admin.<domain>.<action>` form, and 21 admin domains it names (after canonicalization) are absent from the `scopes.Domains` map and 23 from the §15.1:918 closed taxonomy, so the canonical matcher would reject them even after a prefix swap (§1.4). C1 therefore (a) expands the §15.1:918 taxonomy and the `scopes.Domains` map with the complete set of missing admin domains (`artifact_replication`, `billing_correction`, `bootstrap`, `ca_rotation`, `connector`, `credential_rekey`, `delegation_policy`, `deployment`, `environment`, `erasure_job`, `external_adapter`, `impersonation`, `interceptor`, `issued_token`, `legal_hold`, `platform`, `preflight`, `rbac`, `schema`, `tree`, and `user` for the map, plus `sessions` and `experiment` for the taxonomy bullet, which the map already carries), reconciling the pre-existing drift where `scopes.Domains` carries `sessions`, `runtimes`, `pools`, and `experiment` that the §15.1:918 bullet omits, (b) maps the served `openapi.json` and `me.go` `adminToolCatalog()` values to the canonical `tools:<domain>:<action>` taxonomy, mapping each served domain to the exact form the taxonomy and the `scopes.Domains` map carry (dropping the dash and matching the existing entry's number; most plural and dash forms collapse to a singular underscore entry, while `admin.sessions.*` maps to `tools:sessions:*` because the existing entry is the plural `sessions`), then (c) builds a route-to-scope registry from the now-canonical openapi document and adds one scope-enforcement step in the admin `Router` before any destructive handler runs. The complete missing set is derived programmatically from the served document so the enumeration cannot drift. The taxonomy expansion (a) is a normative spec edit, so S1 is no longer the only spec change. The §15.1:933 CI contract (every endpoint carries a conforming `tools:<domain>:<action>` `x-lenny-scope` whose domain is in the taxonomy) must pass after the rename, verified for every admin endpoint.
- **Correct the four §25.9 audit handlers to `SCOPE_FORBIDDEN` and reconcile the three destructive routes' served scopes.** The audit handlers (`audit_query.go`) return generic `FORBIDDEN` with nil details; all four denial sites are corrected to `SCOPE_FORBIDDEN` with `details.requiredScope`/`details.activeScope` so the whole admin surface speaks one §15.1:1030-cataloged code. The three destructive audit routes (drop/retranslate/republish) carry the coarse `admin.audit.write`/`admin.audit.read` in `openapi.json` while each handler enforces a distinct fine-grained scope unconditionally at the top (`tools:audit:partition_drop` at `audit_query.go:291`, `tools:audit:retranslate` at `:899`, `tools:audit:republish` at `:1041`), and `scopes.Set.Matches` requires an exact action match (`scopes.go:232`), so a central registry built from the coarse values would make those three routes unreachable for every scope-narrowed token. C1 changes those three served `x-lenny-scope` values to the fine-grained forms the handlers already enforce (admitted by the §15.1:919 action taxonomy and the §15.1:933 regex, with `audit` already in `scopes.Domains`), so the central registry requires exactly what each handler requires and the per-handler `HasScope` checks on those three routes become genuinely redundant and are dropped. The `GET /v1/admin/audit-events/{seq}` route (`openapi.json:2756`) is left at the coarse `tools:audit:read`, because its handler gates `tools:audit:raw_canonical_read` only when `?format=raw-canonical` is present (`audit_query.go:569-576`) and serves the ordinary OCSF read with no fine-scope check (`audit_query.go:593-613`). Moving its route-level scope to the raw-canonical form would deny every plain OCSF read by a `tools:audit:read` token, a behavioral regression the spec does not call for (`spec/25_agent-operability.md:3653` requires the raw-canonical scope only for the `?format=raw-canonical` query parameter). Its per-handler conditional `HasScope(scopeRawCanonical)` check is therefore retained, since a query-parameter-conditional scope cannot be expressed as a route-level pre-routing gate.
- **Fix token_exchange_failed by inspecting the rejection-audit write.** Make `emitExchangeAudit` return the `auditor.Append` error, and on the rejection path return `500 token_exchange_failed` with the intended rejection reason in detail (fail closed per `spec/13_security-model.md:589`) instead of the current void discard. Map the accepted-exchange write-before-issue non-outage failure (`writeIssueStoreError`) to `token_exchange_failed` rather than `server_error`, and add `token_exchange_failed` to `is5xxErrorClass` so the renamed 500 still increments the §16.1 `lenny_oauth_token_5xx_total` counter. The Postgres-outage 503 branch is unchanged. This is the single canonical classification with no dual mode.
- **Fix ADM-4 by reusing the existing tenant resolver through a new Router seam.** The admin `Router` carries no tenant resolver and sees the lease source only through the narrow `LeaseDenialClearer` interface, so `TenantOf` is not reachable from the handler as the package stands. Add a `TenantResolver` field and a `WithTenantResolver` wiring method to the admin `Router` (mirroring `WithLeaseDenials`) and wire the existing `*MemoryBudgetSource` `leaseBudgets` value into it in `cmd/lenny-gateway/main.go`; that value already implements both `LeaseDenialClearer` and `TenantResolver.TenantOf` (`pkg/gateway/leasecontrol/leasecontrol.go:376-382`; implemented by `MemoryBudgetSource` at `pkg/gateway/leasecontrol/membudget.go:479`). The handler then resolves the tree's owner tenant, reads the principal up front, and for a non-platform-admin caller rejects `403 FORBIDDEN` when the resolved tree tenant differs from `p.TenantID` before the durable clear. The `LeaseDenialClearer`/`ClearSubtreeDenial` signatures are unchanged, so the fix reuses the existing resolver through a new wiring seam rather than widening the clearer interface. This mirrors the `authorizeTenantPath` confinement pattern (`pkg/gateway/admin/custom_roles.go:62-74`) and fails closed on a tenant mismatch or an unwired resolver.
- **Fix ADM-2 by widening the gate and confining the write.** Change the legal-hold `POST` registration from `requireAdmin` to `requireTenantResourceAdmin` (matching the tenant-admin-capable GET list), and add a body-tenant confinement in `handleSetLegalHold` so a non-platform-admin caller is rejected `403 FORBIDDEN` when the body's tenant differs from `p.TenantID`. Rewrite `TestSetLegalHoldRequiresPlatformAdmin` to assert a tenant-admin sets a hold on its own tenant, is rejected on a foreign tenant, and a platform-admin sets across tenants.
- **Fix ADM-3 by widening the gate, persisting provenance, and returning the full GET body.** Change the `GET`/`PUT` registrations to `requireTenantResourceAdmin` with the tenant-path binding, persist `justification`, `changedAt`, and `changedBy` on the tenant row via a new migration plus `tenantstore` fields, and return `platformFloor`, `justification`, `changedAt`, and `changedBy` in the GET response (`platformFloor` is already computable via `r.elicitationFloorValue()`). The spec already defines this body and gate, so this is a code fix against a correct spec.
- **Fix ADM-7 by renaming the emit sites to the cataloged codes.** Rename the 13 duplicate-identifier `RESOURCE_CONFLICT` emit sites to `RESOURCE_ALREADY_EXISTS` (`spec/15_external-api-surface.md:983`) and the two state-conflict sites (`tenants.go:2037`, `pool_upgrade.go:223`) to `INVALID_STATE_TRANSITION` (`spec/15_external-api-surface.md:981`). Both target codes are already cataloged, so no catalog edit is needed.
- **Fix F-REL-1 by wiring a leader-only emission-retry reconciler.** Add an `EscalationEmissionRetry` reconciler field and a 30s `EscalationEmissionRetryInterval` loop to `opsservice.Reconcilers`, wired in `cmd/lenny-ops/main.go` to call `escalationSvc.RetryEmission`. This extends the existing leader-only reconciler list rather than adding a new goroutine mechanism.
- **Fix F-DR-3 by building the missing new-pod OpsRoll startup path and wiring the writer and promoter onto it.** Add a `WriteTargetSnapshot` helper that `Put`s a `SnapshotTarget` row from the rendered Helm values, and an atomic `PromoteTargetToLive` on the `SnapshotStore` called at Verification completion. The §25.8 new-pod OpsRoll startup self-advance is unbuilt today: `RecordOpsHeartbeat` (`upgradeservice.go:542-564`) has zero non-test callers (`grep RecordOpsHeartbeat` returns only the definition and `watchdog_test.go:119,220`), it performs no phase transition (`upgradeservice.go:552-563` stamps `OpsHeartbeat` and returns; the only production advances run through `Service.Proceed`/`upgrade.Advance` at `upgradeservice.go:407-425`), no route in `pkg/ops/opsserver/platform_upgrade.go:21-39` registers it, and the watchdog only reads the heartbeat (`watchdog.go:237,257`). Attaching `WriteTargetSnapshot` to `RecordOpsHeartbeat` alone would make the write dead code that never runs in production, so the target row is never written and `GET /v1/admin/drift?against=target` keeps returning 404 through every upgrade, the exact F-DR-3 failure.
