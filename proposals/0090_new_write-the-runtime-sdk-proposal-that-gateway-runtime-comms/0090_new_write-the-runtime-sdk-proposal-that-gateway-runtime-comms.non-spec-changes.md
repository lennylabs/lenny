# Non-spec changes: Runtime SDKs assume one session per process

## Design (implementation-facing)

The adapter gains a frame-writing helper pair over the existing `RuntimeProcess.WriteEnvelope` and an open sequence that every start runs, so it writes the SPEC-3 frames on the paths the SPEC-3 **Session frame writes.** table states, through one path, and the `RuntimeProcess` interface does not change (CODE-1). The developer-loop executor writes a minimal `session_start` for a child it spawns itself (CODE-2). The session-scoped `CH-RUNTIMEOPS` senders gain a session argument and `terminate` is deleted on the adapter side (CODE-3). The three SDKs keep per-session state keyed by `sessionId` and invoke the handler per session (CODE-4, CODE-5). The compliance harness plays the adapter's new side of the contract (CODE-6). Once the SDKs read the frame, the adapter stops writing the per-session manifest fields (CODE-8). Part B adds the connection handshake on both runtime listeners and the SDK client half (CODE-7).

Each deliverable updates, in the same commit, the existing tests its change breaks. TEST-1 holds the new cross-component tests. The wire rules are stated once in the spec text staged by SPEC-3 (`session_start` rules 1 to 3, `session_end` rules 1 to 3, **Session frame writes.**, **Session errors.**), SPEC-4, and SPEC-8; the deliverables below cite them.

## Staged code changes

### CODE-1 · Adapter session frames: the open sequence and the end write at every row of the SPEC-3 matrix

Targets: `pkg/adapter/sessionframes.go` (new), `pkg/adapter/session.go` (`StartSession`, `tearDownReclaimedSlot`), `pkg/adapter/resume.go` (`Resume`), `pkg/adapter/sdkwarm.go` (`ConfigureWorkspace`, `DemoteSDK`), `pkg/adapter/manifest.go` (`ManifestLLM`, `manifestLLMFromPayload`). `pkg/adapter/holdstate.go`, `pkg/adapter/runtimegeneration.go`, `pkg/adapter/lifecycle.go`, and `pkg/adapter/heartbeat.go` do not change, because their rows write no frame. Each item below implements one or more rows of SPEC-3 **Session frame writes.**

1. `sessionframes.go` defines:
   - `sessionStartFrame`, with JSON members `type`, `sessionId`, `credentialsPath` (`omitempty`), `experimentContext`, `tracingContext`, and `llm`. The last three are written as `null` when the session has none. The members reuse `manifestExperimentContext`, `s.sessionCredentialsPath`, and `s.manifestLLM`, after deleting `ManifestLLM.BaseURL` and its assignment in `manifestLLMFromPayload` (the proxy URL stays in the credential file only, §4.7.11 item 4). `writeSessionStart` sets `credentialsPath` only when the session's registry entry, read under `s.mu`, records `assigned`, and omits it otherwise.
   - `sessionEndFrame`, with JSON members `type` and `sessionId`.
   - `(s *Server) writeSessionStart(sessionID string, in manifestInputs) error` and `(s *Server) writeSessionEnd(sessionID string)`. Both write through `s.Runtime.WriteEnvelope(sessionID, …)`. `writeSessionEnd` logs a failed write with `slog.Debug("session_end_write_failed", "slot_id", …, "error", …)` and returns nothing. Both write nothing when `s.RuntimeKind == RuntimeKindMCP`.
   - `(s *Server) openRuntimeSession(ctx context.Context, sessionID string, claim slotClaim, in manifestInputs, guardHeld bool) (confirmed bool, err error)`, the open sequence:
     a. Unless `guardHeld`, acquire the slot's per-slot guard with `lockSlotGuard(ctx, sessionID)` and release it on return. When `lockSlotGuard` reports `false` (the acquisition outlived `ctx`), return an error and write nothing.
     b. Under `s.mu`, compare `s.slots[sessionID]` with `claim.entry` by pointer identity, as `reclaimSlotIfOwnedLocked` does. This is the first rule-8 confirmation (§4.7.1 rule 8, as SPEC-3 Edit 13 states it). On a mismatch return `(false, nil)` with no frame.
     c. `writeSessionStart`. On error return the error.
     d. `noteRuntimeStarted(sessionID, claim.attempt)`. On true return `(true, nil)`. Its token comparison is the rule-8 entry-identity confirmation at this point: step b established identity under the slot serialization, and until the sequence ends another entry for the identifier cannot be created, because the reclaim hold of any removal lasts until then (§5.2). The entry can only have been removed, which the token comparison detects. Every caller of `noteRuntimeStarted` is replaced by this call, so `runtimegeneration.go` does not change.
     e. Otherwise call `writeSessionEnd(sessionID)` and return `(false, nil)` without re-reading the registry. State in the function's comment why no re-read is needed, citing §28.5.3 (CH-MSGSOCK, Session frame writes) and §5.2 (slot-identifier reclaim hold).
2. Start rows.
   - `StartSession`: after `Runtime.Start` succeeds, call `openRuntimeSession(ctx, sessionID, claim, in, false)` with the `manifestInputs` already passed to `writeSessionManifest`.
     - On an error, call `s.Runtime.Close`, then `releaseClaimedSlot`, and answer `codes.Internal` categorized TRANSIENT.
     - On `!confirmed`, take the existing `rollbackUnconfirmedStart` arm unchanged.
   - `Resume`: the same call with `guardHeld` true, because `Resume` holds the guard from ahead of its claim.
     - On an error, call `s.Runtime.Close`, then `releaseSessionSlotUnderGuard(sessionID, true)`, and answer `codes.Internal`.
     - On `!confirmed`, take the existing `rollbackUnconfirmedStart` arm unchanged.
   - `ConfigureWorkspace`, fresh arm only: after `sw.ConfigureWorkspace` succeeds, call `openRuntimeSession(…, false)` with the `manifestInputs` the RPC already assembles.
     - On an error, call `releaseClaimedSlot` and answer `codes.Internal`. The gateway's `DemoteSDK` fallback then finds no session `running` and writes nothing.
     - On `!confirmed`, take the existing `refuseUnconfirmedSDKWarmStart` arm unchanged. Its `session_end`, when one is owed, was already written at step e and precedes `DemoteSDK`.
     - The idempotent repeat calls nothing and writes nothing.
3. End rows.
   - `tearDownReclaimedSlot`: inside `if r.started`, call `writeSessionEnd(sessionID)` before `Runtime.Close` when `r.live` is true. `r.live` is already read in the deregistration's critical section, and the write precedes the release of the reclaim hold.
   - `DemoteSDK` handler: resolve `sessionID := s.anyRegisteredSession()`. When it is non-empty:
     - acquire `lockSlotGuard(ctx, sessionID)`, and when it reports `false` log `slot_guard_not_acquired` and proceed, as `releaseSessionSlot` does;
     - read `running := s.runtimeHoldsLocked(sessionID)` under `s.mu`;
     - call `writeSessionEnd(sessionID)` when `running`;
     - then call `sw.DemoteSDK`, keeping its current `codes.Internal` answer on error, clear `sdkConnected`, and call `noteRuntimeClosed(sessionID)` and `releaseSessionSlotUnderGuard(sessionID, guarded)`.
     When it is empty, keep the current `sw.DemoteSDK`, `sdkConnected`, and `cancelPodMCPIfRuntimeIdle` path. The SIGTERM-time `ShutdownDemoteSDK` reaches this handler and writes what the `DemoteSDK` rows state.
   - The hold-timeout termination, `Interrupt`, heartbeat escalation, and process exit write nothing and are not edited.
4. Cite `// spec: §28.5.3 (CH-MSGSOCK, Session frame writes); §4.7.1 (role and gateway RPC contract), rule 8; §5.2 (slot-identifier reclaim hold)` on `openRuntimeSession`, and `// spec: §28.5.3 (CH-MSGSOCK, Session frame writes)` at each call site.

Existing adapter tests whose fake `RuntimeProcess` asserts the exact sequence of frames it received gain the frames their row states.

### CODE-4 · Go runtime SDK serves sessions keyed by `sessionId`

Targets: `sdks/runtime/go/runtime/runtime.go`, `types.go`, `context.go`, `mcp.go`, `lifecycle.go`, `options.go`, `sdks/runtime/go/example/{echo,delegate,lifecycle}`, and `cmd/lenny-ctl/runtimescaffold/templates/{go-minimal,go-coding,go-chat}.main.go.tmpl`.

1. Frame loop. The loop reads every inbound frame and never blocks on one session's work. It routes `session_start`, `message`, `tool_result`, and `session_end` to the addressed session's state through a routing table keyed by `sessionId`; it handles `heartbeat` and `shutdown` itself. Each session has its own goroutine and its own queue. **IMPLEMENTOR'S CHOICE:** the queue implementation. A full queue may block delivery only to its own session, never the loop.
2. Session state. `session_start` creates a `sessionState` holding a context derived from the process context and its cancel function, the parsed frame, the `CredentialBundle` loaded from the frame's `credentialsPath` (none when the member is absent), a create error, and a sequence counter. A duplicate `session_start` is ignored. The SDK then invokes `OnCreate` with a `CreateRequest` whose `SessionID` and `TaskID` are the frame's `sessionId` and whose `ExperimentContext`, `TracingContext`, and `LLM` come from the frame.
3. Messages. `Message.SessionID` and `Message.TaskID` come from the inbound frame's `sessionId`, and `Message.Sequence` is the session's counter. A message for a session with no state, or whose create failed, is answered as SPEC-3 **Session errors.** states, with `error.code` `RUNTIME_ERROR`, and is not dispatched. The process keeps running.
4. `session_end`. The frame loop removes the session from its routing table when it reads `session_end` and hands the state to the session's goroutine, which cancels the session context, discards queued messages without dispatching them, cancels the session's pending `tool_call` waiters, waits for the in-flight handler to return, and calls `OnTerminate(ctx, sessionID, TerminationReason{Reason: "session_end"})`. A `session_start` for that `sessionId` read afterwards creates a new state whose `OnCreate` runs after the removed state's `OnTerminate` returns, and its messages queue meanwhile. When the frame loop reads `session_end` it marks the removed state ended under the stdout writer's lock, and every `response` and `tool_call` written for that state, including the in-flight handler's answer and a leaked goroutine's `tool_call`, checks the mark under that lock and is logged and dropped once it is set (SPEC-3 **Inbound: `session_end`** rule 2); a dropped `tool_call` returns an error to its caller at once. `Lifecycle.Send` applies no per-session filter, because SPEC-3 **Inbound: `session_end`** rule 2 admits a late `llm_request_completed`. A `session_end` for an unknown session is ignored.
5. EOF and `shutdown` close every live session's queue. Each session dispatches its queued messages, its in-flight handler returns, and the SDK then calls `OnTerminate(ctx, sessionID, reason)` with the reason `Run` passes today (the `shutdown` frame's reason, or `stdin_closed` on EOF). Sessions drain concurrently, and `Run` returns after the last one. Only `session_end` discards queued messages.
6. MCP. The platform and connector MCP connections stay process-scoped: `startChannels` dials them once per process with `CH-RUNTIMEOPS` and keeps its current hard-error and degrade behavior. A failed credential-file read sets that session's create error and does not end the process.
7. Handler signature. `Handler.OnTerminate` becomes `OnTerminate(ctx context.Context, sessionID string, reason TerminationReason) error`. The `Handler` doc comment follows SPEC-5 Edit 1; the comment that a recycled session gets a fresh `OnCreate` after the runtime exits is removed. The `types.go` comments on `CreateRequest` and `Message` follow SPEC-5.
8. Credentials. Delete `resolvedCredentialsPath`'s fallbacks to the manifest's `credentialsPath` and to `WithCredentialsPath`, and delete the `WithCredentialsPath` option. The `session_start` `credentialsPath` is the only source. `CredentialBundle` decodes the credential file in the layout item 4 of §4.7.11 states, a `Providers` list whose entries carry `LeaseID`, `Provider`, `ExpiresAt`, `DeliveryMode`, and `MaterializedConfig` (the entry's object, left undecoded), in place of the flat `Mode`, `APIKey`, `APIKeyEnv`, and `BaseURL` fields. `credentials_rotated` reloads the bundle of the session its `sessionId` names.
9. Lifecycle routing (the SDK half of SPEC-4). `OnCheckpoint`, `OnInterrupt`, and `OnCredentialsRotated` callbacks gain a leading `sessionID string` parameter, and `LifecycleEvent` gains `SessionID`. A `CH-RUNTIMEOPS` event naming a session the SDK does not hold is held, then handled or dropped, as SPEC-4 Edit 2 states. When the frame loop reads that session's `session_start`, the session's held events are handed to it in arrival order once its `sessionState` exists; an event dropped when its wait ends is logged. A new `Run` option, `WithSessionStartWait(time.Duration)`, sets the wait, and the wait for an event that carries `deadlineMs` ends before that deadline whatever the option says. **IMPLEMENTOR'S CHOICE:** the default wait. Constraint: it covers the scheduling gap between the two read loops on a loaded host and stays well below the adapter's 60-second `credentials_acknowledged` timeout. The spec fixes no value, so the option makes the default overridable, and TEST-1 sets it short.
10. `AdapterManifest` drops `SessionID`, `TaskID`, `CredentialsPath`, and `TracingContext`. `withSessionContext` takes the `sessionState`, which carries the session's context and credentials and the process-scoped `Tools` and `Lifecycle`.
11. The echo example reports the session's `SessionID` and experiment variant in its reply text, so TEST-1's tier-10 cases can observe the context. The delegate and lifecycle examples and the Go scaffold templates adopt the new `OnTerminate` and lifecycle callback signatures, and the go-chat template's header comment names `session_start` as the source of `credentialsPath`.
12. In the same commit, retarget the Go cases of `tests/tier10_conformance/credential_path_resolution_conformance_test.go` to drive `session_start` (`…FromTheManifest` becomes `…FromSessionStart`), including the rotation case, which writes `credentials_rotated` after the session's `session_start`, and `TestGoRuntimeSDKStartsWithNoCredentialFileAtTheManifestPath_spec_4_7`, which sends a `session_start` without `credentialsPath`. The Go cases write their credential files with a providers-layout `writeCredentialBundle` and assert `Providers[0].Provider`; the Python and TypeScript cases keep the flat writer under another name until CODE-5 item 8. Update `runtime_test.go`, `lifecycle_test.go`, and `mcp_test.go` for the new behavior.

### CODE-7 · Part B: adapter handshake on both runtime listeners and the SDK client half

Targets: `pkg/adapter/intrapodauth.go` (new), `pkg/adapter/peercred.go`, `pkg/adapter/mcp/challenge.go`, and every file the client inventory below names.

1. `authenticateRuntimeConn(conn net.Conn, br *bufio.Reader, nonce func() string, nonceOnly bool) error` implements SPEC-8 **Runtime connection handshake.**. It reads the first line through `br` under the 500 ms `mcp.ChallengeTimeout`, refuses an empty provider value, compares with `subtle.ConstantTimeCompare`, and in nonce-only mode issues the challenge through the existing `pkg/adapter/mcp` challenge code. Export `newChallenge` as `mcp.NewChallenge` for this adapter-side caller.
2. The nonce provider returns the `mcpNonce` of the currently published manifest. `NewSocketRuntimeProcess` and `NewRuntimeOps` take it as a constructor argument, because both listeners are built at adapter boot before any nonce exists. This deliverable does not change when or how the nonce is minted. A caller of either constructor that neither dials nor accepts (`cmd/lenny-adapter/main.go`, and the tests that construct a listener and dial nothing, found by grepping for the two constructors) passes a provider and needs no other change.
3. `SocketRuntimeProcess.acceptLoop` loops. It accepts, runs the handshake on a new `bufio.Reader` over the connection, and on a failure closes the connection, logs it through `logRefusedPeer`, and accepts again. It installs only a connection that passes, with its reader, in every `SocketPeerAuth` mode, because `wrap` installs no retrying listener in nonce-only or embedded mode. `startReaderLocked` builds the fan-out scanner over the installed reader rather than over `p.conn`, so bytes buffered during the handshake are not lost.
4. `RuntimeOps.Run`/`serveConn`: run the handshake on the connection's reader after the peer check and before `handshake` sends `lifecycle_capabilities`, with the same refusal path.
5. Client half. One exported helper in `pkg/runtimekit` beside `DialSocket` implements the runtime half of SPEC-8 **Runtime connection handshake.**. The helper takes the manifest path its caller resolved, once, and never resolves a path itself: it re-reads that file before each dial and each redial, and polls for the file and between redials at a short interval with no overall deadline. Python and TypeScript implement the same helper in their transport modules. The `binary-minimal` scaffold template imports no Lenny package, so its `openTransport` implements the runtime half inline with the standard library. The Go, Python, and TypeScript MCP clients answer a `_lennyChallenge` that arrives in place of the `initialize` response with the same answer code. The table below names every caller and the path each one passes.
6. Update the header comments of `socketruntime.go` and `runtimeops.go` that say the handshake is not performed, and the `SocketPeerAuth.NonceOnly` comment in `peercred.go` that says `CH-MSGSOCK` is unauthenticated.

## Edge cases and accepted failure modes

- A `session_end` write that fails on a live connection is logged and dropped. The partial-write hazard on the shared connection predates this proposal and applies to every frame.
- For a refused SDK-warm start that wrote `session_start`, the adapter writes `session_end` before `DemoteSDK`, because `DemoteSDK` does not end the runtime process (SPEC-3 **Session frame writes.**).
- Under the developer loop no credential file is provisioned, so the SDK loads no credential bundle for the session.
- A runtime process that crashes takes every session's context with it; the pod is retired and a resume on a fresh pod re-delivers the context in a new `session_start`.
