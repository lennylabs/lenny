# Non-spec changes — Pre-materialize large git repositories on a warm pod

## Design (implementation-facing)

The normative rules live in the staged spec text: §6.4 **Repository stores.** (SPEC-2), §4.7.1 `FetchGitPack` (SPEC-5), §14 **Cache-served `gitClone` sources.** rules 1 to 7 (SPEC-3), §6.4 **Private repository stores.** (SPEC-2 Edit (c)), the §4.9 **`hostPatterns`** rules, **`git-https` credentials.**, and **Token Service secret resolution.** (SPEC-8), and the §12.4 and §28.3 restore lineage rows (SPEC-10). The deliverables below cite those homes and add only what the implementor needs beyond them.

Component split:

- **Gateway** (CODE-3, CODE-5): a per-replica bare mirror per mirror key (§6.4 **Private repository stores.** rule 4), tree validation at materialization, eligibility routing in the binder, and the `FetchGitPack` handler.
- **Pool ownership** (CODE-8): `ownerTenantId` on pool records, its admission, and the resolution rule.
- **Controller and registry** (CODE-2): the `gitRepository` entry travels from the Runtime CRD to the adapter flag and into `runtimestore`, so the pod, the binder, and the `FetchGitPack` authorizer see the same url set.
- **Adapter** (CODE-4, CODE-5, CODE-6): the warm fill before READY, slot-repository construction, the capture copy, and restore completion.
- **Images** (CODE-1): the images of the binaries that run git carry a git binary (CODE-1 step 2).
- **Credential resolution** (CODE-7): the `git-https` provider and host-to-pool binding that every authenticated gateway git operation goes through.
- **Restore lineage** (CODE-9): the record that §14 **Cache-served `gitClone` sources.** rule 7 states.

One url-normalization function, `gitref.NormalizeURL` in `pkg/gateway/provisioning/gitref`, implements the §6.4 rule. The CODE-2 uniqueness check, the binder, the `FetchGitPack` authorizer, and the adapter all call it. The adapter imports it from that package, or the function moves to a leaf package both trees import; it is never reimplemented.

Every adapter git invocation runs with `-c protocol.allow=never` and an environment with `GIT_TERMINAL_PROMPT=0` and no `HOME` config. The adapter runs only the git subcommands named in this file.

### CODE-3 · Gateway mirror, tree validation, and the `FetchGitPack` handler

Targets: `schemas/lenny-adapter.proto` and regenerated `pkg/proto/adapter/v1`; `pkg/gateway/provisioning/gitref/mirror.go` (new); a `FetchGitPack` handler beside `pkg/gateway/mcpfabric/delegationtree/leasecontrol/scrubreport_server.go`; `cmd/lenny-gateway/gwcontrol_server.go`; `charts/lenny/templates` (gateway deployment), `charts/lenny/values.yaml`, and `charts/lenny/presets/dev.yaml`; `pkg/embedded/manifests/manifests.yaml` (regenerated); `pkg/observability/metrics/catalog.go` and `catalog_test.go` (`spec161Metrics`); `pkg/gateway/provisioning/gitref/archive.go`; `pkg/gateway/mcpfabric/delegationtree/leasecontrol/satoken_verify.go` and `satoken.go`; `tests/testinfra/kind/e2e-values.yaml`.

1. **Proto.** In `service GatewayControl`, after `ReportPodScrub`:

   ```proto
   // FetchGitPack returns a git pack for a gitRepository shared asset.
   // The first response is header; every later response is pack_chunk.
   // The adapter rejects any other order.
   // spec: §4.7.1 Role and Gateway RPC Contract (FetchGitPack)
   rpc FetchGitPack(FetchGitPackRequest) returns (stream FetchGitPackResponse) {}

   message FetchGitPackRequest {
     string pod_id = 1;
     string url = 2;
     string want = 3;            // a ref, or a 40-hex commit SHA
     repeated string haves = 4;  // commit SHAs; empty when want is a ref
     // No session_id: the request is pod-scoped (§4.1 Request Message Scope).
   }

   message FetchGitPackHeader {
     string resolved_commit = 1;
     bool shallow = 2;
   }

   message FetchGitPackResponse {
     oneof payload {
       FetchGitPackHeader header = 1;
       bytes pack_chunk = 2;
     }
   }
   ```

2. **Authentication.** In `gwcontrol_server.go`, register a stream interceptor chain (`grpc.ChainStreamInterceptor`) carrying stream forms of `leasecontrol.RequireVerifiedPeerInterceptor` and `leasecontrol.RequireSATokenInterceptor`, built from the same arguments as the unary chain. Without it the server-streaming RPC bypasses both checks.
3. **Mirror** (`gitref.Mirror`). One bare repository per key (step 7 rule M1), created with `transfer.fsckObjects=true`, `fetch.fsckObjects=true`, `fetch.unpackLimit=1`, `gc.auto=0`, `maintenance.auto=false`, `pack.threads=1`, `pack.windowMemory=64m`, `pack.deltaCacheSize=64m`, `core.deltaBaseCacheSize=32m`, `http.lowSpeedLimit=1024`, and `http.lowSpeedTime=60`. With these settings a fetch never starts a gc or leaves loose objects, a stalled transfer fails, and each git process the mirror runs, index-pack included, stays inside the peaks rule M7 sizes. Each operation on a key (`Ensure`, `ResolveRef`, `ValidateTree`, `Pack`) holds that key's lock shared for its duration. Fetches for one key run one at a time, and identical concurrent fetches share one. A fetch adds objects beside running readers, so only rules M2 and M8 take the lock exclusively, and neither waits for it.
   - `Ensure(ctx, key, cred, sha)` (step 7 rule M1) fetches `sha` when absent with `git fetch -- <url> <sha>:refs/lenny/<sha>`, in `gitref.Clone`'s `authEnv` environment with the credential the caller passes (zero for a public key), so later fetches negotiate from the commits the mirror holds.
   - `ResolveRef(ctx, key, cred, ref)` (step 7 rule M1) reuses `LsRemoteResolver.Resolve` against the remote on every call with the credential the caller passes, then `Ensure`s the commit with it.
4. **ValidateTree** (`gitref.Mirror.ValidateTree(ctx, url, sha, pathPrefix, allow, limit)`, where `allow` is the source's `upload.RuntimeAllow`). Walks the whole tree with `git ls-tree -r -t -l --full-tree` for each entry's path, mode, and blob size, and lists its objects with `git rev-list --objects --no-walk <sha>` piped to `git cat-file --batch-check='%(objecttype) %(objectsize) %(rest)'` (`%(rest)` makes cat-file split off the path). ls-tree prints no tree sizes and omits the root tree, so the bound's tree-object term comes from the listing. It applies §14 rule 2 from both. `allow` carries the Runtime's `allowSymlinks`; do not copy `extractGitCloneSource`'s `AllowSymlinks: true`. Symlink targets go through `upload.ValidateSymlinkTarget` with the link path joined under `allow.WorkspaceRoot` and `pathPrefix`. A violation returns `*upload.ValidationError` with the matching `upload.Reason`.
   - Memoize the limit-independent results under step 7 rule M5: the path and symlink verdict and the materialization bound go in the verdict memo, and the listing's summed blob and tree-object bytes go in the tree-bytes memo. Compare the bound against `limit` on every call.
5. **Pack** (`gitref.Mirror.Pack(ctx, key, cred, want, haves, w)`, with the key and credential of step 7 rule M1). Implements the §4.7.1 pack rule. Before it acquires its slot (step 7 rule M4), `Pack` `Ensure`s `want` and gives each unknown have one `Ensure`, dropping a have that is still absent. The delta's object bytes come from `git rev-list --objects <want> --not <haves>` piped to `git cat-file --batch-check='%(objectsize)'`, compared with the `want` tree's summed blob and tree-object bytes (step 7 rule M5). The pack is produced with `git pack-objects --stdout` (never `--thin`) and streamed to `w`. A shallow pack is produced by piping step 4's object listing of `want` (`git rev-list --objects --no-walk <want>`) into `pack-objects`.
6. **Handler.** Takes the pod name from the SA token through a new `TokenReviewVerifier.VerifyPod`, which returns `status.user.extra["authentication.kubernetes.io/pod-name"]`; on the interceptor's dev path it takes the decoded `kubernetes.io` pod claim. Resolves the pod's pool and Runtime from `pod_id` through the pod registry, normalizes `url`, and checks it against the Runtime's `gitRepository` entries in `runtimestore`. On a commit-SHA `want` that the pod's Runtime does not match, it reads the pod's restore lineage record through the CODE-9 store that `cmd/lenny-gateway` passes it (`gitlineage.Store.Pools`) and repeats the check, through the same pool-to-Runtime resolution, for each unexpired pool in ascending name order. The first pool whose Runtime names the url replaces the pod's pool for the private-entry checks, the credential resolution, and the mirror key. It reads no session row, `pod_assignment`, `agent_pod_state`, or `SandboxClaim`. For a private entry it reads the pool's `OwnerTenantID` from `poolstore` and calls `vcscred.Resolver.Resolve(ctx, OwnerTenantID, url, entry.Auth.LeaseScope)` (CODE-7 step 3) on every call before any mirror read, per §6.4 **Private repository stores.** rule 4.

   | Condition | Status |
   |:--|:--|
   | pod unknown, `pod_id` not the token's pod, url on neither its Runtime nor the Runtime of an unexpired lineage pool (§14 rule 7), private entry with empty `OwnerTenantID`, or failed credential resolution | `PERMISSION_DENIED` |
   | `want` neither a ref nor a 40-hex SHA, or a ref `want` with `haves` | `INVALID_ARGUMENT` |
   | ref or commit absent on the remote | `NOT_FOUND` |
   | remote unreachable, fetch failed, or the lineage record unreadable | `UNAVAILABLE` |
   | rule M2 leaves the mirror over `maxBytes` | `RESOURCE_EXHAUSTED` |
   | the caller's context ends while it waits for a slot (rule M6) | `DEADLINE_EXCEEDED` |

   The handler sends the header, then pack chunks of at most 1 MiB, and never holds the whole pack in memory.
7. **Resource and admission model.** These rules are the one home of the mirror's keys, disk, concurrency, waiting, and memory. Every other site cites them by number.
   1. **M1 · Key.** A mirror key is the key §6.4 **Private repository stores.** rule 4 defines, carried as `gitref.MirrorKey{Owner, URL}`, with `Owner` empty for a public entry and set to the `OwnerTenantID` of the pool step 6 matched for a private one. The `url` parameter of `Ensure`, `ResolveRef`, `ValidateTree`, and `Pack` is a `MirrorKey`. `Ensure`, `ResolveRef`, and `Pack` also take a `gitref.Credential` after the `MirrorKey`, zero for a public key: the step 6 handler and the CODE-5 binder pass the credential they resolve under §6.4 rule 4, and `Pack` passes it to its own `Ensure` calls. Every lock, single-flight, memo entry, and recency record in steps 3 to 5 is per key. Each key has one bare repository at `<root>/m/<hex sha256 of Owner, a NUL byte, and URL>`. The gateway uses a key only after step 6's authorizer or §14 rule 1 has matched the request to a registered entry, so request input alone never creates a key. No per-tenant cap applies. Rule M2's deletion ignores the owner, so one tenant's fetches can delete another tenant's idle mirror, which costs that tenant a refetch.
   2. **M2 · Disk.** The root is the `git-mirror` volume (step 9). The budget is `gateway.gitMirror.maxBytes`, measured as the summed size of the regular files under `<root>/m`. The replica takes the measure before each fetch, and before `Ensure` takes the requested key's lock. While the measure exceeds `maxBytes`, the replica deletes the least-recently-used key mirror whose lock it can take exclusively without waiting, taking the requested key's mirror last, and drops the deleted key's memo entries. When no mirror is left to delete and the measure still exceeds `maxBytes`, the fetch fails with `RESOURCE_EXHAUSTED`, and the replica logs the measure and `maxBytes` at WARN. Each fetch adds at most its own pack, so the measure stays below `maxBytes` plus `maxConcurrentFetches` times the largest single fetch. `<root>/tmp` holds `CloneArchive`'s clone directories and is outside the measure. When the gateway constructs `gitref.Mirror`, before any mirror operation, it deletes the root's contents.
   3. **M3 · Fetches.** Each mirror fetch holds one slot of a per-replica `subsystem.Limiter` sized by `gateway.gitMirror.maxConcurrentFetches` from before git starts until git exits. Concurrent `Ensure` calls that step 3 merges into one fetch hold one slot between them. That fetch runs under a context that is cancelled when its last waiting caller returns. Step 3's `http.lowSpeed*` settings fail a stalled transfer, which releases its slot. `ResolveRef`'s `ls-remote` holds no slot.
   4. **M4 · Packs and tree walks.** A second per-replica `subsystem.Limiter`, sized by `gateway.gitMirror.maxConcurrentPacks`, bounds pack production and tree walks. A `Pack` holds one slot from before its walk or `pack-objects` starts until its stream or its context ends. A `ValidateTree` memo miss holds one slot for its walk, and a walk inside a `Pack` uses that `Pack`'s slot. No caller holds a fetch slot while it holds a pack slot. The binder calls `ValidateTree` directly, through neither `UploadGate` nor `gatedExtract`. A walk therefore holds no Upload Handler slot, and its refusals never reach the upload breaker or `lenny_upload_extraction_aborted_total`. Neither limiter has a breaker, and neither is a `subsystem.Subsystem` or publishes a `subsystem`-labelled gauge.
   5. **M5 · Tree memo.** Step 4 memoizes into two maps per key. The verdict memo is keyed by `(sha, pathPrefix, allow.AllowSymlinks, allow.WorkspaceRoot)`. The tree-bytes memo is keyed by `sha`, and every walk fills it. Concurrent `ValidateTree` calls with one verdict key share one walk, and the leader acquires its M4 slot only after it becomes the leader. A `Pack` reads the tree-bytes memo when it holds the `sha`; otherwise it computes the sum in its own slot, and it never waits on another caller's walk. Entries are dropped only with their key's mirror or on restart, so the memo grows by one entry of a few hundred bytes per distinct validated `(sha, pathPrefix, allow)`. This growth is accepted.
   6. **M6 · Waiting.** A caller waits for an M3 or M4 slot within its own context, with no queue-depth bound. When the context ends first, the caller returns `DEADLINE_EXCEEDED` and holds no slot. The contexts are the adapter's fill deadline (CODE-4 step 2.1) for a warm fill, `maxFinalizingTimeoutSeconds` for the binder and for §14 rule 3 packs, and the Resume call's deadline for restore completion. On a replica that starts with an empty mirror, the last of n warm fills against it completes within the fill deadline when ceil(K / `maxConcurrentFetches`) × t_fetch + ceil(n / `maxConcurrentPacks`) × t_warm does not exceed that deadline. K is the number of keys the replica fetches at once, and t_fetch and t_warm are INFRA-1 phase (g)'s times. A fill that misses the deadline takes its pod to `failed` (§6.4 **Repository stores.**), and the replacement pod's fill finds the key already mirrored.
   7. **M7 · Memory.** The gateway container's memory limit is at least its memory request plus `maxConcurrentFetches` × P_fetch plus `maxConcurrentPacks` × P_slot. P_fetch is INFRA-1 phase (g)'s full-fetch peak, and P_slot is the largest peak among the M4 slot holders it measures. Both are measured under step 3's git configuration and include the handler's 1 MiB chunk buffer. The cold `gitClone` path is outside this sum.
   8. **M8 · Tenant purge.** Every 30 seconds, the replica deletes the mirror of each private key whose `Owner` the `OwnerRegistered` function reports unregistered, per §6.4 **Private repository stores.** rule 4. It takes the key's lock exclusively without waiting and drops the key's memo entries as rule M2 does. A key whose lock is held, or whose registration read fails, is kept until a later pass, and a failed read is logged at WARN. `gitref.Mirror` gains the field `OwnerRegistered func(ctx context.Context, tenantID string) (bool, error)`, which `cmd/lenny-gateway` sets to `tenantRegistered` over its tenant store.
8. **Metrics.** Register `lenny_workspace_git_pack_bytes` (histogram, `pool`, `kind`) and `lenny_workspace_git_cache_sources_total` (counter, `pool`) per SPEC-7, and add both to `catalog.go` and `spec161Metrics`. The handler observes `kind` from the request and the served pack: `warm` for a ref `want`, `delta` for a pack that excludes at least one have, `full` for a shallow pack.
9. **Chart.** Add a gateway `emptyDir` named `git-mirror`, mounted at `/var/lib/lenny/git-mirror`, with no `sizeLimit`. Render the gateway container's `resources.requests.ephemeral-storage` from `gateway.gitMirror.maxBytes`. Add `gateway.gitMirror.maxBytes` (default `20Gi`), `gateway.gitMirror.maxConcurrentFetches` (default `2`), and `gateway.gitMirror.maxConcurrentPacks` (default `8`), each operator-tunable, and pass the path and all three values to the gateway through its existing configuration surface. Set the default `gateway.resources.limits.memory` from INFRA-1's results by step 7 rule M7, and state rule M7's sum in the `values.yaml` comment. In `charts/lenny/presets/dev.yaml`, delete the `memory` limit from the `gateway.resources` override and set `gateway.gitMirror.maxBytes: 2Gi`. Set the same `maxBytes` in `tests/testinfra/kind/e2e-values.yaml`, so the ephemeral-storage request fits a laptop or Kind node. `gitref.CloneArchive` creates its temporary directory under `<root>/tmp` instead of `os.TempDir()`, because the gateway's root filesystem is read-only and the gateway has no other writable path.

### CODE-4 · Adapter warm fill before READY

Targets: `cmd/lenny-adapter/main.go`; `pkg/adapter/gitstore.go` (new); `pkg/adapter/server.go` (`GitStoreFillTimeout` and the url-map field); the adapter's GatewayControl client wiring in `pkg/adapter/gatewaylink.go`.

`Server.ConnectGateway` runs the fill, an unexported method in `gitstore.go`, after it dials GatewayControl. `cmd/lenny-adapter` and the embedded-adapter runtimes `cmd/runtimes/echo-embedded` and `cmd/runtimes/preconnect-echo` all call `ConnectGateway` before they report ready, so no binary adds its own call. It implements §6.4 **Repository stores.**

1. When the decoded shared-asset set has any `gitRepository` entry and `gatewayAddr` is empty, `ConnectGateway` returns an error, which every caller treats as a fatal startup error.
2. For each `gitRepository` entry, in order:
   1. Call `FetchGitPack(pod_id = POD_NAME from the downward API, url, want = gitRef, no haves)` under the deadline `Server.GitStoreFillTimeout` (zero means `15m`). `cmd/lenny-adapter` sets it from the flag `--git-store-fill-timeout` (default `15m`, operator-tunable; the controller does not render it, so pods use the default), and the embedded-adapter runtimes leave it at the default. Run the call with gRPC keepalive on the connection. The deadline is not a Runtime or pool field. Non-preConnect pools have no warming watchdog, so this deadline is the only bound on a stalled fill.
   2. Run `git init --bare` in `/workspace/shared/.tmp-<hex sha256 of the normalized url>`.
   3. Pipe the pack chunks to `git index-pack --strict --stdin`.
   4. Run `git cat-file -e <resolved_commit>^{commit}`. A pack that lacks the announced commit is a fill failure.
   5. Run `git update-ref refs/lenny/store <resolved_commit>`.
   6. Set directories to 0755 and files to 0444 (matching `warmSharedMode`), so the runtime UID can read the store through alternates whatever the umask.
   7. Create `destPath`'s parent directories, then rename the temporary directory to `destPath`.
3. Keep, on `Server`, an in-memory map from normalized url to `(destPath, resolved_commit)`. CODE-5 and CODE-6 read it.
4. Any error, deadline expiry, or volume exhaustion is a fatal startup error (§6.4 **Repository stores.**).

### CODE-5 · Binder routes cache-served sources; the adapter builds the slot repository

Extend the `stageWorkspace` inputs with the `gitRepository` entries of the matched pool's `SandboxTemplate` `runtimeRef`, as a map from normalized url to `leaseScope` (empty for a public entry) (§14 rule 1), the pool's `OwnerTenantID` (CODE-8 step 3), and the pool's `workspaceSizeLimitBytes`, carried on the bind request from `resolve.go`'s match at both call sites. 1. **Capture copy** (§14 rule 5). ## Edge cases and accepted failure modes

- **A `pod_id` naming another pod.** The handler refuses it (CODE-3 step 6). Every other GatewayControl RPC keeps the gap REC-1 files.
- **A pod that consumes its pack stream slowly.** It holds its rule M4 slot until its call's context ends (CODE-3 step 7 rules M4 and M6).
- **Mirror loss on a gateway restart.** The mirror is an `emptyDir` cache. The next request refetches.
- **Many keys fetched on a cold replica.** Warm fills queue on the mirror limiters and can miss the fill deadline (CODE-3 step 7 rule M6).
- **A gateway replica without the source's commit.** `Ensure` fetches it by SHA. A remote that deleted the commit returns `NOT_FOUND`, and the materialization or restore fails.
- **Store staleness on recycling pools.** A store is never refreshed. A fresher store arrives with a replacement pod, bounded by the existing recycle limits.
