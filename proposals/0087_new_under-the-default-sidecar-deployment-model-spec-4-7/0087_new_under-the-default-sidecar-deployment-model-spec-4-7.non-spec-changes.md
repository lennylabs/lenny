# Non-spec changes: Sidecar runtime processes have no platform supervisor

These changes are staged. Applying them is the implementation's work, under the
implementation checklist.

## Design (implementation-facing)

Every change below is written against the tree at `f52fc9a49` (2026-10-22). Code is located by symbol and file. The behavior each change implements is stated in the spec-changes file, and each code change cites the spec home it implements by heading. The re-baseline of 2026-10-22 replaced the draft's Go `supervise` subcommand with a C supervisor in its own image (D-BINARY) and widened every change to every sidecar pod (D-SCOPE). The review run completes the per-symbol detail.

### Process model

```
init container lenny-supervisor-stage (stage UID)
  /lenny-supervisor stage DEST          copies itself into the emptyDir, mode 0555

runtime container (agent UID), PID 1 = /lenny-supervisor/lenny-supervisor run --env K=V ... -- ARGV
  clearenv; PR_SET_DUMPABLE 0; flag-setting handlers for every catchable signal 1.._NSIG-1
  except SIGSEGV/SIGBUS/SIGFPE/SIGILL, which stay SIG_DFL and blocked
  property self-test (result reported in ready; the adapter gates)
  dial @lenny-supervise until accepted or --dial-timeout ends (then exit non-zero); SO_PEERCRED peer must be the adapter UID (not in nonce-only mode)
  send ready{gen:0,properties}; serve requests in order until EOF, then exit

adapter (adapter UID)
  SO_PEERCRED self-test
  AwaitSupervisor: listen @lenny-supervise  <====  dial until accepted
  accept once (agent-UID check), close listener
  read ready; log each failed property    <====  ready{gen:0,properties}
  restart pod and a gating property failed: exit non-zero (no READY)
  [--launch-mode service or preconnect-sdk-warm: write manifest, bind listeners, launch, accept CH-MSGSOCK]
  srv.Serve (READY)
  ...
  step 6 final manifest; listeners bound
  launch{gen,id}                        ====>  fork; child: empty signal mask, setsid, exec argv with the rendered env
                                        <====  launched{gen,id}
  CH-MSGSOCK accept (0090 handshake)    <====  runtime process dials
  ping{gen,id} every interval           ====>  <==== pong{gen,id}
  ...occupancy zero, restart pod (each step's outcome: §5.2 Supervised scrub sequence)...
  scrub step 0
  end{gen,id,graceMs:0}                 ====>  kill(-1,SIGTERM); kill(-1,SIGKILL); reap; /proc check x2
                                        <====  ended{gen,id}
  sweep{gen,id}                         ====>  fork worker (no CH-SUPERVISE fd): IPC by cuid/uid,
                                               POSIX mqueues, agent-owned entries; parent kill(-1) + /proc check
                                        <====  swept{gen,id}
  cleanup{gen,id,commands,timeoutMs,prev...} ====>  fork worker (no CH-SUPERVISE fd), cwd workspace base:
                                               each argv in its own session, launch env + cleanup metadata
                                        <====  cleaned{gen,id}
  end{gen,id,graceMs:0}                 ====>  second end: kill(-1) and /proc check x2
                                        <====  ended{gen,id}
  sweep{gen,id}                         ====>  second sweep, as above
```

### Adapter state for one pod

| State | Set | Cleared |
|:--|:--|:--|
| `gen` | Incremented by each `launch` | Never |
| `live` (a process is running) | `launched` with no error | `ended` with no error, `exited` |
| `notLive` (sticky) | Each cause of §4.7.10 **Runtime supervisor.** **Liveness.** | Never |
| `disposition` (the end disposition, in precedence order: `endDemote`, `endScrub`, `shutdown`, `holdTimeout`, `deleting`, and `none`) | Under `s.mu`, before the act the §4.7.10 **Runtime exits.** *Set before* column names for the value | `launch` |
| `launchPermitted` | Adapter start; an attested end (`ended` with no error) | `launch` |

§4.7.10 **Runtime supervisor.** **Liveness.** and its table are the one statement of `notLive`. The adapter's part in every channel is fixed here: it exits non-zero (**Exit**), fails a start (**Start**, and under **Claim**), or reports `runtime_live: false` (**Report**); the WarmPoolController's part in **Exit** is the precursor fix (summary D-PREREQS), and the gateway's part in **Start**, **Claim**, and **Report** is unchanged.

`ServesNextSession()` returns false when `notLive` is set or, on a `keep` pod, when the composed `SocketRuntimeProcess.ServesNextSession` does, which is how a `keep` pod's connection state reaches the report when nothing set `notLive` earlier. The pod's lifetime is the `--runtime-process` row of the CODE-3 **Adapter inputs** table; the adapter holds no other recycle state. `podscrub.go` reads it as today.

### CODE-2 · The C supervisor, its image, and the binary check

**Targets.** `supervisor/` (new top-level directory: `supervisor.c`, `wire.c`, `procs.c`, `sweep.c`, `selftest.c`, `syscalls.h`, `Makefile`), `Dockerfile.supervisor`, the Makefile's `images` target (which builds `ghcr.io/lennylabs/lenny-supervisor:dev` from `Dockerfile.supervisor`), the image build and signing in CI and the release workflow, `scripts/cloud/aws/build-images.sh` (a `lenny-supervisor` entry built from `Dockerfile.supervisor`), and `scripts/cloud/aws/source-hash.sh` (`supervisor/` and `Dockerfile.supervisor` in the hashed set).

**Change.**

- A freestanding C program built with `-static -nostdlib -ffreestanding` over raw syscall wrappers. No `PT_INTERP`, no dynamic section, no libc, and no NSS. The binary check fails when the ELF has a `PT_INTERP` header or a dynamic section, or its symbol table contains `dlopen` or an NSS entry point.
- Modes: `stage DEST` copies `/proc/self/exe` to `DEST/lenny-supervisor` with mode `0555`. `run --socket NAME [--adapter-uid UID] [--dial-timeout D] --env K=V ... -- ARGV...` does, in order: `clearenv`; `prctl(PR_SET_DUMPABLE, 0)`; the signal dispositions of the signal bullet below; the property self-test; dial, repeating a dial refused with `ECONNREFUSED` until one connects or the `--dial-timeout` window ends, when it exits non-zero (the flag's default is at least the `--supervise-wait-timeout` default); `SO_PEERCRED` check against `--adapter-uid` when the flag is given, exiting non-zero without sending `ready` on a mismatch; `ready` with the self-test result; serve. The supervisor gates on no property; the adapter does (§4.7.11 item 8 **Property self-test.**). `selftest` runs the self-test alone, writes one result line per property to stdout, and exits non-zero when a gating property (§4.7.11 item 8 **Property self-test.**) fails; it is the mode `lenny-ctl preflight supervisor` runs, in a pod with no runtime process, so D-LOGS does not apply to it. The launch environment is the fixed `PATH`, then each `--env` pair in order, a later pair replacing an earlier one of the same name, so the Runtime's `env` (rendered first) can replace `PATH` and the platform's variables (rendered last) cannot be replaced.
- Signal handling implements each row of the §4.7.10 **Runtime supervisor.** **Signals.** table and nothing else. A handler that only sets a flag is installed for every signal from 1 to `_NSIG - 1`, real-time signals included, other than SIGKILL, SIGSTOP, SIGSEGV, SIGBUS, SIGFPE, and SIGILL. Those four fault signals keep `SIG_DFL` and are blocked in the supervisor from before the self-test, so a sent one stays pending or is discarded and a synchronous fault is delivered through the block by the kernel and ends the supervisor. The workers inherit the mask; every child that calls `execve` (the launched runtime process and each cleanup command) first sets an empty signal mask, and `execve` resets the handlers. No code path reads a signal's sender, and no handler is installed with `SA_SIGINFO`. `// spec: §4.7.10 (Runtime supervisor, Signals)`.
- Reaping implements the §4.7.10 **Runtime supervisor.** **Children.** table. The main loop clears the SIGCHLD flag before it runs the reap loop, `wait4(-1, WNOHANG)` until it returns 0 or `ECHILD`, so a SIGCHLD that arrives during the loop runs it again. The reap loop records the status of the launched process, a sweep worker, and the cleanup worker against that child's PID for the step that waits for it, and a waiting step that finds no recorded status for its child when the reaper reports `ECHILD` reports the child's failure. A child ended by a signal is tested with `WIFSIGNALED` before `WEXITSTATUS`, which reads 0 for it. `// spec: §4.7.10 (Runtime supervisor, Children)`.
- Hazards the C code handles everywhere: every descriptor the supervisor and its workers open carries `O_CLOEXEC` or `SOCK_CLOEXEC` (the `CH-SUPERVISE` socket included), so no child that calls `execve` inherits one; every syscall that can return `EINTR` is retried; deadlines are computed from `CLOCK_MONOTONIC` and waited with `ppoll` timeouts; every signal with a flag-setting handler is blocked outside `ppoll` and unblocked only by the signal mask passed to `ppoll`, so a signal that arrives between a flag check and the wait interrupts the wait instead of being missed until the timeout; and no `alarm`, `setitimer`, or other SIGALRM timer is used.
- Wire: a bounded line reader and a strict JSON subset parser for the request schema. Replies are written from fixed templates with integer and enumerated fields only.
- `end`: SIGTERM, a wait of `graceMs`, SIGKILL, the reap loop, and a `/proc` scan for any numeric entry other than 1. Two consecutive clean passes are required, and `pids.current` is read where `/sys/fs/cgroup/pids.current` is readable. A deadline yields `ended` with an error code.
- `sweep`: a forked worker that closes the `CH-SUPERVISE` descriptor first. It removes System V segments, queues, and semaphore sets whose `cuid` or `uid` is the agent UID (`/proc/sysvipc/*`, with `*_STAT` enumeration as fallback), POSIX message queues under the mqueue mount when present, and every entry the agent UID owns in the volumes §4.7.10 **Runtime supervisor.** **Sweep.** lists, skipping the workspace base's `slots/`, with `openat` and `O_NOFOLLOW | O_DIRECTORY`, `unlinkat` without following links, and bounded depth and entry counts. A walk that reaches either bound stops, and the worker exits with a status that reports it. The parent repeats `kill(-1)` and the `/proc` check before it replies `swept` as the §4.7.10 **Children.** table states for the worker's status.
- `cleanup`: a forked worker that closes the `CH-SUPERVISE` descriptor first, changes to the workspace base with `O_NOFOLLOW | O_DIRECTORY`, and runs each argv list in order: fork, an empty signal mask, `setsid`, `execve` with the launch environment plus `LENNY_PREV_CREDENTIAL_PROVIDER` and `LENNY_PREV_LEASE_ID`, and `waitpid` for that command. At the `cleanupTimeoutSeconds` deadline (§4.7.10 **Runtime supervisor.** **Cleanup.**), which `timeoutMs` carries, it sends SIGKILL to the running command's process group and stops. A command's stdout and stderr stay on the container's streams. The worker's exit status and the parent's `cleaned` reply follow the cleanup-worker and cleanup-command rows of the §4.7.10 **Children.** table, including the stop after the first failed command, which matches today's `workspace.RunSetup`; the table's deadline error is `cleanup_timeout` and its cleanup failure error is `cleanup_failed`. The parser's argv-list decoding is bounded in list length and string length and is fuzzed with the rest of the parser.
- `exited`: sent as the launched-runtime row of the §4.7.10 **Children.** table states, carrying the exit status or the signal.
- The supervisor writes nothing to stdout or stderr.
- The self-test forks a child that tries `ptrace(PTRACE_ATTACH)` and reads `/proc/1/mem` and `/proc/1/fd` (must fail), and double-forks a grandchild that a `kill(-1)` must reach; the kill-reach test passes only when the grandchild's `/proc` entry is present before the `kill(-1)` and absent after it, so a grandchild that had already exited cannot pass it. It tests PID-namespace init immunity to SIGKILL and SIGSTOP. It tests no signal sender, because no supervisor action reads one. `ready` carries `properties`, an object whose members are the enumerated property names and whose values are `pass` or `fail`, written from a fixed template. `// spec: §4.7.11 (Runtime supervisor, Property self-test); §28.5.3 (CH-SUPERVISE)`.
- `Dockerfile.supervisor` builds `FROM scratch` with the single binary. The image is signed and added to the cosign verified set.

**IMPLEMENTOR'S CHOICE:** the enumerated error code set, constrained to distinguish a launch exec failure, an end deadline, a `/proc` read failure, a sweep failure, a sweep walk that reached its bound, a cleanup command failure, a cleanup deadline, a malformed request, and a generation mismatch; the JSON member names of `cleanup` and `exited`; and the property names in `ready`'s `properties`. The §28.5.3 `CH-SUPERVISE` card leaves these unnamed, and the TEST-1 tier-3 contract test of the real supervisor binary against the real adapter client pins them, so the supervisor and the adapter change them together.

**Pre-READY sequence.** This table is the one statement of the adapter's startup order and of every exit before READY.
