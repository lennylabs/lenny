# Non-spec changes: Sidecar runtime processes have no platform supervisor

These changes are staged. Applying them is the implementation's work, under the
implementation checklist.

## Design (implementation-facing)

Every change below is written against the tree at `f52fc9a49` (2026-10-22). Code is located by symbol and file. The behavior each change implements is stated in the spec-changes file, and each code change cites the spec home it implements by heading. The re-baseline of 2026-10-22 replaced the draft's Go `supervise` subcommand with a C supervisor in its own image (D-BINARY) and widened every change to every sidecar pod (D-SCOPE). The review run completes the per-symbol detail.

### Process model

```
init container lenny-supervisor-stage (stage UID)
  /lenny-supervisor stage DEST          copies itself into the emptyDir, mode 0555

runtime container (agent UID), PID 1 = /lenny-supervisor/lenny-supervisor run --env K=V ... -- ARGV
  clearenv; PR_SET_DUMPABLE 0; flag-setting handlers for every catchable signal 1.._NSIG-1
  except SIGSEGV/SIGBUS/SIGFPE/SIGILL, which stay SIG_DFL and blocked
  property self-test (result reported in ready; the adapter gates)
  dial @lenny-supervise until accepted or --dial-timeout ends (then exit non-zero); SO_PEERCRED peer must be the adapter UID
  send ready{gen:0,properties}; serve requests in order until EOF, then exit

adapter (adapter UID)
  SO_PEERCRED self-test
  AwaitSupervisor: listen @lenny-supervise  <====  dial until accepted
  accept once (agent-UID check), close listener
  read ready; log each failed property    <====  ready{gen:0,properties}
  restart pod and a gating property failed: exit non-zero (no READY)
  [--warm-up-launch: write manifest, bind listeners, launch, accept CH-MSGSOCK]
  srv.Serve (READY)
  ...
  step 6 final manifest; listeners bound
  launch{gen,id}                        ====>  fork; child: empty signal mask, setsid, exec argv with the rendered env
                                        <====  launched{gen,id}
  CH-MSGSOCK accept (0090 handshake)    <====  runtime process dials
  ping{gen,id} every interval           ====>  <==== pong{gen,id}
  ...occupancy zero, restart pod (each step's outcome: §5.2 Supervised scrub sequence)...
  scrub step 0
  end{gen,id,graceMs:0}                 ====>  kill(-1,SIGTERM); kill(-1,SIGKILL); reap; /proc check x2
                                        <====  ended{gen,id}
  sweep{gen,id}                         ====>  fork worker (no CH-SUPERVISE fd): IPC by cuid/uid,
                                               POSIX mqueues, agent-owned entries; parent kill(-1) + /proc check
                                        <====  swept{gen,id}
  cleanup{gen,id,commands,timeoutMs,prev...} ====>  fork worker (no CH-SUPERVISE fd), cwd workspace base:
                                               each argv in its own session, launch env + cleanup metadata
                                        <====  cleaned{gen,id}
  end{gen,id,graceMs:0}                 ====>  second end: kill(-1) and /proc check x2
                                        <====  ended{gen,id}
  sweep{gen,id}                         ====>  second sweep, as above
                                        <====  swept{gen,id}
  close and rebind CH-MSGSOCK and CH-RUNTIMEOPS listeners
  steps 1-6 (openat2 RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS)
  ReportPodScrub(runtime_live)
  ...occupancy zero, keep pod: step 0; cleanup ====> <==== cleaned; steps 1-6; ReportPodScrub
```

### Adapter state for one pod

| State | Set | Cleared |
|:--|:--|:--|
| `gen` | Incremented by each `launch` | Never |
| `live` (a process is running) | `launched` with no error | `ended` with no error, `exited` |
| `notLive` (sticky) | Each cause of §4.7.10 **Runtime supervisor.** **Liveness.** | Never |
| `launchPermitted` | Adapter start; an attested end (`ended` with no error) | `launch` |

§4.7.10 **Runtime supervisor.** **Liveness.** and its table are the one statement of `notLive`: its causes, what it refuses, how it is reported, and, for each `Sandbox` phase and kind of sidecar pod, which causes can arise and the one channel through which the pod retires. The adapter's part in every channel is fixed here: it exits non-zero (**Exit**), fails a start (**Start**, and under **Claim**), or reports `runtime_live: false` (**Report**); the WarmPoolController's part in **Exit** is the precursor fix (summary D-PREREQS), and the gateway's part in **Start**, **Claim**, and **Report** is unchanged. Every session start checks `notLive` first, whether the start would launch a process or use the live one, and fails while it is set; the launch check refuses while it is set, whatever `launchPermitted` holds. Before `srv.Serve`, and on a service-mode pod at any time, a cause exits the adapter non-zero instead. On every other pod after `srv.Serve` a cause never exits the adapter, whether or not the registry holds a session entry (summary D-NOTLIVE).

`ServesNextSession()` returns false when `notLive` is set or, on a `keep` pod, when the composed `SocketRuntimeProcess.ServesNextSession` does, which is how a `keep` pod's connection state reaches the report when nothing set `notLive` earlier. The pod's lifetime is the `--runtime-process` flag the pod builder rendered at pod creation (D-PODLIFETIME); the adapter holds no other recycle state. `podscrub.go` reads it as today.

### CODE-2 · The C supervisor, its image, and the binary check

**Targets.** `supervisor/` (new top-level directory: `supervisor.c`, `wire.c`, `procs.c`, `sweep.c`, `selftest.c`, `syscalls.h`, `Makefile`), `Dockerfile.supervisor`, the image build and signing in CI and the release workflow, and a CI check script under `scripts/`.

**Change.**

- A freestanding C program built with `-static -nostdlib -ffreestanding` over raw syscall wrappers. No `PT_INTERP`, no dynamic section, no libc, and no NSS. The CI check fails the build when `readelf` reports an interpreter or a dynamic section, or the symbol table contains `dlopen` or an NSS entry point.
- Modes: `stage DEST` copies `/proc/self/exe` to `DEST/lenny-supervisor` with mode `0555`. `run --socket NAME --adapter-uid UID [--dial-timeout D] --env K=V ... -- ARGV...` does, in order: `clearenv`; `prctl(PR_SET_DUMPABLE, 0)`; the signal dispositions of the signal bullet below; the property self-test; dial, repeating a dial refused with `ECONNREFUSED` until one connects or the `--dial-timeout` window ends, when it exits non-zero (the flag's default is at least the adapter's `AwaitSupervisor` timeout); `SO_PEERCRED` check against `--adapter-uid`; `ready` with the self-test result; serve. The supervisor gates on no property; the adapter does (§4.7.11 item 8 **Property self-test.**). `selftest` runs the self-test alone, writes one result line per property to stdout, and exits non-zero when the non-dumpable or kill-reach property fails; it is the mode `lenny-ctl preflight supervisor` runs, in a pod with no runtime process, so D-LOGS does not apply to it. The launch environment is the fixed `PATH`, then each `--env` pair in order, a later pair replacing an earlier one of the same name, so the Runtime's `env` (rendered first) can replace `PATH` and the platform's variables (rendered last) cannot be replaced.
- Signal handling implements each row of the §4.7.10 **Runtime supervisor.** **Signals.** table and nothing else. A handler that only sets a flag is installed for every signal from 1 to `_NSIG - 1`, real-time signals included, other than SIGKILL, SIGSTOP, SIGSEGV, SIGBUS, SIGFPE, and SIGILL. Those four fault signals keep `SIG_DFL` and are blocked in the supervisor from before the self-test, so a sent one stays pending or is discarded and a synchronous fault is delivered through the block by the kernel and ends the supervisor. The workers inherit the mask; every child that calls `execve` (the launched runtime process and each cleanup command) first sets an empty signal mask, and `execve` resets the handlers. SIGPIPE does nothing, and the `EPIPE` that the failed write returns is a closed connection, on which the supervisor exits. Every other catchable signal does nothing. No code path reads a signal's sender, and no handler is installed with `SA_SIGINFO`. `// spec: §4.7.10 (Runtime supervisor, Signals)`.
- Reaping implements the §4.7.10 **Runtime supervisor.** **Children.** table. The main loop clears the SIGCHLD flag before it runs the reap loop, `wait4(-1, WNOHANG)` until it returns 0 or `ECHILD`, so a SIGCHLD that arrives during the loop runs it again. The reap loop records the status of the launched process, a sweep worker, and the cleanup worker against that child's PID for the step that waits for it, and a waiting step that finds no recorded status for its child when the reaper reports `ECHILD` reports the child's failure. A child ended by a signal is tested with `WIFSIGNALED` before `WEXITSTATUS`, which reads 0 for it. `// spec: §4.7.10 (Runtime supervisor, Children)`.
- Hazards the C code handles everywhere: every descriptor the supervisor and its workers open carries `O_CLOEXEC` or `SOCK_CLOEXEC` (the `CH-SUPERVISE` socket included), so no child that calls `execve` inherits one; every syscall that can return `EINTR` is retried; deadlines are computed from `CLOCK_MONOTONIC` and waited with `ppoll` timeouts; every signal with a flag-setting handler is blocked outside `ppoll` and unblocked only by the signal mask passed to `ppoll`, so a signal that arrives between a flag check and the wait interrupts the wait instead of being missed until the timeout; and no `alarm`, `setitimer`, or other SIGALRM timer is used.
- Wire: a bounded line reader and a strict JSON subset parser for the request schema. Replies are written from fixed templates with integer and enumerated fields only.
- `end`: SIGTERM, a wait of `graceMs`, SIGKILL, the reap loop, and a `/proc` scan for any numeric entry other than 1. Two consecutive clean passes are required, and `pids.current` is read where `/sys/fs/cgroup/pids.current` is readable. A deadline yields `ended` with an error code.
- `sweep`: a forked worker that closes the `CH-SUPERVISE` descriptor first. It removes System V segments, queues, and semaphore sets whose `cuid` or `uid` is the agent UID (`/proc/sysvipc/*`, with `*_STAT` enumeration as fallback), POSIX message queues under the mqueue mount when present, and every entry the agent UID owns in the volumes §4.7.10 **Runtime supervisor.** **Sweep.** lists, skipping the workspace base's `slots/`, with `openat` and `O_NOFOLLOW | O_DIRECTORY`, `unlinkat` without following links, and bounded depth and entry counts. A walk that reaches either bound stops, and the worker exits with a status that reports it. The parent repeats `kill(-1)` and the `/proc` check before it replies `swept` as the §4.7.10 **Children.** table states for the worker's status.
- `cleanup`: a forked worker that closes the `CH-SUPERVISE` descriptor first, changes to the workspace base with `O_NOFOLLOW | O_DIRECTORY`, and runs each argv list in order: fork, an empty signal mask, `setsid`, `execve` with the launch environment plus `LENNY_PREV_CREDENTIAL_PROVIDER` and `LENNY_PREV_LEASE_ID`, and `waitpid` for that command. At the `cleanupTimeoutSeconds` deadline (§4.7.10 **Runtime supervisor.** **Cleanup.**), which `timeoutMs` carries, it sends SIGKILL to the running command's process group and stops. A command's stdout and stderr stay on the container's streams. The worker's exit status and the parent's `cleaned` reply follow the cleanup-worker and cleanup-command rows of the §4.7.10 **Children.** table, including the stop after the first failed command, which matches today's `workspace.RunSetup`; the table's deadline error is `cleanup_timeout` and its cleanup failure error is `cleanup_failed`. The parser's argv-list decoding is bounded in list length and string length and is fuzzed with the rest of the parser.
- `exited`: sent as the launched-runtime row of the §4.7.10 **Children.** table states, carrying the exit status or the signal.
- The supervisor writes nothing to stdout or stderr.
- The self-test forks a child that tries `ptrace(PTRACE_ATTACH)` and reads `/proc/1/mem` and `/proc/1/fd` (must fail), and double-forks a grandchild that a `kill(-1)` must reach; the kill-reach test passes only when the grandchild's `/proc` entry is present before the `kill(-1)` and absent after it, so a grandchild that had already exited cannot pass it. It tests PID-namespace init immunity to SIGKILL and SIGSTOP. It tests no signal sender, because no supervisor action reads one. `ready` carries `properties`, an object whose members are the enumerated property names and whose values are `pass` or `fail`, written from a fixed template. `// spec: §4.7.11 (Runtime supervisor, Property self-test); §28.5.3 (CH-SUPERVISE)`.
- `Dockerfile.supervisor` builds `FROM scratch` with the single binary. The image is signed and added to the cosign verified set.

**IMPLEMENTOR'S CHOICE:** the enumerated error code set, constrained to distinguish a launch exec failure, an end deadline, a `/proc` read failure, a sweep failure, a sweep walk that reached its bound, a cleanup command failure, a cleanup deadline, a malformed request, and a generation mismatch; the JSON member names of `cleanup` and `exited`; and the property names in `ready`'s `properties`. The §28.5.3 `CH-SUPERVISE` card leaves these unnamed, and the TEST-1 tier-3 contract test of the real supervisor binary against the real adapter client pins them, so the supervisor and the adapter change them together.

### CODE-3 · Adapter: the `CH-SUPERVISE` client and the supervised runtime

**Targets.** `pkg/adapter/supervise.go` and `supervise_wire.go` (new), `pkg/adapter/socketruntime.go`, `pkg/adapter/runtimegeneration.go`, `pkg/adapter/podscrub.go`, `pkg/adapter/scrub/` (`Ops`, `DefaultOps`, `Run`), `pkg/adapter/sdkwarm.go`, `pkg/adapter/heartbeat.go`, `pkg/adapter/runtimeops.go`, `pkg/adapter/manifest.go`, `cmd/lenny-adapter/main.go`, the doc comments of `schemas/lenny-adapter.proto` with the regenerated `pkg/proto/adapter/v1/lenny-adapter.pb.go` and `lenny-adapter_grpc.pb.go`, the `Shutdown` doc comment of `pkg/gateway/runtime/adapterclient/client.go`, `tests/claim-map.json`, `tests/registers/exceptions-deployment-boundary.yaml`, and `tests/registers/deployment-boundary-defaults.yaml`.

**Change.**

- `AwaitSupervisor(ctx, socket, auth, lifetime, timeout)` listens through `peerCheckedListener` with the agent-UID check (none in nonce-only mode), accepts one connection, closes the listener, reads `ready` within the same timeout, logs each failed property through `slog` with its enumerated name, returns an error on a `restart` pod when the non-dumpable or kill-reach property failed, and starts one reader goroutine. A missing, late, or malformed `ready`, or a first message other than `ready`, is an error. `// spec: §4.7.11 (Runtime supervisor, Property self-test)`. The reader decodes strictly with a decoder that rejects the decode failures of §28.5.3 **Degradation.**, including a second `ready`, and sets `notLive` on any failure. `// spec: §28.5.3 (CH-SUPERVISE); §4.7.9 (step 4); §4.7.10 (Runtime supervisor, Liveness)`.
- `SupervisedRuntime` implements `RuntimeProcess`, `ServesNextSession`, `CloseListener`, `SDKWarmRuntime`, and `RuntimeGeneration() uint64`. It composes one `SocketRuntimeProcess` per launch on a `keep` pod and a `restart` pod alike (on a `keep` pod that is one per pod unless `DemoteSDK` ends the process) and sends `launch` before the composed `Start` accepts (D-TRANSPORT). A launch mutex spans the `launchPermitted` check (§4.7.10 **Launch.**), `launch`, and the composed `Start`, so concurrent first starts send one `launch`.
- `EndProcess(ctx, grace)` and `Sweep(ctx)` wrap `end` and `sweep`. After each attested end, before the next `launch`, the composed `CloseListener` runs and the `CH-RUNTIMEOPS` listener is closed and rebound (`RuntimeOps.Rebind`, new), which discards every backlogged connection (D-STALE); a rebind error sets `notLive` (the listener-rebind row of §5.2 **Supervised scrub sequence.**).
- The scrub order changes on a pod that runs the supervisor: `scrub.Run` gains an optional `EndRuntime` step between step 0 and `cleanupCommands`, which calls `EndProcess` and `Sweep` on a `restart` pod and is skipped on a `keep` pod, and an optional `EndRuntimeAgain` step between `cleanupCommands` and step 1, which calls `EndProcess` and `Sweep` on a `restart` pod. `scrub.Run` applies the outcome of each row of the §5.2 **Supervised scrub sequence.** table to the new steps, the cleanup step, and the rebind, recording not live as `notLive` and scrub failed as the step's error. The Step 0 row's skip of the cleanup step is gated in `scrub.Run` itself, so it holds on every pod, the adapter-run cleanup of an unsupervised pod included; today `scrub.Run` runs `runCleanup` after a step-0 error. The scrub's supervisor requests run under a context with a deadline; today `startPodScrub` runs the scrub under `context.Background()`, which has none. IMPLEMENTOR'S CHOICE: that deadline, provided the whole sequence fits inside the gateway's missing-report timeout (`cleanupTimeoutSeconds` plus its grace) and the `cleanup` request bound exceeds the `cleanupTimeoutSeconds` deadline (§28.5.3 `CH-SUPERVISE` **Timing.**). `scrub.Config` gains an optional `CleanupRunner`; when it is set, `runCleanup` sends the commands through it (`SupervisedRuntime.RunCleanup`, which splits each command as the argv mode of `workspace.RunSetup` does and sends `cleanup`) instead of `workspace.RunSetup`, and a `cleaned` error is the step's error. `podscrub.go` `scrubConfig` sets `CleanupRunner` when `--supervise-socket` is set and leaves it nil otherwise (D-CLEANUP). ### CODE-4 · Pod builder, controller flag, and chart

**Change.**
