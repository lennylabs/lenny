### Settled decisions

- **D1. Pods hold no Lenny-issued JWT.** The §10.2 boundary table, §10.3, and the §13.3 credential flow are canonical, and the code follows them. Rejected: pods hold Lenny JWTs so the §10.2 claims list wins (needs a delivery channel, a `subject_token` the gateway lacks on the pod path, 24-hour renewal, redelivery after restart or handoff); threading the user's JWT or bearer `jti` through `LNK-GWCONTROL` (§13.3 bars client tokens from pods).
- **D2. Session creation mints no JWT.** No implemented endpoint consumes one; the playground bearer keeps `typ: session_capability`. Rejected: signing and recording the token as a revocation anchor (KMS dependency and 24-hour `exp` on long sessions); returning it in the `POST /v1/sessions` response; minting it lazily at first delegation.
- **D3. The 0102 step (1a) refusal survives**, re-anchored on session creation (SPEC-1 Edit (b)); one function serves every root-creating handler and client-facing `lenny/delegate_task`. Rejected: a route enumeration (drifts); triggers "presented client bearer" and "Lenny-issued bearer".
- **D4. `exchange_type: session_mint` stays**, redefined in §16.7 as the caller-check rejection row. Rejected: a new enum value or renaming `DELEGATION_PARENT_REVOKED` (churn with no behavior gain).
- **D5. Internal delegation mints no token.** Child identity is the session row and the §8.3 lease. Rejected: routing child minting through the Token Service by HTTP or a new gRPC RPC (needs parent tokens the gateway does not store); binding a session to the creating bearer's `jti` (15-minute rotation breaks delegation).
- **D6. Parent freshness keys on the parent row**: the child insert reads the parent `FOR SHARE` and refuses a terminal or absent parent with the existing `CreationRefusal`; `ErrParentRevoked` is deleted. Rejected: a lock-free `INSERT ... WHERE EXISTS` (READ COMMITTED race); relying on the FK's `FOR KEY SHARE` (does not conflict with a non-key UPDATE).
- **D7. The fence refuses only a terminal parent.** Rejected: refusing every non-running parent; mapping admission's `ErrParentNotRunning` to `DELEGATION_PARENT_REVOKED`.
- **D8. Revocation reaches a tree through session-tree mechanisms** (§11.4 full revoke, the creation fence, the §8.10 cascade). Rejected: a session-tree recursive-revocation endpoint; making `RevokeCascade`/`RevokeBySubject` take the §11.7 advisory lock; a cascading `POST /v1/admin/issued-tokens/{jti}/revoke`.
- **D9. `DELEGATION_AUDIT_CONTENTION`, the §8.2 retry paragraph, and `ErrAuditContention` are deleted.** Rejected: re-anchoring the code on the `delegation.spawned` audit write (no spec rule puts it under the lock).
- **D10. 0104 lands after 0102's spec steps and 0102 CODE-2 item 7** (`SourceRefusal`).
- **D11. The forwarded-call session binding is split out.** SPEC-1 Edit (f) deletes the false §10.2 paragraph with no replacement; REC-1 stages an `ABSENT` claim-register row (generator `scripts/seed-claim-register.py`, `deferral_id: R14`) and a Medium BUILD-GAPS finding routed to its own proposal in plan §10.2; SPEC-2 "Child identity" states that a pod-path child's parent is the session ID the adapter presents.
